## 1. Behaviour × platform: visible today? provable? what closes it

Legend: **Y** = visible and provable from `state`/receipt; **p** = only partly, or only by an extra
query or reading between the lines; **N** = invisible. "Fix" names the rule from §2 that closes it:
D = derived, generic; C = chokepoint, one call site; S = declared by the component and gated.

| # | Behaviour | Desktop (page + Tauri) | iOS (SwiftUI + editor page) | Android (Compose + editor page) | Fix |
|---|---|---|---|---|---|
| 1 | Web overlay open/closed (dialog, menu, listbox, search popup, find panel) | **p**: rows appear in `elements` and the diff (since 9bc08048). No `overlay` in `state`. `settingsOpen`/`searchOpen` are the only booleans (`NotesShell.svelte:327-338`). A container with `role=menu` is not "interactable", so `find {"role":"menu"}` misses an open context menu (verified live). | **p**: slash menu and autocomplete inside the page, same as desktop | **p**: same | D1 |
| 2 | Which overlay is on top, and is it modal | **N**. With Settings open, `elements` still lists e1–e24 (sidebar, editor) as plain rows. `at` at a row's centre shows `takes e67 presentation SettingsScreen` (verified): the data is there, the list does not use it. | **N** for sheets, alerts and covers beyond `navigation.sheet`. `modalUp` only filters the verb list. | **N**. `AgentVerbs.modalUp()` exists but is never reported (audit F3). | D1 (hit-test `top`, `modal`, `covered` flag) |
| 3 | Closed-but-mounted overlays | **p**: `e25 listbox "Insert block" 0×0` appears in `find`, `observe` and `elements {"all"}` | same | same | D1 filters by visibility |
| 4 | OS dialogs (`confirmDialog` → Tauri `ask`, folder/image `open`) | **N**. Verbs skip them ("arrive as if confirmed"). A real click on "Delete" leaves the page awaiting a dialog nobody can see. | UIAlertController-backed `.alert`/`.confirmationDialog` are **N** today | `AlertDialog`/`ConfirmDialog` windows are **N** | C1 (desktop), D2/D3 (native) |
| 5 | Native sheets / full-screen covers / pickers / share sheet | n/a | **p**: `sheet` covers settings/sync/feedback only. The move sheet, rename alert, delete cover, new-folder cover, `ShareLink` and image picker are **N** (`NoteListView.swift:81-435`, `NoteEditorView.swift:366-386`). | **N**: `FolderPickerSheet` (ModalBottomSheet), `NewFolderDialog`, `ConfirmDialog`, crash dialog | D2 / D3 |
| 6 | Native menus (iOS ⋯ `Menu`, `.contextMenu`; Android `DropdownMenu`) | n/a | **N** (a person opens them; an agent cannot tap native chrome) | **N** (a `DropdownMenu` is a Popup window) | D3 on Android. iOS: out of scope until an agent can open one. |
| 7 | Native in-view surfaces (the find bar is `@State findVisible` in SwiftUI/Compose; the transient banner; the keyboard toolbar) | n/a | **N**. Page `editor.find` is the *page's* find field, and the native bar may disagree (not verified live). | **N** | S1 (state on the existing verb scope) |
| 8 | Toasts / banners | **p**: `toast` is in shell state for its 5 s (`TOAST_DURATION_MS`), then gone. A toast raised by an async verb between two reads is lost. `<div class="toast">` has no role. | **N**: `NotesStore.transientMessage` is not in state | **N**: 39 raw `Toast.makeText` call sites. The toast is a system window, which no in-app walk can see. | D4 (live regions), C3 (Android helper) |
| 9 | Tooltips (`title` attr, OS-drawn) | **N** (the text is used as the row label; whether it is showing is not). Low value. | — | — | none (YAGNI) |
| 10 | Which element has focus | **p**: the `focused` flag is set on the active element **and every ancestor**. Live: the Search input and its panel and overlay were all "focused"; with the listbox open, both e45 and e46 were. With Settings open **nothing** had focus: the dialog does not take focus, an a11y bug the agent cannot even name. `find {"selector":":focus"}` returns nothing whenever the window is not key. | page only. The native first responder (the title field) is **N**. | page only. Native focus is **N**. | D1 `focus` (activeElement), D2/D3 |
| 11 | Window focused / visible / minimised | **N**: `document.hasFocus()` is never reported, which is why `:focus` lies and `qa-shot` sees blank frames | app state (foreground) **N** | **N** | D1 `window` |
| 12 | Soft keyboard shown / height | n/a | **N** | **N** | D2 (keyboard notifications) / D3 (IME insets) |
| 13 | Caret / selection | **Y** (`state.editor.selection`, `diff.selection`) | **Y** (page) | **Y** (page) | — |
| 14 | IME composition | **p**: `compositionstart/end` are recorded in `events` for real input. `view.composing` is not in state. `Type` never composes. | **N** (a real keyboard only) | **N** | D1 `focus.composing`. Producing a composition stays a person's job. |
| 15 | Input values | **p**: `textOf` prefers `aria-label` over `value` (`agentElements.ts:185-191`), so a labelled field shows its label. The find field `"Find in note"` never shows the query, and clearing it read as "no change" (audit F2). Unlabelled inputs (the search box, the sync URL) do show their value. | the native title field's live text is **N** | same | D1 `value` field on rows and focus |
| 16 | checked / pressed / expanded / selected / disabled | **p**: flags only for `aria-*="true"` and `.disabled`. `aria-expanded="false"` looks the same as "not a popup trigger". `<input type=checkbox>` reads `"on"` with no `checked` (e23, the task box). `aria-disabled` is ignored. | settings values are **Y** in `state.settings` | same | D1 flags |
| 17 | Covered / clipped / off-screen | **p**: `show` has `clippedBy` and `hitVersusPaint`, and `at` has the stack, but only per element. `elements` never says covered. | — | — | D1 `covered by eN` |
| 18 | Scroll position | **N** (indirectly: `find {"text"}` gives `rect: null` off-screen) | same | same | D1 `focus`/`show` add `scroll {top,max}`. Otherwise YAGNI. |
| 19 | Animations / transitions | **N**. Snapshots land mid-transition; 42% of element changes are rect-only (audit F2). | same | — | D5 settle on `document.getAnimations()` |
| 20 | Async loads / late renders (Settings "Loading…" → path, `OpenNote` document) | **p**: seen only as `changedSinceLast` on the *next* action (live: the `ToggleLanguageOptions` receipt carried Settings' late `+ "Reset to default"`). Lost on 202 rebuilds and ring eviction (audit F2). | native loads **N** | **N** | D5 (settle + `aria-busy`), E (ui events in the ring) |
| 21 | Debounced save pending / landed | **p**: `note.dirty` shows pending. "Landed" is not in any receipt: `MoveNote` got 115/115 receipts with no diff (the vault is not in the snapshot). | `notes` query only | `notes` query only | C2 (effect at the mutation apply point) |
| 22 | Renames / moves / deletes in the vault | **p**: `notes` query, or the disk | **p**: same | **p** | C2 |
| 23 | Clipboard | **p**: `clipboard` query. It is **not** in the snapshot, so `Copy` got 50/50 "no change". `CopyCurrentNotePath` writes the *person's* OS clipboard (`navigator.clipboard.writeText`, `createCurrentNoteActions.svelte.ts:46`; iOS `UIPasteboard.general`), invisible to the agent. | **N** (OS pasteboard) | **N** | D1 (clipboard in the snapshot), C2 (record the OS write) |
| 24 | Sync / network | **p**: `just journal` after the fact; `state` has no `sync` (audit C5, sibling). Network is in Rust, so the page sees none of it. | **Y** `state.sync` | **Y** `state.sync` | sibling (b) / C5 |
| 25 | JS errors / rejections / `console.error`/`warn` | **p**: a handler throw shows as `threw` in `events`, and a verb throw is a 500. `window.onerror`/`unhandledrejection` go to `crashHandler.ts`, which writes a file and localStorage only. `console.warn("[local-notes] …")` from `_applyLocalMutation` is invisible. | print/os_log **N** | Log **N** | D4 (error entries in the ring) |
| 26 | Crash | **p**: the CLI says "app answered nothing". The next launch's crash dialog is **Y** (modal verbs). | same | same | CLI names the last verb and the crash-report path (sibling b) |
| 27 | macOS menu-bar commands / accelerators | **N**: NSApp takes ⌘W before the webview (`app_menu.rs:1-15`) and emits `app-menu`, a Tauri event with no DOM event, so the trace shows the tab closing with no cause | — | — | C2 (record `app-menu` at its one listener) |
| 28 | Navigation stack / screen | **Y** `screen` | **Y** `screen` (`list`/`folder:`/`editor:`/`search`/sheet) | **Y** | — |
| 29 | Native verb receipt says what changed | — | **N**: `{ok, verb}` only (46/109 Jev iOS turns, audit F2) | **N** | CLI diffs `state` before/after (audit C5) + `ui` |
