# Portable text-first core

This core is under development for #283. Shipping apps continue using the shared
Milkdown editor until a separate renderer integration and cutover.

- A plain-note session opens exact UTF-8 source, including CRLF, trailing whitespace and final-newline spelling; opening and dropping an unchanged store session writes neither the note nor a recovery file. → crates/futo-notes-editor, crates/futo-notes-store/src/editor_session
- Plain-text insertion, deletion and replacement use distinct source/display UTF-8 byte coordinates; revision-checked conversions expose distinct source/display UTF-16 code-unit ranges for native hosts. Display and source correspond directly for this plain-text slice. → crates/futo-notes-editor/src/coordinates.rs
- Reversed or out-of-range edits, UTF-8 character splits, UTF-16 surrogate splits, unpaired surrogate input and stale revisions reject explicitly before recovery acceptance, leaving text, selection and history unchanged; input preserves exact line endings and Unicode spelling. → crates/futo-notes-editor/src/coordinates.rs, crates/futo-notes-editor/tests/unicode.rs
- Selection-only updates carry the current source revision and create no source delta, recovery record or history step; Undo/Redo restore the exact selection before/after their original edit. → crates/futo-notes-editor/src/session.rs
- Caret movement and selection collapse stop at extended grapheme boundaries, including combining sequences, joined emoji, flags and CRLF; valid foreign replacement ranges may address code-point boundaries within a grapheme. → crates/futo-notes-editor/src/movement.rs
- Input acceptance holds an exclusive session borrow that prevents synchronous callback re-entry; repeated native notifications using the original revision reject before host acceptance. → crates/futo-notes-editor/src/session.rs, crates/futo-notes-editor/tests/unicode.rs
- Each successful operation returns one ordered display replacement, its resulting selection and the accepted revision; views apply these changes without parsing source. The portable callback is a host acceptance seam, not a WebAssembly durability acknowledgement. → crates/futo-notes-editor/src/types.rs, crates/futo-notes-editor/tests/common/mod.rs
- Basic Undo and Redo restore exact bytes one action at a time and pass through the same recovery acceptance boundary as replacement. Undo history is in-session only. → crates/futo-notes-editor/src/session.rs
- The store accepts each completed edit into an unbuffered recovery stream before returning its display change; process exit can lose the operation being applied, but reopening replays every previously accepted edit. OS acceptance alone is not a power-loss durability acknowledgement. → crates/futo-notes-store/src/editor_session/recovery.rs
- Recovery records stay in the vault's hidden `.futo-editor-recovery` directory, excluded from visible note listings and sync inventory; the versioned header binds the stream to its canonical vault root, note id, exact base and base revision. SHA-256 frames protect the header and records against accidental corruption. The first edit initializes the stream with its exact base. → crates/futo-notes-store/src/editor_session/recovery.rs
- One process can attach only one session to a note's recovery stream, including through different store handles. Independent app processes editing the same vault remain unsupported, as for the existing local note engine. → crates/futo-notes-store/src/editor_session/lease.rs
- Checkpoint owns the write/converge/recreate/park decision and log retirement under the store gate and vault mutation guard. It durably records the chosen destination before installation and returns the existing flush disposition and complete mutation; the installed note is synced before the log is retired. → crates/futo-notes-store/src/editor_session/mod.rs, crates/futo-notes-store/src/flush.rs
- A checkpoint that commits markdown but fails its durability check or recovery retirement reports the committed disposition and complete mutation in `CheckpointCommitted`; the draft remains copyable, edits pause, and checkpoint can retry the committed save decision after revalidating its destination. A markdown-write failure leaves the healthy recovery stream available and allows further protected edits. → crates/futo-notes-store/src/editor_session/mod.rs
- Recovery status exposes monotonic accepted and durable revision watermarks within an attached session, including Undo/Redo and checkpoint; append acceptance advances only accepted, while a successful flush or durable checkpoint advances durable. Recovery durability does not mean markdown has been checkpointed. Reopening conservatively treats replayed records as accepted until another successful flush acknowledges them. → crates/futo-notes-store/src/editor_session/mod.rs
- The first unflushed edit sets a provisional 100 ms deadline in an injected monotonic clock; further edits do not postpone it. Hosts can query the remaining delay without knowing the clock origin and run due flushes on a background worker; timer execution alone never acknowledges storage. Successful flushes report deadline lateness measured at completion, including storage time. This core scheduling contract is not a device durability-window measurement. → crates/futo-notes-store/src/editor_session/clock.rs, crates/futo-notes-store/src/editor_session/recovery.rs
- Append, short-write and flush failures report their stage, retain the current accepted draft for copying, and pause Replace/Undo/Redo without advancing either watermark for rejected edits. Resume repairs a failed live append's unaccepted tail or an explicitly reported torn final record and must successfully flush the accepted prefix before unpausing; failed repair remains paused. → crates/futo-notes-store/src/editor_session/recovery.rs
- Recovery tests exercise real public editor/store workflows above an injected filesystem: process death retains OS-accepted bytes, while modeled power loss discards unflushed bytes and preserves successful flushes; a failed flush never advances the durable prefix. → crates/futo-notes-store/src/tests/editor_session/durability.rs, crates/futo-notes-store/src/tests/editor_session/storage.rs
- A torn final record opens the validated draft prefix paused, reports its record number and retains the original log bytes; explicit resume truncates only that incomplete tail and successfully flushes the prefix before accepting further edits. → crates/futo-notes-store/src/tests/editor_session/recovery
- Corrupt complete records, invalid edit footprints, duplicate/out-of-order revisions, wrong note/vault identity and incompatible formats report a typed recovery issue, retain the log and keep editing/checkpoint paused; no later records are skipped or guessed into place. The validated prefix remains copyable, while an untrusted header opens the current disk source for copying. → crates/futo-notes-store/src/editor_session/recovery_format.rs
- A valid stream whose base differs from the current note retains its exact recovered draft and reports the mismatch; checkpoint preserves both versions through the existing persist-or-park workflow. → crates/futo-notes-store/src/tests/editor_session/recovery
- Controlled store writes, creates, backlink rewrites and sync adoption durably record local replacement intent before installing outside bytes when an editor recovery log exists, including bytes equal to the draft's old checkpoint; recovery parks the validated draft instead of undoing that replacement. This metadata stays hidden and out of the sync payload. → crates/futo-notes-core/src/files/recovery_coordination.rs, crates/futo-notes-store/src/tests/editor_session/recovery/outside_writes.rs
- Recovery append and stream repair share the vault mutation guard with controlled writes, so the first accepted edit cannot initialize its log inside an outside writer's decision/install window; native and portable hosts use the same acceptance boundary. → crates/futo-notes-store/src/editor_session/recovery.rs, crates/futo-notes-store/src/tests/editor_session/recovery/outside_writes.rs
- A committed park whose destination already owns another pending recovery stream reports `CheckpointCommitted`, retains the original stream and keeps input/resume paused before retargeting; recovering the destination's draft first lets checkpoint retry finish without deleting or appending to foreign recovery bytes. → crates/futo-notes-store/src/editor_session/mod.rs, crates/futo-notes-store/src/tests/editor_session/recovery/outside_writes.rs
- A checkpoint retry revalidates its previously committed destination under the vault guard and refreshes its complete positioned mutation before retiring recovery; if another writer replaced that destination, the draft returns through persist-or-park. → crates/futo-notes-store/src/editor_session/mod.rs
- Reopening an interrupted checkpoint recognizes its exact installed draft at the recorded destination and resumes retirement with a complete mutation, including a parked target from an earlier calendar day; repeated recovery creates no additional conflict copy. Process-death checks interrupt before installation, before retirement and after retirement. → crates/futo-notes-store/src/tests/editor_session/recovery

- The portable WASM session emits one small ordered source-edit handoff at a time; page-local completion changes the copyable draft but releases no view delta until a matching native store append acknowledgement. Further input is backpressured while that active edit is unacknowledged, so process interruption cannot discard an already displayed timer backlog. → crates/futo-notes-editor/src/portable.rs
- Session-incarnation tokens and monotonic request sequences bind append, flush and resume replies; duplicate, stale and superseded acknowledgements never apply a view delta twice, regress watermarks or claim durability from timer execution. Matching impossible watermarks reject without discarding the pending edit. → crates/futo-notes-editor/src/portable.rs
- Opening a portable page preserves the store's recovered pause and copyable source; native hosts expose the store's typed recovery issue, and resume never bypasses review-required corruption. → crates/futo-notes-store/src/editor_session/portable.rs
- The portable store endpoint performs blocking I/O only on its host worker; it validates exact source records before append acceptance and replay, and a successful flush advances durable independently from accepted. Failed storage retains the active page draft and pauses input; resume repairs and flushes the accepted prefix before a retained edit is acknowledged or retried. → crates/futo-notes-store/src/editor_session/portable.rs
- The compiled wasm32 consumer exchanges edits, Undo/Redo and flushes with a separate real Rust store worker; WASM ships without native filesystem/store or heavyweight service dependencies. Shipping renderers and bridge schemas remain unchanged. → scripts/test-editor-wasm.mjs, crates/futo-notes-editor/tests/wasm-consumer.mjs

Rename/delete lifecycle coordination, markdown interpretation and production renderers follow in their dependent tickets.

The current work counters report engine-materialized source and inserted bytes;
they do not claim parser work bounds or native device latency measurements.
