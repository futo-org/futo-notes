# Portable text-first core

This core is under development for #283. Shipping apps continue using the shared
Milkdown editor until a separate renderer integration and cutover.

- A session opens exact UTF-8 source, including CRLF, trailing whitespace and final-newline spelling; opening and dropping an unchanged store session writes neither the note nor a recovery file. → crates/futo-notes-editor, crates/futo-notes-store/src/editor_session
- Insertion, deletion and replacement use distinct source/display UTF-8 byte coordinates; revision-checked conversions expose distinct source/display UTF-16 code-unit ranges for native hosts. Hidden markers and decoded entities have explicit source/display correspondence. → crates/futo-notes-editor/src/coordinates.rs
- Reversed or out-of-range edits, UTF-8 character splits, UTF-16 surrogate splits, unpaired surrogate input and stale revisions reject explicitly before recovery acceptance, leaving text, selection and history unchanged; input preserves exact line endings and Unicode spelling. → crates/futo-notes-editor/src/coordinates.rs, crates/futo-notes-editor/tests/unicode.rs
- Identical selection/affinity echoes retain carried formatting and the typing group; an actual selection or affinity change breaks the run even if the caret later returns. Selection-only updates carry the current source revision and create no source delta, recovery record or history step; Undo/Redo restore the exact selection, affinity and carried formats before/after their original edit. → crates/futo-notes-editor/src/session.rs
- Caret movement and selection collapse stop at extended grapheme boundaries, including combining sequences, joined emoji, flags and CRLF; valid foreign replacement ranges may address code-point boundaries within a grapheme. → crates/futo-notes-editor/src/movement.rs
- Input acceptance holds an exclusive session borrow that prevents synchronous callback re-entry; repeated native notifications using the original revision reject before host acceptance. → crates/futo-notes-editor/src/session.rs, crates/futo-notes-editor/tests/unicode.rs
- Each successful operation returns one ordered display replacement, its resulting selection and the accepted revision; views apply these changes without parsing source. The portable callback is a host acceptance seam, not a WebAssembly durability acknowledgement. → crates/futo-notes-editor/src/types.rs, crates/futo-notes-editor/tests/common/mod.rs
- Consecutive adjacent single-grapheme typing, backward deletions or forward deletions of the same kind join a history group while the injected monotonic clock advances less than 500 ms between accepted inputs; exactly 500 ms, a backward clock movement, a changed selection/affinity, a direction change, a newline or an isolated action starts a new group. Rejected input does not change the group. → crates/futo-notes-editor/src/history.rs, crates/futo-notes-editor/tests/history.rs
- Undo and Redo restore exact source bytes plus opening/resulting selection, affinity and carried formats for the entire group, including local marker repairs; each group travels through one recovery acceptance before one display change. Failed acceptance preserves the whole group and current draft, and a new accepted edit discards the redo branch. → crates/futo-notes-editor/src/session.rs, crates/futo-notes-editor/tests/history.rs
- Explicit isolated input covers paste/correction and final composition commits: hosts retain provisional marked text and submit only its final commit as one action separate from preceding/following typing. Composition staging and command arbitration remain in the dependent composition slice. → crates/futo-notes-editor/src/history.rs
- A multi-run replacement supplies nonoverlapping ranges in ascending opening-display coordinates; one action preserves exact unchanged runs, validates every foreign range/string before acceptance and creates one protected recovery record and history step. Its final caret and carried formats follow the final replacement. Compound planning materializes its affected paragraph envelope, never an unrelated note prefix or suffix. → crates/futo-notes-editor/src/session/transaction.rs
- Paragraph Enter and Shift+Enter use the supplied platform display range, insert exactly one LF, and each form an isolated Undo action. Start/middle/end, repeated and empty-line input retain exact untouched CRLF and final-newline bytes through checkpoint and recovery. Structural block and table keys remain in their dependent command slices. → crates/futo-notes-editor/src/session/paragraphs.rs, crates/futo-notes-store/src/tests/editor_session/paragraphs.rs
- Paragraph Backspace/Delete remove the supplied selection or one visible extended grapheme in their direction; CRLF is one line-break deletion. Deleting at the document boundary changes neither revision nor history. Each key Undo restores its exact source, selection and carried formatting. → crates/futo-notes-editor/tests/paragraphs.rs
- Formatting survives selection deletion and a single inserted line break; a blank line closes and reopens the inline span locally, retaining carried formatting for the next typed character. Native and WASM paragraph-key consumers forward intent to this same engine without interpreting Markdown or choosing deletion footprints. → crates/futo-notes-editor/src/inline/spelling.rs, crates/futo-notes-ffi/tests/editor_paragraphs.rs
- History remains in-session only: reopening a recovered or checkpointed note starts with no Undo/Redo groups; recovery retains source edits rather than persistent Undo. The store adapts its injected recovery clock into the engine grouping clock. → crates/futo-notes-store/src/editor_session/clock.rs, crates/futo-notes-store/src/tests/editor_session.rs
- Bold, italic, strikethrough and inline code return display text without their markers, semantic runs and source/display correspondence; nested/adjacent runs retain original delimiter spelling outside the necessary edit footprint. Multiline emphasis follows CommonMark, and code contents isolate inline syntax. → crates/futo-notes-editor/src/inline/row.rs, crates/futo-notes-editor/tests/inline.rs
- Selection affinity explicitly chooses the preceding or following visible neighbor at hidden boundaries; native UTF-16 ranges address display text independently of exact source. Caret movement crosses visible graphemes without exposing markers. → crates/futo-notes-editor/src/session.rs, crates/futo-notes-editor/src/coordinates.rs
- Replacing a selection preserves the surviving marks on either side and carries the selection's initial formatting; deleting all marked content removes empty markers while retaining the format for subsequent input. Whitespace at emphasis edges remains visible outside markers until following input can join the span. → crates/futo-notes-editor/src/inline/edit.rs
- Formatting toggles preserve visible text and selection and form one exact-source history action; a collapsed toggle changes carried formatting without writing empty markdown or a recovery record. Candidate verification rejects unsafe formatting before acceptance. → crates/futo-notes-editor/src/session.rs
- When an edit changes CommonMark delimiter flanking, a necessary local boundary repair may encode the immediate adjacent scalar as a numeric entity; the visible scalar, surrounding formats and exact Undo remain intact. Decoded multi-scalar entities support valid code-point replacement ranges without losing the unselected scalar. → crates/futo-notes-editor/src/inline/edit.rs, crates/futo-notes-editor/tests/inline.rs
- Inline-code editing repairs backtick length and padding locally, preserves visible spaces, and splits code around newly inserted literal line breaks; existing code-span line endings project as CommonMark spaces while their exact source bytes remain intact. → crates/futo-notes-editor/src/inline/row.rs, crates/futo-notes-editor/src/inline/edit.rs
- Each source change carries a revision-tagged semantic replacement for its reparsed paragraph window, even if formatting changes leave display text identical; explicit projection queries return semantics and correspondence for a requested display range. → crates/futo-notes-editor/src/types.rs
- Inline source edits, formatting and history use the same store acceptance/replay/checkpoint workflow as plain input; recovery records contain source ranges rather than rendered offsets. → crates/futo-notes-store/src/editor_session/input.rs, crates/futo-notes-store/src/tests/editor_session.rs
- The store accepts each completed edit into an unbuffered recovery stream before returning its display change; process exit can lose the operation being applied, but reopening replays every previously accepted edit. OS acceptance alone is not a power-loss durability acknowledgement. → crates/futo-notes-store/src/editor_session/recovery.rs
- Recovery records stay in the vault's hidden `.futo-editor-recovery` directory, excluded from visible note listings and sync inventory; the versioned header binds the stream to its canonical vault root, note id, exact base and base revision. SHA-256 frames protect the header and records against accidental corruption. The first edit initializes the stream with its exact base. → crates/futo-notes-store/src/editor_session/recovery.rs
- One process can attach only one session to a note's recovery stream, including through different store handles. Independent app processes editing the same vault remain unsupported, as for the existing local note engine. → crates/futo-notes-store/src/editor_session/lease.rs
- Checkpoint owns the write/converge/recreate/park decision and log retirement under the store gate and vault mutation guard. It durably records the chosen destination before installation and returns the existing flush disposition and complete mutation; the installed note is synced before the log is retired. → crates/futo-notes-store/src/editor_session/mod.rs, crates/futo-notes-store/src/flush.rs
- A checkpoint that commits markdown but fails its durability check or recovery retirement reports the committed disposition and complete mutation in `CheckpointCommitted`; the draft remains copyable, edits pause, and checkpoint can retry without repeating the committed save decision. A markdown-write failure leaves the healthy recovery stream available and allows further protected edits. → crates/futo-notes-store/src/editor_session/mod.rs
- Recovery status exposes monotonic accepted and durable revision watermarks within an attached session, including Undo/Redo and checkpoint; append acceptance advances only accepted, while a successful flush or durable checkpoint advances durable. Recovery durability does not mean markdown has been checkpointed. Reopening conservatively treats replayed records as accepted until another successful flush acknowledges them. → crates/futo-notes-store/src/editor_session/mod.rs
- The first unflushed edit sets a provisional 100 ms deadline in an injected monotonic clock; further edits do not postpone it. Hosts can query the remaining delay without knowing the clock origin and run due flushes on a background worker; timer execution alone never acknowledges storage. Successful flushes report deadline lateness measured at completion, including storage time. This core scheduling contract is not a device durability-window measurement. → crates/futo-notes-store/src/editor_session/clock.rs, crates/futo-notes-store/src/editor_session/recovery.rs
- Append, short-write and flush failures report their stage, retain the current accepted draft for copying, and pause Replace/Undo/Redo without advancing either watermark for rejected edits. Resume repairs a failed live append's unaccepted tail or an explicitly reported torn final record and must successfully flush the accepted prefix before unpausing; failed repair remains paused. → crates/futo-notes-store/src/editor_session/recovery.rs
- Recovery tests exercise real public editor/store workflows above an injected filesystem: process death retains OS-accepted bytes, while modeled power loss discards unflushed bytes and preserves successful flushes; a failed flush never advances the durable prefix. → crates/futo-notes-store/src/tests/editor_session/durability.rs, crates/futo-notes-store/src/tests/editor_session/storage.rs
- A torn final record opens the validated draft prefix paused, reports its record number and retains the original log bytes; explicit resume truncates only that incomplete tail and successfully flushes the prefix before accepting further edits. → crates/futo-notes-store/src/tests/editor_session/recovery
- Corrupt complete records, invalid edit footprints, duplicate/out-of-order revisions, wrong note/vault identity and incompatible formats report a typed recovery issue, retain the log and keep editing/checkpoint paused; no later records are skipped or guessed into place. The validated prefix remains copyable, while an untrusted header opens the current disk source for copying. → crates/futo-notes-store/src/editor_session/recovery_format.rs
- A valid stream whose base differs from the current note retains its exact recovered draft and reports the mismatch; checkpoint preserves both versions through the existing persist-or-park workflow. → crates/futo-notes-store/src/tests/editor_session/recovery
- Reopening an interrupted checkpoint recognizes its exact installed draft at the recorded destination and resumes retirement with a complete mutation, including a parked target from an earlier calendar day; repeated recovery creates no additional conflict copy. Process-death checks interrupt before installation, before retirement and after retirement. → crates/futo-notes-store/src/tests/editor_session/recovery

- The portable WASM session emits one small ordered source-edit handoff at a time; page-local completion changes the copyable draft but releases no view delta until a matching native store append acknowledgement. Further input is backpressured while that active edit is unacknowledged, so process interruption cannot discard an already displayed timer backlog. → crates/futo-notes-editor/src/portable.rs
- Session-incarnation tokens and monotonic request sequences bind append, flush and resume replies; duplicate, stale and superseded acknowledgements never apply a view delta twice, regress watermarks or claim durability from timer execution. Matching impossible watermarks reject without discarding the pending edit. → crates/futo-notes-editor/src/portable.rs
- Opening a portable page preserves the store's recovered pause and copyable source; native hosts expose the store's typed recovery issue, and resume never bypasses review-required corruption. → crates/futo-notes-store/src/editor_session/portable.rs
- The portable store endpoint performs blocking I/O only on its host worker; it validates exact source records before append acceptance and replay, and a successful flush advances durable independently from accepted. Failed storage retains the active page draft and pauses input; resume repairs and flushes the accepted prefix before a retained edit is acknowledged or retried. → crates/futo-notes-store/src/editor_session/portable.rs
- The portable/WASM facade exposes range projection, explicit selection affinity and formatting toggles; pending source changes block projection and selection until acceptance so semantic descriptions cannot overtake the displayed revision. A paused recovered session can still query its accepted projection for display and copying. Rich view changes serialize semantic runs, correspondence and affinity through the same acknowledgement boundary. → crates/futo-notes-editor/src/portable.rs, crates/futo-notes-editor/tests/portable.rs
- The compiled wasm32 consumer exchanges hidden-marker edits, formatting toggles, Undo/Redo and flushes with a separate real Rust store worker; WASM ships without native filesystem/store or heavyweight service dependencies. Shipping renderers and bridge schemas remain unchanged. → scripts/test-editor-wasm.mjs, crates/futo-notes-editor/tests/wasm-consumer.mjs

- Native Swift and Kotlin sessions retain the opening store for their lifetime and serialize calls through one session attachment; detaching releases the attachment while retaining accepted recovery for reopening, without an implicit markdown checkpoint. _(native shells)_ → crates/futo-notes-ffi/src/editor
- Native input carries exact UTF-16 code units and fixed-width unsigned ranges, including malformed strings that ordinary string transport would repair; checked native-width conversion rejects oversized ranges on 32-bit runtimes. Returned deltas and semantic/source correspondence retain explicit byte coordinates, with revision-checked UTF-16 conversion queries. _(native shells)_ → crates/futo-notes-ffi/tests/editor_contract.rs
- Swift and Kotlin forward isolated input, final composition commits, multi-run UTF-16 replacements, explicit affinity selection and formatting through the shared engine; one compound action appends once and Undo/Redo restore exact bytes and carried formatting. Their consumers apply engine deltas and verify recovery starts with no persistent Undo. _(native shells)_ → crates/futo-notes-ffi/src/editor/mod.rs, crates/futo-notes-ffi/tests/editor_history.rs
- Native failures preserve editor validation kinds, recovery stages, review issues and committed checkpoint mutations as structured values; native projections add no markdown interpretation or save policy. _(native shells)_ → crates/futo-notes-ffi/src/editor/contract.rs

Outside-writer/lifecycle coordination,
block/link interpretation, composition and renderer integration follow in their dependent tickets.
Paragraph projections use a length-indexed tree and display Rope, so an ordinary
edit after a distant jump reparses only its paragraph window without rewriting
the note's tail offsets. Work counters include actual parser input for candidate
verification, paragraph partitioning and projection. Work in a single large
paragraph or fence is still proportional to that region; progressive interpretation,
complete allocation/work bounds and native device latency measurements remain
in their dependent tickets.
