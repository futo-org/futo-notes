# Images and non-text atoms

These are the portable replacement core's contracts. The shipping Milkdown editor keeps
its image node, `vaultImageSrc` resolution and picker flow (see `docs/spec/editor/images.md`)
until renderer integration and cutover.

- A projection reports each image and divider as an atom. An image keeps its source spelling in display text (`![alt](destination)`; hidden emphasis inside the alt follows ordinary inline rules); the role's range covers those glyphs. Inline, reference, collapsed and shortcut images are atoms; code, HTML, escaped `\!` and unresolved references are not. Divider atoms cover their one object-replacement glyph. → crates/futo-notes-editor/src/inline/images.rs, crates/futo-notes-editor/src/inline/row/parse.rs, crates/futo-notes-editor/tests/images.rs
- An image role carries the alt's source spelling, the parsed destination (a reference definition's destination for reference images, with its label), the title, and `vault`, the canonical vault-image classification: an image filename that is not a remote (`http:`, `https:`, `data:`) source. A shell resolves a platform URL for display only; it never enters source or this role. → crates/futo-notes-image/src/lib.rs, crates/futo-notes-editor/tests/images.rs
- An atom's only caret stops are `before` (its range start) and `after` (its range end); a renderer keeps the caret outside it. Deleting an atom is replacing its range with nothing through the ordinary input path: exact bytes, one Undo. Metadata (front matter, #300) has no atom role and keeps its inert behavior. → crates/futo-notes-editor/tests/images.rs
- A collapsed Backspace or forward Delete whose one-grapheme step reaches into an image atom removes the whole image (its entire spelling), never leaving part of `![alt](destination)` behind as text; it is one edit and one Undo group. Elsewhere a collapsed deletion is still one grapheme. → crates/futo-notes-editor/src/session/paragraphs.rs, crates/futo-notes-editor/tests/images.rs `a_carets_backspace_or_delete_next_to_an_image_removes_it_whole`, `deleting_an_image_whole_is_one_undo_step`
- Image insertion takes the stored vault reference (and an alt, normally empty) and writes `![alt](reference)`, using `<...>` for a destination with spaces or parentheses. The text is exact source, not typed text, so markup in it is never literalized, and its parse must read back as one image with exactly that destination or the call is `InvalidText`. An alt containing a backtick is refused too, since a code span in the surrounding text could swallow it. It replaces a selection or inserts at the caret, leaves the caret after the image, accepts one record and forms one isolated Undo group. Inside code nothing is inserted. A composition in progress is `CompositionActive`. → crates/futo-notes-editor/src/session/images.rs, crates/futo-notes-editor/tests/images.rs, crates/futo-notes-store/src/tests/editor_session/images.rs
- An insertion that finishes asynchronously (picker, paste, capture) presents the claim `image_claim` issued when it began. A claim names its editor session: ordinary edits do not invalidate it (the image lands at the caret now), while another note's session, or the same note reopened, gets `StaleClaim` and nothing changes. Asset writing, naming and cleanup stay with existing infrastructure; the engine never reads, writes or decodes image files. → crates/futo-notes-editor/tests/images.rs, crates/futo-notes-ffi/tests/editor_links.rs, crates/futo-notes-editor/tests/wasm-image-consumer.mjs
- Enter with a selection that is exactly one image atom keeps the image and acts after it (a new line below, caret on it) instead of replacing it. A shell must keep a keyboard's collapse-and-delete answer to Enter from reaching a selected image, so a last image can always be left. → crates/futo-notes-editor/src/session/paragraphs.rs, crates/futo-notes-editor/tests/images.rs
