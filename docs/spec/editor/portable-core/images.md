# Images and non-text atoms

These are the portable replacement core's contracts. The shipping Milkdown editor keeps
its image node, `vaultImageSrc` resolution and picker flow (see `docs/spec/editor/images.md`)
until renderer integration and cutover.

- A projection reports each image and divider as an atom. An image is `![alt](destination)` or `![alt](destination "title")` on one line; its display is its whole source spelling as typed, and the atom's range covers those glyphs. Nothing inside an image is read: `*x*` in its alt shows its asterisks. Code, an escaped `\!`, `![[note]]` (a wikilink) and reference-style `![alt][id]` (not in Linedown version 1) are not atoms. A divider atom covers its one object-replacement glyph. → crates/futo-notes-editor/src/lines/inline/scan.rs, crates/futo-notes-editor/src/engine/project.rs, crates/futo-notes-editor/src/engine/tests/images.rs
- An image role carries the alt's source spelling, the destination, the title, and `vault`, the canonical vault-image classification: an image filename that is not a remote (`http:`, `https:`, `data:`) source. Its `reference` is always empty. A shell resolves a platform URL for display only; it never enters source or this role. → crates/futo-notes-image/src/lib.rs, crates/futo-notes-editor/src/engine/project.rs
- An atom's only caret stops are `before` (its range start) and `after` (its range end); a renderer that draws it as one object keeps the caret outside it. Input at a caret strictly inside an image (a host that let one in) lands at the image's nearer edge (after, on a tie), never in its source, and so does a caret the user places there (`place_selection`), while a range the user places with an end strictly inside an image grows to include the whole image; `place_selection` answers with the fitted selection, and a host's echo (`select`) is taken as given; a nonempty selection touching part of an image expands to include the whole image before any input, key or command plans from it (typing, a composition's commit, Enter, Shift+Enter, Backspace, Delete, the divider, paste, Cut, Copy and drag-to-move alike), so no edit leaves part of an image's spelling behind and Cut copies what it removes. Deleting an atom is replacing its range with nothing through the ordinary input path: exact bytes, one Undo. Metadata (front matter, #300) has no atom role and keeps its inert behavior. A wikilink is one unit the same way, from outside it ([wikilinks.md](wikilinks.md)). → crates/futo-notes-editor/src/engine/commands/atoms.rs `outside_atoms` `outside_images`, crates/futo-notes-editor/src/engine/selection.rs `place_selection`, crates/futo-notes-editor/src/engine/edit/plan.rs `plan_writing`, crates/futo-notes-editor/src/engine/commands/mod.rs `key_command`, crates/futo-notes-editor/src/engine/commands/clipboard/copy.rs `copied`, crates/futo-notes-editor/tests/fixtures/engine/images.json
- A collapsed Backspace or forward Delete whose one-grapheme step reaches into an image removes the whole image (its entire spelling), never leaving part of `![alt](destination)` behind as text; bold or italic marks around nothing but the image go with it. It is one edit and one Undo step. Backspace at a line's start and Delete at its end join lines as usual and leave a neighboring image alone; a selection is deleted as it is, taking whole any image it covers part of. → crates/futo-notes-editor/src/engine/commands/atoms.rs `atom_key`, crates/futo-notes-editor/tests/fixtures/engine/images.json
- Enter with a selection that is exactly one image keeps the image and acts after it, as Enter at a caret there would (a new line below, caret on it). A shell must keep a keyboard's collapse-and-delete answer to Enter from reaching a selected image, so a last image can always be left. → crates/futo-notes-editor/src/engine/commands/atoms.rs `atom_key`, crates/futo-notes-editor/tests/fixtures/engine/images.json
- Image insertion takes the stored vault reference (and an alt, normally empty) and writes `![alt](reference)` at the caret, or in place of a selection. A reference with a space or a parenthesis is written as `<reference>`. The text is exact source, not typed text: nothing in it is escaped. It accepts one record and forms one isolated Undo step. → crates/futo-notes-editor/src/engine/commands/images/insert.rs, crates/futo-notes-editor/tests/fixtures/engine/images.json
- On an unindented, unquoted plain line or a heading that shows other content, the image goes on a line of its own (only what a reader sees counts: markers, whitespace and hidden syntax, such as a link with no text `[](u)`, do not), with the note's line ending (the caret line's, else the line's above, else `\n`). Where the image is, and what is around it, is read where it lands: over a selection that ends inside bold or a link's text the mark's opener stays after the image, outside it, so `«a **b»c**d` (the shown `a b` selected) gives `![](x.png)\n‸**c**d`. → crates/futo-notes-editor/src/engine/commands/images/insert.rs `own_line`, crates/futo-notes-editor/tests/fixtures/engine/images.json
- When the caret is at the start of the line's content, the image goes before the line: `![](x.png)\n# ‸Title`, the caret where it was. → crates/futo-notes-editor/src/engine/commands/images/insert.rs `own_line`, crates/futo-notes-editor/tests/fixtures/engine/images.json
- Otherwise it goes after the text before the caret, and the caret moves to the start of the line after the image: the rest of the line (`ab‸cd` gives `ab\n![](x.png)\n‸cd`), or a new empty line when the caret was at the line's end (`ab‸` gives `ab\n![](x.png)\n‸`). Splitting a heading mid-line leaves its second half a plain line. → crates/futo-notes-editor/src/engine/commands/images/insert.rs `own_line`, crates/futo-notes-editor/tests/fixtures/engine/images.json
- A split happens only where the lines it leaves read as they should: the text kept on the caret's line (before the image, or all of it when the image goes before) keeps that line's block, and the text after an image put after it is a plain line or an empty one, read with the line below. Where either would read as anything else, the image is written inline as below: `# Title‸ - [ ] ship` gives `# Title![](x.png)‸ - [ ] ship` rather than exposing a task, `---‸x` gives `---![](x.png)‸x` rather than leaving a divider, and `ab ‸| c |` above a `|---|` row stays one line rather than making a table header. → crates/futo-notes-editor/src/engine/commands/images/insert.rs `split_reads`, crates/futo-notes-editor/tests/fixtures/engine/images.json
- Spaces at the split end the line before it rather than indenting the line after (`ab‸ cd` gives `ab \n![](x.png)\n‸cd`; `«ab» cd` gives `![](x.png) \n‸cd`). → crates/futo-notes-editor/src/engine/commands/images/insert.rs `own_line`, crates/futo-notes-editor/tests/fixtures/engine/images.json
- Everywhere else the image is written inline with the caret after it: a split that would not read as it should (above), an empty or whitespace-only line, a list item, a quote line, a table cell, an indented plain line, and inside another mark (bold, a link's text), which a line of its own would split. → crates/futo-notes-editor/src/engine/commands/images/insert.rs `own_line`, crates/futo-notes-editor/tests/fixtures/engine/images.json
- An insertion is refused with `InvalidText`, changing nothing, when the reference is not a vault image, when the reference or alt holds a control character (a line break, a lone CR), when the reference holds `<`, `>` or `\`, or when the alt holds `[`, `]`, `\` or a backtick, even where the text would read back today. Otherwise it is refused unless the written text reads back, with the whole note read after the insertion, as exactly one image with exactly that destination, that alt and no title: so an escape the reader would remove, an image right after a `\`, inside a wikilink, holding a `|` inside a table cell, or landing where the lines around it would read as front matter are refused too. → crates/futo-notes-editor/src/engine/commands/images/insert.rs `reads_as_image`, crates/futo-notes-editor/src/engine/command/mod.rs `Command::image`, crates/futo-notes-editor/tests/fixtures/engine/images.json
- Inside a code block, or inside inline code, nothing is inserted; nor when a selection reaches into a code block. A composition in progress is `CompositionActive`. → crates/futo-notes-editor/src/engine/commands/images/insert.rs, crates/futo-notes-editor/src/engine/tests/images.rs
- An image inserted into a heading, list item, task, quote or table cell leaves that line the block it was; on the empty body line after front matter it writes a line break first. An insertion that would change another line's block is cancelled by the commands' one guard. → crates/futo-notes-editor/src/engine/tests/images.rs, crates/futo-notes-editor/src/engine/command/mod.rs
- An insertion that finishes asynchronously (picker, paste, capture) presents the claim `image_claim` issued when it began. A claim names its editor session: ordinary edits do not invalidate it (the image lands at the caret now), while another note's session, or the same note reopened, gets `StaleClaim` and nothing changes. Asset writing, naming and cleanup stay with existing infrastructure; the engine never reads, writes or decodes image files. → crates/futo-notes-editor/src/session/commands.rs `image_claim`, crates/futo-notes-editor/src/engine/commands/images/insert.rs, crates/futo-notes-editor/src/engine/tests/images.rs, crates/futo-notes-ffi/tests/editor_links.rs, crates/futo-notes-editor/tests/wasm-image-consumer.mjs
