# Images and non-text atoms

These are the portable replacement core's contracts. The shipping Milkdown editor keeps
its image node, `vaultImageSrc` resolution and picker flow (see `docs/spec/editor/images.md`)
until renderer integration and cutover.

- A projection reports each image and divider as an atom. An image is `![alt](destination)` or `![alt](destination "title")` on one line; its display is its whole source spelling as typed, and the atom's range covers those glyphs. Nothing inside an image is read: `*x*` in its alt shows its asterisks. Code, an escaped `\!`, `![[note]]` (a wikilink) and reference-style `![alt][id]` (not in Linedown version 1) are not atoms. A divider atom covers its one object-replacement glyph. → crates/futo-notes-editor/src/lines/inline/scan.rs, crates/futo-notes-editor/src/engine/project.rs, crates/futo-notes-editor/src/engine/tests/images.rs
- An image role carries the alt's source spelling, the destination, the title, and `vault`, the canonical vault-image classification: an image filename that is not a remote (`http:`, `https:`, `data:`) source. Its `reference` is always empty. A shell resolves a platform URL for display only; it never enters source or this role. → crates/futo-notes-image/src/lib.rs, crates/futo-notes-editor/src/engine/project.rs
- An atom's only caret stops are `before` (its range start) and `after` (its range end); a renderer that draws it as one object keeps the caret outside it. Input at a caret strictly inside an image (a host that let one in) lands at the image's nearer edge (after, on a tie), never in its source; a nonempty selection touching part of an image expands to include the whole image before replacement. Deleting an atom is replacing its range with nothing through the ordinary input path: exact bytes, one Undo. Metadata (front matter, #300) has no atom role and keeps its inert behavior. → crates/futo-notes-editor/src/engine/commands/images.rs `outside_images`, crates/futo-notes-editor/src/engine/tests/images.rs
- A collapsed Backspace or forward Delete whose one-grapheme step reaches into an image removes the whole image (its entire spelling), never leaving part of `![alt](destination)` behind as text; bold or italic marks around nothing but the image go with it. It is one edit and one Undo step. Backspace at a line's start and Delete at its end join lines as usual and leave a neighboring image alone; a selection is deleted as it is, image or not. → crates/futo-notes-editor/src/engine/commands/images.rs, crates/futo-notes-editor/tests/fixtures/engine/images.json
- Enter with a selection that is exactly one image keeps the image and acts after it, as Enter at a caret there would (a new line below, caret on it). A shell must keep a keyboard's collapse-and-delete answer to Enter from reaching a selected image, so a last image can always be left. → crates/futo-notes-editor/src/engine/commands/images.rs, crates/futo-notes-editor/tests/fixtures/engine/images.json
- Image insertion takes the stored vault reference (and an alt, normally empty) and writes `![alt](reference)` at the caret, or in place of a selection. A reference with a space or a parenthesis is written as `<reference>`. The text is exact source, not typed text: nothing in it is escaped. It accepts one record and forms one isolated Undo step. → crates/futo-notes-editor/src/engine/commands/images.rs, crates/futo-notes-editor/tests/fixtures/engine/images.json
- On an unindented, unquoted plain line or a heading that has other content, the image goes on a line of its own, with the note's line ending (the caret line's, else the line's above, else `\n`). → crates/futo-notes-editor/src/engine/commands/images.rs `own_line`, crates/futo-notes-editor/tests/fixtures/engine/images.json
- When the caret is at the start of the line's content, the image goes before the line: `![](x.png)\n# ‸Title`, the caret where it was. → crates/futo-notes-editor/src/engine/commands/images.rs `own_line`, crates/futo-notes-editor/tests/fixtures/engine/images.json
- Otherwise it goes after the text before the caret, and the caret moves to the start of the line after the image: the rest of the line (`ab‸cd` gives `ab\n![](x.png)\n‸cd`), or a new empty line when the caret was at the line's end (`ab‸` gives `ab\n![](x.png)\n‸`). Splitting a heading mid-line leaves its second half a plain line. → crates/futo-notes-editor/src/engine/commands/images.rs `own_line`, crates/futo-notes-editor/tests/fixtures/engine/images.json
- Spaces at the split end the line before it rather than indenting the line after (`ab‸ cd` gives `ab \n![](x.png)\n‸cd`; `«ab» cd` gives `![](x.png) \n‸cd`). → crates/futo-notes-editor/src/engine/commands/images.rs `own_line`, crates/futo-notes-editor/tests/fixtures/engine/images.json
- Everywhere else the image is written inline with the caret after it: an empty or whitespace-only line, a list item, a quote line, a table cell, an indented plain line, and inside another mark (bold, a link's text), which a line of its own would split. → crates/futo-notes-editor/src/engine/commands/images.rs `own_line`, crates/futo-notes-editor/tests/fixtures/engine/images.json
- An insertion is refused with `InvalidText`, changing nothing, when the reference is not a vault image, when the reference or alt holds a control character (a line break, a lone CR), when the reference holds `<`, `>` or `\`, or when the alt holds `[`, `]`, `\` or a backtick, even where the text would read back today. Otherwise it is refused unless the written text reads back on the line it lands on as exactly one image with exactly that destination, that alt and no title: so an escape the reader would remove, an image right after a `\`, inside a wikilink, or holding a `|` inside a table cell are refused too. → crates/futo-notes-editor/src/engine/commands/images.rs, crates/futo-notes-editor/tests/fixtures/engine/images.json
- Inside a code block, or inside inline code, nothing is inserted; nor when a selection reaches into a code block. A composition in progress is `CompositionActive`. → crates/futo-notes-editor/src/engine/commands/images.rs, crates/futo-notes-editor/src/engine/tests/images.rs
- An image inserted into a heading, list item, task, quote or table cell leaves that line the block it was; on the empty body line after front matter it writes a line break first. An insertion that would change another line's block is cancelled by the commands' one guard. → crates/futo-notes-editor/src/engine/tests/images.rs, crates/futo-notes-editor/src/engine/command/mod.rs
- An insertion that finishes asynchronously (picker, paste, capture) presents the claim `image_claim` issued when it began. A claim names its editor session: ordinary edits do not invalidate it (the image lands at the caret now), while another note's session, or the same note reopened, gets `StaleClaim` and nothing changes. Asset writing, naming and cleanup stay with existing infrastructure; the engine never reads, writes or decodes image files. → crates/futo-notes-editor/src/session/commands.rs `image_claim`, crates/futo-notes-editor/src/engine/commands/images.rs, crates/futo-notes-editor/src/engine/tests/images.rs, crates/futo-notes-ffi/tests/editor_links.rs, crates/futo-notes-editor/tests/wasm-image-consumer.mjs
