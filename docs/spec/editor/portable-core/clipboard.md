# Plain Markdown copy, cut and paste

Every line is read alone (linedown.md), so the clipboard writes what was copied and pasted; it never adds a blank line, an entity or an escape because of what the text is.

- Copy exports the exact source of a display selection. A list item's marker shows as one unit (lists.md), so a selection holding it carries the marker's source, a selection of the marker alone included (`- [x] `), and one starting at the item's text start leaves it out. A selection starting at a line's display start and reaching that line's end carries the line's quote and heading markers and its indent; one ending at a line's display end carries the closing syntax there. A bold, italic, strikethrough, code or link mark that a selection boundary cuts is closed or opened again with its own spelling (a link keeps its destination), outside edge spaces and tabs; a selection of only spaces and tabs gets no marks. The first copied line's leading whitespace comes off every copied line, so copied nested items keep their nesting relative to the first. CRLF stays as written; code lines copy without their fence lines when the selection stays in one block's code (the indent a fence under a list item hides comes off with the first line's leading whitespace), and a selection that crosses a block's boundary, or the block selected as one object, copies the block whole with its fences (fenced-code.md). A block nothing closes, copied whole, gains a matching closing fence. A collapsed selection copies nothing. → crates/futo-notes-editor/src/engine/commands/clipboard/copy.rs
- Cut returns the copied Markdown and removes the selection exactly as Backspace over it does, as one accepted edit and one Undo step that restores the exact bytes and selection. Like Backspace it always lands. It removes the selected display text, not whole lines: cutting `a`…`b` from `> a`, `> b`, `z` leaves `> ` then `z`, and pasting the copy back there gives `> a`, `> b` again. Over a table it covers every cell of, it copies and removes the table's lines whole (tables.md). Cutting exactly an item's marker takes it off as Backspace after it does (lists.md). The formats of the cut text's first character stay carried for the next typed character (`a **bold** c`, cut `bold`, type `x`: `a **x** c`), also after Redo. Removing a plain line's first word, by Cut, Backspace or Delete, leaves the caret before the space after it though that space now reads as hidden indent (linedown.md), so typing or pasting there goes before it, in the formats the cut word carried (`ab cd` less `ab`, then `xy`, saves `xy cd`; `**ab** cd` saves `**xy** cd`). → crates/futo-notes-editor/src/engine/commands/clipboard/mod.rs, crates/futo-notes-editor/src/engine/edit/mod.rs `keep_before_indent`
- Paste writes the pasted text as it is: edge spaces, tabs, runs of whitespace, leading whitespace on later lines and Markdown syntax all stay (`-` pasted on an empty line is saved as `-`). One trailing copied line ending is dropped (`x ` plus a line ending into `ab|cd` saves `abx cd`), unless it is all that was pasted, and every pasted `\n` or `\r\n` takes the caret line's line ending (on the note's last line, the one above it), so a CRLF note stays CRLF. A lone `\r` is an ordinary character. Pasting nothing at a caret changes nothing; over a selection it removes it. → crates/futo-notes-editor/src/engine/commands/clipboard/paste.rs
- A paste over a selection always ends it, a selected block too, even when it writes the bytes already there: the caret goes where that paste ends. With no byte changed there is no source edit and no Undo step; the portable session and WASM answer `null` and the host reads the caret from `selection`, while store and native FFI return a view change at the same revision. → crates/futo-notes-editor/src/engine/command/run.rs `Engine::run`, crates/futo-notes-editor/src/engine/commands/clipboard/mod.rs `paste_markdown`
- A paste is one accepted edit and one Undo step of its own; text typed before or after it is a separate step. Pending marked text commits first, in the same acceptance and as its own Undo step. → crates/futo-notes-editor/src/engine/command/run.rs `Engine::run`
- Outside tables, paste lands as typing does even when it changes how later lines read. A paste on a table line outside its cells uses the command guard; one that would change another table line is cancelled. → crates/futo-notes-editor/src/engine/commands/clipboard/paste.rs
- Text without a line break, other than a block line, lands at the caret as typing it would. So does a lone list marker (`- `, `10. `, `- [ ] `, as copying a marker gives it), wherever the caret is (`|foo` with `10. ` saves `10. foo`, `ab|cd` saves `ab10. cd`), and any one line over a selected list marker, which then takes its place (`10. a` with `10. ` selected and `5. ` pasted saves `5. a`): inside the marks that start there (a selection of bold text replaced by `*it*` saves `***it***`), in the formats a toolbar toggle left the caret carrying (Bold on, paste `x y`: `**x y**`), with the caret after it. Text that does not show as typed (a link, an image, a wikilink) is written inside the carried formats' house marks instead (Bold on, paste `[x](u)`: `**[x](u)**`; Code on: `` `[x](u)` ``, shown literally), kept only when every pasted visible character then shows in the carried formats plus its own and every other character as before; otherwise it is pasted plain. A carried format the pasted text already starts in is not written around it again (Bold carried, `**bold**` pasted: `**bold**`). → crates/futo-notes-editor/src/engine/commands/clipboard/paste.rs, crates/futo-notes-editor/src/engine/edit/plan.rs `plan_input`, crates/futo-notes-editor/src/engine/commands/clipboard/carried.rs
- A pasted link never lands inside another link's text: inside one, that link closes before it and opens again after it (`[ab|cd](u)` with `[x](v)` saves `[ab](u)[x](v)[cd](u)`); at a link's text start or end the pasted link goes before or after it. Other marks stay around it. → crates/futo-notes-editor/src/engine/commands/clipboard/paste.rs `link_split`
- Pasted lines after the first take the caret line's quote markers (`> q|` with `a`, blank, `b` saves `> qa`, `>`, `> b`), unless they start with quote markers of their own, which replace them (`> a|d` with `b`, `> c` saves `> ab`, `> cd`; a bare `>` gains the space the quote needs before the text, `b`, `>` saves `> ab`, `> d`); they take no list marker and no indent, so plain lines pasted into a list item are plain lines under it. → crates/futo-notes-editor/src/engine/commands/clipboard/paste.rs
- A first pasted line that is a block (heading, list item with text, quote, divider or fence) starts its own line: after the text before the caret, with the caret line's quote markers (`ab|cd` with `# Title` saves `ab`, `# Title`, `cd`); or, with no text before the caret, in place of the caret line's own marker (an empty bullet, heading or quote line takes the pasted line instead of nesting it). A pasted quote line replaces the caret line's quote markers too, so cut quote lines paste back without nesting. → crates/futo-notes-editor/src/engine/commands/clipboard/paste.rs
- A pasted list takes the caret line's indent on every line, so a list pasted into a list item becomes items beside it and nested pasted items keep their nesting under them (`  - |` with `- x`, `  - y` saves `  - x`, `    - y`). Pasted into an item's text, it splits the item: the text before the caret stays in its item, the pasted items follow, and the text after the caret goes to an item of its own with the caret item's marker as typed (`- ab|cd` with `- x`, `- y` saves `- ab`, `- x`, `- y`, `- cd`). Numbers are written as pasted; nothing is renumbered. → crates/futo-notes-editor/src/engine/commands/clipboard/paste.rs
- Text after the caret joins the last pasted line, unless that line is a block (a quote line at the plain caret line's own quote depth is not: the text carries on in it) or the paste leaves a fence open: then it keeps a line of its own with the caret line's markers (`## Head|tail` with `# T` saves `## Head`, `# T`, `## tail`). A divider or fence line after the caret (a caret at a divider, or a selection ending at its line) is no marker to paste in place of: it always keeps a line of its own, whole (`a`, a caret before `***`, with `# h`, `z` saves `a`, `# h`, `z`, `***`). A fence the paste opens and leaves open is closed after the pasted lines, with its own characters at its own indent (`ab|cd` with a fence and `code` saves `ab`, the fence, `code`, a closing fence, `cd`). Inside a quote a pasted fence is quoted text and is not closed. → crates/futo-notes-editor/src/engine/commands/clipboard/paste.rs `shape`, crates/futo-notes-editor/tests/fixtures/engine/hidden-line-edges.json
- A paste whose last line closes a code block (a selected block's copy is one) leaves the caret at the start of the line after the block, at its text start: the text after the caret, which keeps a line of its own there (`ab|cd` with a block saves `ab`, the block, `|cd`), else the next line when it is a paragraph, heading, list item or empty line. → crates/futo-notes-editor/src/engine/commands/clipboard/paste.rs `below_pasted_block`
- Where the line after such a block opens another code block, or the block ends the note, an empty line is opened after it as `OpenLineAfterCodeBlock` opens one (the line ending, then the closing fence's indent) and the caret is on it, in the paste's one Undo step: a block pasted on the empty line above a copy of itself saves the block, an empty line, the copy, and the same block pasted twice at the note's end leaves two blocks and the caret on an empty line under them. This holds at a caret, over a selection and over a selected block; not for a paste in code or one that leaves a fence open. → crates/futo-notes-editor/src/engine/commands/clipboard/paste.rs `below_pasted_block`, crates/futo-notes-editor/src/engine/commands/fences/open_line.rs `line_after_closing`
- Marks the caret is inside close at the first pasted line break and open again where the text after the caret continues (`**a|b**` with `x`, `y` saves `**ax**`, `**yb**`; a link keeps its destination on both sides). A caret at a mark's text start pastes before the mark, at its text end after it. → crates/futo-notes-editor/src/engine/commands/marks.rs `split`
- A one-line paste inside an inline code span writes its text as code: the pasted text's own code marks are left off, not typed into the span (cut `a` from `` `gamma` ``, paste it back: `` `gamma` ``), where the paste lands; text that still holds a backtick is pasted as it is. → crates/futo-notes-editor/src/engine/commands/clipboard/paste.rs `code_text`
- Paste in fenced code inserts the text verbatim, unescaped, each line after the first starting with the opening fence's leading whitespace, and it stays code: when a pasted line would close the fence (a run of the fence's character at least as long), the opening and closing fence lines grow one character longer than the longest such run. An empty code block takes the pasted lines as its code. → crates/futo-notes-editor/src/engine/commands/clipboard/code_paste.rs
- A paste, like Enter, Shift+Enter and the divider command, never removes a byte outside its reach (the selection's source, the code blocks it takes whole, and the caret line's marker a pasted block replaces) besides the numbers Enter's renumbering bumps (lists.md); it may only write between the bytes it keeps. The property run checks this after every random paste, Enter, Shift+Enter and divider. → crates/futo-notes-editor/src/engine/tests/properties/command_step.rs `kept_outside`
- Paste over a selection that crosses a code block's boundary, or over the selected block, takes the block whole as typing does (fenced-code.md, interpretation-and-input.md), with the pasted text as it is. → crates/futo-notes-editor/src/engine/edit/plan.rs, crates/futo-notes-editor/src/engine/commands/fences/reach.rs
- Paste inside one table cell stays in that cell, as the table family writes it (tables.md): edge blank lines go, other line breaks become one space, and a pipe is written `\|` (`| x| |` with `1`, `2` saves `| x1 2 |`). A caret on a table line outside its cells pastes as it would anywhere; a selection across cells or out of the table is refused (`UnrepresentableFormat`, never `InvalidRange`, #355) and changes nothing. Rich HTML paste (#303) is deferred. → crates/futo-notes-editor/src/engine/commands/tables/paste.rs `cell_paste`, crates/futo-notes-editor/src/engine/commands/clipboard/paste.rs
- Drag-to-move (`move_markdown`) cuts a display selection and pastes its Markdown at a drop offset given in the display before the move, as a paste at a caret placed there lands (not in the cut's carried formats), and leaves the moved text selected (`a **bold** word here`, `bold` dropped after `word`, saves `a  word**bold** here`). The cut and the paste are two accepted edits and one Undo step that restores the bytes and the selection before the move; Redo restores the move with the moved text selected. A drop inside the selection or at its edges moves nothing. A paste that cannot land (a drop in front matter) takes the cut back, leaving no Redo. Portable WASM exposes it; store and native FFI do not. → crates/futo-notes-editor/src/engine/commands/clipboard/move_text.rs, crates/futo-notes-editor/tests/move_text.rs
- Paste work is proportional to the pasted text and the lines it lands on; it does not grow with distant note content (200 pasted lines into the middle of a 20,000-line note read 2.5 KB and take about 0.24 ms in a release build). → crates/futo-notes-editor/src/engine/tests/clipboard/rules.rs
- Store, native FFI and portable WASM expose `copy_markdown`, `cut_markdown` and `paste_markdown`; copying reads the page's draft, so a paused draft stays copyable. Rejected append leaves the draft, selection and history unchanged; checkpoint and reopen reproduce the pasted and cut bytes. → crates/futo-notes-store/src/editor_session/clipboard.rs, crates/futo-notes-store/src/tests/editor_session/clipboard.rs, crates/futo-notes-ffi/src/editor/clipboard.rs, crates/futo-notes-editor/src/portable/clipboard.rs, crates/futo-notes-editor/tests/clipboard/wasm-clipboard-consumer.mjs
