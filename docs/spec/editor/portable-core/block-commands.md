# Heading, quote and divider block commands

Each line is read on its own (linedown.md): a heading is `#` to `######` and a space at column 0
after any quote markers, a quote is one or more `>` (`>>` or `> >` nests), a divider is a top-level
line such as `---`. These commands rewrite the start of the lines they act on and leave the text
alone. → crates/futo-notes-editor/src/engine/commands/blocks/

## Commands

- Heading and Text (the explicit Heading 1–6 and Text commands) act on every line the selection touches; a selection ending at the very start of a line does not touch it. Blank lines are set aside unless every touched line is blank, and code, front matter, dividers and tables are never changed. → crates/futo-notes-editor/src/engine/commands/blocks/mod.rs `targets`, crates/futo-notes-editor/tests/fixtures/engine/blocks.json
- A heading keeps the line's quote markers (`> title` becomes `> # title`); a list item loses its marker and task box (`1. a` becomes `## a`, `> - [ ] a` becomes `> ## a`); an indented plain line loses its indent; leading spaces in the text stay. → crates/futo-notes-editor/src/engine/commands/blocks/mod.rs `as_heading`
- Text takes the heading or list marker off and keeps the quote markers. Nothing else is written, unless the text left behind would read as another block: then one `\` keeps it plain (`- # todo` becomes `\# todo`, `- 1. a` becomes `1\. a`, `# ---` becomes `\---`). No blank line is added around the line. → crates/futo-notes-editor/src/engine/command.rs `kept_line`
- Choosing a line's current heading level changes nothing and leaves no Undo step. The toolbar's heading toggle (`ToggleHeading`) instead turns the lines to Text when every touched line already has that level, and otherwise sets it. → crates/futo-notes-editor/src/engine/commands/blocks/mod.rs `block_toggle`
- Quote decides once, on the touched lines with text (all of them if all are blank): when every one is quoted, it takes one quote level off every quoted touched line, each keeping its block (`> ## a` becomes `## a`, `> - a` becomes `- a`, `> > a` and `>> a` become `> a`, an empty `>` line becomes an empty line). Otherwise it adds one level to every touched line from the first line with text to the last, blank lines between them too (`a\n\nb` becomes `> a\n> \n> b`), each keeping its block and marker: `> ` is written before the line as it is (`## Title` becomes `> ## Title`, `- item` becomes `> - item`, `  - b` becomes `>   - b`), so Quote again returns the exact bytes. → crates/futo-notes-editor/src/engine/commands/blocks/mod.rs `quote`, `quoted`, `unquoted`
- Quote never changes code, front matter, dividers or table lines (Linedown reads a table only at the top level, so a quoted table line is no longer one), and they do not stop quoted lines around them from toggling off. Over a selection holding tables and other lines it quotes the other lines before, after and between the tables; over table lines alone it does nothing. A line under a quoted line is not part of that quote, so Quote on it quotes only it. → crates/futo-notes-editor/src/engine/commands/blocks/mod.rs `targets`, crates/futo-notes-editor/src/engine/tests/blocks.rs `quote_never_changes_a_table_line`, crates/futo-notes-editor/tests/fixtures/engine/format-over-tables.json
- Taking a quote level off writes one `\` where the line would otherwise read as another block (`> ---` becomes `\---`, ` > ``` ` becomes ` \``` `). → crates/futo-notes-editor/src/engine/commands/blocks/mod.rs `unquote`
- The toolbar shows the heading level every touched line with text shares (0 for text) and whether Quote would take a level off, by the same rules the commands use, so a lit button's tap takes its format off and an unlit one's never does. → crates/futo-notes-editor/src/engine/surface.rs `toolbar`, crates/futo-notes-editor/src/engine/tests/blocks.rs `a_lit_toolbar_button_takes_its_format_off_and_an_unlit_one_never_does`
- The toolbar state lists in `allowed` each command a toolbar offers that would act at the selection now, changing the note or (a format toggle at a caret) the formats typing there carries, so a host greys every button whose command is left out: Bold, Italic, Strike and Code (the toolbar's toggle, `toggle_toolbar_format`, which formats the word a caret is in), Link (`set_link` with a destination the selection's link does not have), Heading (the heading toggle, which acts at every level or none), Quote, the Bullet, Numbered and Task lists, Code block, Divider, Table and Image (`insert_image` at the selection). Each is read by its command's own rule, so `allowed` holds a command exactly when running it changes something: the heading toggle, Quote, the lists, Code block and Table by the lines they would change, Divider by the text it would write, Image by building the insertion with an ordinary vault reference (`image.png`; one that reads back differently, a `|` in a table cell, is still refused when inserted), and the format toggles and Link by building them a line at a time, from one reading of the selected lines, until one line changes. A caret in code, or a code block selected as one object, allows only Code block (which takes the code out of its block), and a caret in inline code no Image; table lines alone allow only the formats, Link and Image; a code block selected with a line outside it allows no Code block. `heading_allowed` and `quote_allowed` say whether `allowed` holds Heading and Quote. → crates/futo-notes-editor/src/engine/commands/allowed.rs, crates/futo-notes-editor/src/engine/commands/images.rs `image_acts`, crates/futo-notes-editor/src/engine/commands/inline/toggle.rs `format_acts`, crates/futo-notes-editor/src/engine/commands/inline/links/mod.rs `link_acts`, crates/futo-notes-editor/src/engine/tests/properties/toolbar_allowed.rs
  > **Gap:** `allowed` does not run the guard, so a command whose edits the guard cancels is listed though it changes nothing. Random runs meet a few in 400,000 checks: a list marker taken off a `|` line right above a delimiter row, and a link written into an empty `| ` line above one, would each make a table header. → crates/futo-notes-editor/src/engine/tests/properties/toolbar_allowed.rs `a_toolbar_command_is_allowed_exactly_when_it_would_act`
- Portable WASM reads the whole toolbar state as `toolbar_state()` (JSON `ToolbarState`), beside `active_formats()`; store and native FFI read it as `toolbar_state`. → crates/futo-notes-editor/src/wasm.rs `toolbar_state`, packages/editor/src/wasmPayloads.d.ts `ToolbarState`, crates/futo-notes-ffi/src/editor/toolbar.rs
- Reading the toolbar state reads only the caret's line and the lines the selection touches, so a host may read it after every selection change: on a desktop release build about 1.1 ms for a 60 KB note selected whole and 13 ms at 600 KB, linear in the selected lines, and about 15 µs at a caret. → crates/futo-notes-editor/src/engine/surface.rs `toolbar`
- Divider writes `---` at the caret, the selection removed first. Text before the caret stays on its line above the divider; text after it moves to a plain line below at the same quote depth, where the caret lands (on a blank line, the spaces and tabs after the caret go there too); with none, the caret lands on a new empty line below (in the line's quote). No other blank line is written. A heading split by a divider keeps its level above; a caret at a line's text start puts the divider above the whole line. → crates/futo-notes-editor/src/engine/commands/blocks/divider.rs, crates/futo-notes-editor/tests/fixtures/engine/divider.json
- Table (`{ Table: { rows, columns } }`, `rows` counting the header row) writes an empty table where Divider writes its line: the selection removed first, text before the caret stays on its line above it, text after it goes to a plain line below at the same quote depth, a caret at a line's text start puts it above the whole line, and on a divider, or the body line after front matter closed on the note's last line, it goes below. A blank line becomes the table, and no line is written after it when no text follows. Its rows are `|` then `  |` per column and its delimiter row `|` then ` --- |` per column, as the table commands write them; the caret lands in the header's first cell. Linedown reads a table only at column 0, so it is never quoted or in a list. A blank line goes between it and a table line above it or a `|` line below it, so neither reads as part of it. It changes nothing in code, front matter or a table, or with no rows or columns. → crates/futo-notes-editor/src/engine/commands/blocks/table.rs, crates/futo-notes-editor/tests/fixtures/engine/tables/commands.json
- A divider is never quoted: inside a quote it sits at column 0 between the quoted lines (`> ab` becomes `> ab\n---\n> `). Divider changes nothing in code, front matter or a table. → crates/futo-notes-editor/src/engine/commands/blocks/divider.rs
- Where a `---` would make line 1 open front matter (line 1 is a `---` divider, or the divider goes on line 1 with a `---` line below), Divider writes `----`, which is a divider and closes nothing. → crates/futo-notes-editor/src/engine/commands/blocks/divider.rs `divider_mark`
- `block_command_removing` (`block_command_removing_utf16` on WASM, store and FFI) removes typed text on one line, such as a `/` menu's query, as typing removes it, then runs a block command at the caret left, as one host acceptance and one Undo step that gives the typed text back. Where the command then changes nothing (Heading in a table cell, Table in code), the removal alone is that step. A range across a line break, holding part of an image or wikilink, on a code line or in front matter is refused: nothing is removed and the answer is `None`. → crates/futo-notes-editor/src/engine/command/run.rs `run_removing`, crates/futo-notes-editor/src/engine/tests/block_removing.rs
- Every command is one host acceptance and one exact Undo step that restores the bytes and the selection; Redo restores the edit. The selection follows its text, and a caret never lands between a `\` the command wrote and the character it escapes. A command that would change a line it did not act on (a fence, front matter or table opened or closed) is cancelled with no edit and no history. Pending marked text commits first as its own Undo step. → crates/futo-notes-editor/src/engine/command/run.rs `Engine::run`

## Keys on heading and quote lines

Keys on list items belong to the list commands (lists.md); keys elsewhere edit text as typed.

- Enter in a heading splits it: the text after the caret moves to a plain line below at the same quote depth (`# Ti|tle` becomes `# Ti\ntle`), with a `\` where that text would read as another block. Enter at the end leaves an empty plain line below. → crates/futo-notes-editor/src/engine/commands/blocks/keys.rs `block_enter`
- Enter at the start of a heading's or quoted line's text opens an empty line above it, and the line keeps its block and the caret; the new line holds the line's quote markers when the line above it is quoted (`> a\n> b` becomes `> a\n> \n> b`). → crates/futo-notes-editor/src/engine/commands/blocks/keys.rs `block_enter`
- Enter in a quoted line continues the quote one line at a time, with the quote markers as typed: `> quote|` becomes `> quote\n> |`, `> a|b` becomes `> a\n> b`, `>> a|b` becomes `>> a\n>> b`. → crates/futo-notes-editor/src/engine/commands/blocks/keys.rs `block_enter`
- Enter on an empty quote line (`> `, `>` or `> > `) takes one quote level off that line and writes no other line: `> quote\n> |` becomes `> quote\n|`, `> > x\n> > |` becomes `> > x\n> |`. → crates/futo-notes-editor/src/engine/commands/blocks/keys.rs `block_enter`
- Enter splits inline marks the caret is inside: they close before the break and open again after it, and the caret stays after them (`# **ab|cd**` becomes `# **ab**\n**cd**`; a link is split into two links). A caret at a mark's text start or end moves the whole mark to one side. List items and plain lines split marks the same way (lists.md, inline-formatting.md). → crates/futo-notes-editor/src/engine/commands/marks.rs `split`
- Enter and Shift+Enter act alike here, remove a selection first in the same action, and write the caret line's own line ending (CRLF on a CRLF line). Each is one Undo step. → crates/futo-notes-editor/src/engine/commands/blocks/keys.rs
- Backspace at a heading's text start makes it Text, keeping its quote markers. → crates/futo-notes-editor/src/engine/commands/blocks/keys.rs `block_backspace`
- The joining Backspace (iOS sends it for every caret Backspace) joins a heading to the line above instead: an empty line above is removed; text, a list item or a heading above takes the heading's text at its end; code above (behind its closing fence) takes the heading's shown text on its last line, as code (an empty code block gains that line). A heading on the first line, or under a divider, table or front matter, becomes Text. Away from a heading's text start it is an ordinary Backspace. → crates/futo-notes-editor/src/engine/commands/blocks/keys.rs `join_heading`
- Paired Backspace (`PairedBackspace`, the Backspace desktop sends; its empty-pair rule is every Backspace's, paired-typing.md) at a heading's text start joins as the joining Backspace does, and never makes a heading with text into Text: an empty line above is removed and the heading stays; text, a list item or a heading above takes the heading's text at its end; code above takes its shown text on its last line. → crates/futo-notes-editor/src/engine/commands/blocks/keys.rs `block_backspace`
- Where paired Backspace joins nothing, the heading stays a heading: on the note's first line and under a table or front matter nothing changes; under a divider the divider line is removed. An empty heading becomes Text. → crates/futo-notes-editor/src/engine/commands/blocks/keys.rs `heading_kept`
- Backspace at a quoted line's text start, under a quoted line of the same depth, joins it: under text or a list item the text joins that line's end; under an empty quote line, that line is removed. Otherwise (first line of a quote, under a heading, or under a line of another depth) it takes one quote level off the line, with a `\` where needed. → crates/futo-notes-editor/src/engine/commands/blocks/keys.rs `block_backspace`
- Delete at a quoted line's end and Backspace or Delete across a heading's line break edit as typed: the joined line's markers go with the line break (`> a|\n> b` becomes `> ab`). → crates/futo-notes-editor/src/engine/edit/plan.rs `plan`

## Typing

- Typing `# `, `> ` or `---` makes a heading, quote or divider because that is how the line reads; nothing converts the line, escapes it or writes anything else. A lone `#` is saved as `#`, a plain line. → crates/futo-notes-editor/src/engine/edit/, docs/spec/editor/portable-core/linedown.md
- An empty quote line with no space after its last `>` (`>`, `>>`, `> >`) shows as an empty quoted line, so text typed there that as typed would take the line out of its quote (`>x` is a plain line) gets the space the quote needs first, as Enter in a quote writes `> `: `>` then `x` writes `> x`, `> >` then `x` writes `> > x`. A typed space, tab, line break or `>` lands as typed. Carried formats apply to the text after the space, and a selection, a text service's text or a composition landing there takes the space too. → crates/futo-notes-editor/src/engine/edit/plan.rs `quote_space`, crates/futo-notes-editor/src/engine/line.rs, crates/futo-notes-editor/tests/fixtures/engine/blocks.json
