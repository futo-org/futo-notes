# Front matter, raw HTML and unfamiliar Markdown

- Leading YAML front matter follows the shipping rule: an optional BOM, a first line of `---` plus spaces/tabs ended by CR, LF or CRLF, and a later column-zero `---` line (spaces/tabs allowed) ended by a line break or EOF. Without that closer, and for `----`, indented, mid-note or `+++` fences, the lines stay ordinary Markdown. → crates/futo-notes-editor/src/inline/front_matter.rs, crates/futo-notes-editor/tests/foreign.rs
- Front matter is one inert metadata block: its fences are hidden, its body shows verbatim with no inline, block or reference meaning, and its block description sets `metadata`; empty metadata shows nothing. Interior blank lines and BOM, fence spacing and line-ending bytes stay exact. → crates/futo-notes-editor/src/inline/front_matter.rs
- The caret opens at the body start. Selection endpoints inside metadata move to the body start, while a selection starting at the note's start may cover it; editing input within it rejects before acceptance, input covering it changes only the body, and Backspace at the body start is a boundary no-op. Typing after a closer at EOF first ends the closer's line with the metadata's line-ending style. Only an exact recorded source edit can change metadata bytes, and the projection then reinterprets it. → crates/futo-notes-editor/src/session/front_matter.rs, crates/futo-notes-editor/tests/foreign.rs
- Body edits never rescan or copy unchanged metadata; only an edit at the opener, inside the metadata or on a line that can close an unclosed opener rescans, and an unclosed rescan is charged to EOF. → crates/futo-notes-editor/src/inline/front_matter.rs
- Raw HTML blocks follow CommonMark start/end conditions: kinds 1-5 (`<pre>`, `<script>`, `<style>`, `<textarea>`, comments, processing instructions, declarations, CDATA) own their interior blank lines until their end condition or EOF, so a fence, heading or definition-looking line inside them stays literal; kinds 6 and 7 end at a blank line. Opening one, or removing its end condition, reinterprets the following rows it now owns. Raw HTML shows as literal editable text, and typed Markdown shortcuts inside it (fence, divider, heading, quote, list) stay literal. → crates/futo-notes-editor/src/inline/row.rs, crates/futo-notes-editor/src/session/blocks/typing.rs, https://spec.commonmark.org/0.31.2/#html-blocks
- GFM footnote references and definitions keep their exact, visible source (including continuation lines) rather than becoming hidden CommonMark reference definitions; reference definitions, tables, definition-list-like text, wikilinks and block ids keep their current interpretation and bytes through unrelated edits. → crates/futo-notes-editor/tests/foreign.rs
- Malformed supported text (unclosed HTML or comments, BOMs, NUL, unclosed links/emphasis/fences) opens with its exact source, a nonblank display and an editable caret; interpretation never yields a blank successful note. Representative notes keep their incremental projection equal to a fresh open after edits. → crates/futo-notes-editor/tests/foreign.rs
- Rust, WebAssembly and native FFI block descriptions all carry `metadata`, so hosts can render front matter as a panel. → crates/futo-notes-ffi/src/editor/contract.rs, crates/futo-notes-editor/tests/wasm-block-consumer.mjs
- `<!-- -->` and `<!---->` lines are ordinary raw HTML: they display as written, their bytes survive ordinary editing and exact Undo/Redo, and the editor never writes them. Typing at the start of a raw HTML line is never refused; when the typed text turns the line into a paragraph, a following list reads as CommonMark reads it. → crates/futo-notes-editor/tests/lists/comment_seams.rs, crates/futo-notes-editor/src/session/blocks/literal_typing.rs
