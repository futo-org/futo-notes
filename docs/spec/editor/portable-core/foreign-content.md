# Front matter and unfamiliar Markdown

- Front matter is the dialect's: line 1 exactly `---` and a later line exactly `---`, with the lines between them as its body (linedown.md, "Front matter"). Without the closing line, line 1 is a divider and every line reads as usual; `--- `, a byte-order mark before `---`, `+++`, an indented or mid-note `---` are not front matter. → crates/futo-notes-editor/src/lines/block.rs, crates/futo-notes-editor/tests/fixtures/linedown/
- Front matter is inert metadata: its fence lines are hidden, each body line shows its whole text with no inline or block meaning, and its block descriptions set `metadata`. Front matter closed on the note's last line shows one empty line for the body, described as body, not `metadata`. Blank lines, fence spacing and line-ending bytes stay exact. → crates/futo-notes-editor/src/engine/line.rs, crates/futo-notes-editor/src/engine/project.rs, crates/futo-notes-editor/tests/foreign.rs
- The caret opens at the body start and never rests in front matter, also after an edit lands there. A selection's end in front matter moves to the body's start, unless the selection covers all of it (Select All); input at a range holding part of it is refused. Outside changes (sync, another program) may rewrite it. → crates/futo-notes-editor/src/engine/mod.rs `metadata_end` `outside_metadata`, crates/futo-notes-editor/src/engine/tests/front_matter.rs `front_matter_is_metadata_and_the_caret_starts_in_the_body`
- No edit changes front matter: over a selection covering all of it, typing, Enter, paste, Backspace, Delete, Cut, a composition and the toolbar's block commands replace the body only, from its start, and the front matter with its closing fence keeps its exact bytes (typing `X` over all of `---`, `title: x`, `---`, `body` saves `---`, `title: x`, `---`, `X`). Copy copies all it selects, fences included; Cut copies what it removes, the body. → crates/futo-notes-editor/src/engine/mod.rs `in_body`, crates/futo-notes-editor/src/engine/commands/clipboard/copy.rs `copied`, crates/futo-notes-editor/src/engine/tests/front_matter.rs `select_all_edits_the_body_and_keeps_the_front_matter`
- An edit that can open or close front matter (on line 1, or on a `---` line below it) re-reads from line 1; any other edit re-reads only its lines and on until the carry settles. → crates/futo-notes-editor/src/engine/read.rs
- There is no raw HTML, footnote or reference definition: `<div>`, `<!-- -->`, `[^1]` and `[id]: url` lines are plain text, shown and saved exactly as written, and Markdown on them reads as on any line. → docs/spec/editor/portable-core/linedown.md, crates/futo-notes-editor/tests/foreign.rs
- Malformed text (unclosed fences, emphasis or links, a lone CR, NUL) opens with its exact source, a display and an editable caret; opening and saving without an edit changes no bytes. → crates/futo-notes-editor/src/engine/tests/properties/
- Rust, WebAssembly and native FFI block descriptions all carry `metadata`, so hosts can render front matter as a panel. → crates/futo-notes-ffi/src/editor/projection.rs
