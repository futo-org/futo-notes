# Wikilink roles and note ids

These are the portable replacement core's contracts. The shipping Milkdown editor keeps
its existing wikilink contract until renderer integration and cutover.

- A projection reports each `[[target]]` the line reader finds with the canonical `find_wikilinks` grammar: the whole inner text is the target (`|alias`, an inner `[[` and Markdown-looking text included), a leading `!` stays text, and empty or line-crossing brackets are not links. The role's range covers the visible glyphs, brackets included; display text keeps the source spelling. → crates/futo-notes-editor/src/engine/project.rs, crates/futo-notes-editor/src/engine/tests/wikilinks/
- Wikilinks are read on every line with inline marks (plain, indented, heading, list, quote and table lines) and before link syntax, so `[[a]](u)` is a wikilink. Code spans, fenced code, an escaped bracket and front matter hold none. → crates/futo-notes-editor/src/lines/inline/scan.rs, crates/futo-notes-editor/tests/fixtures/linedown/inline.json
- A resolved link's label is its note id's shortest unique suffix. An absent or ambiguous target is unresolved (`note_id` absent) and its label is the raw target. Before any note ids arrive every link is unresolved. Resolution and labels use the canonical index, which answers exactly as `resolve_wikilink` and `shortest_unique_suffix` do. → crates/futo-notes-editor/src/engine/project.rs `resolve`, crates/futo-notes-wikilinks/src/index.rs
- Edits at a link's boundaries — completing or removing a bracket, typing inside the target, or typing next to it — save exact bytes, and Undo restores them. The edited lines' roles follow the new source. Roles are not history or saved state.
- The store reads the vault's note ids itself and delivers them to a live session. Note identity, backlinks and relink intent stay store-owned. A delivery leaves source, display, revision, selection, history and an open composition unchanged. It returns one projection per link whose resolution or label changed, and nothing for a delivery equal to the ids held. A portable page with an unreleased change answers Busy. → crates/futo-notes-editor/src/engine/commands/wikilinks/note_ids.rs, crates/futo-notes-store/src/editor_session/links.rs, crates/futo-notes-ffi/src/editor/links.rs
- A note-id delivery costs one pass over the id lists. It visits only the lines holding a link whose last component matches a changed id: each line keeps one bit per link leaf hash and a tree over the store's chunks ORs them, so a 20,000-paragraph note with sparse links enters about 85 tree nodes and lines. The 64 bits saturate at high link density: then every chunk holding links is entered. Typing computes a line's bits only when the line is read again. → crates/futo-notes-editor/src/engine/store.rs `lines_linking`, crates/futo-notes-editor/src/engine/line.rs `link_bit`
- A tapped schemeless link destination resolves to a delivered note id from the current note's folder, and the link prompt keeps a destination naming a note as typed. → crates/futo-notes-editor/src/link_target.rs, crates/futo-notes-editor/src/engine/commands/wikilinks/note_ids.rs
- The store delivers the vault's note ids when a session opens, so a host calls `refresh_note_ids` only for later vault changes. Drawing the label as one caret-proof atom, with matching caret stops, belongs to renderer integration. → crates/futo-notes-store/src/editor_session/mod.rs, crates/futo-notes-store/src/tests/editor_session/wikilinks.rs
- Completion: an unfinished `[[` run before a collapsed caret on its line (after the line's last `]`, at most 512 source bytes, both brackets shown as typed — not hidden syntax, escaped, in code or in an image — on a line with inline marks, no composition) is the engine's to describe. A request returns the run's display range (first `[` through the caret and an immediately following `]]`), the source query typed after `[[`, and up to 20 candidates in the delivered note-id order: ids whose folded text (lowercase, one Greek sigma) contains the trimmed folded query, labelled by shortest unique suffix with the full id as `detail` when the label differs. A run nothing matches is still reported with no candidates. Ids that cannot be written as `[[id]]` are never offered. → crates/futo-notes-editor/src/engine/commands/wikilinks/completion.rs, crates/futo-notes-editor/src/engine/tests/wikilinks/
- Accepting a candidate takes the requested range, query and a note id and replaces exactly that range with `[[id]]`, leaving the caret after it, as one command: one accepted edit holding only the bytes that differ (`[[Ro` accepted as `[[Projects/Roadmap]]` records `Ro` → `Projects/Roadmap]]`), one Undo that restores the typed run and caret. A claim is stale, and changes nothing, after any edit (`StaleRevision`), when the caret left the run or the run changed, or when the id is no longer in the delivered ids (`StaleClaim`). An unwritable id is `InvalidText`; a composition in progress is `CompositionActive`; a refused acceptance changes nothing. Cancelling is not calling accept: the contract keeps no completion state, so dismissal memory (Escape for the same run) is renderer-owned. Note ids are not refreshed per request. → crates/futo-notes-editor/src/engine/commands/wikilinks/completion.rs, crates/futo-notes-editor/tests/fixtures/engine/wikilinks.json, crates/futo-notes-store/src/tests/editor_session/wikilinks.rs, crates/futo-notes-ffi/tests/editor_links.rs
