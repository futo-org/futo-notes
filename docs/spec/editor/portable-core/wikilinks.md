# Wikilink roles and note ids

These are the portable replacement core's contracts. The shipping Milkdown editor keeps
its existing wikilink contract until renderer integration and cutover.

- A projection reports each `[[target]]` with the canonical `find_wikilinks` grammar: the whole inner text is the target (`|alias` and an inner `[[` included), a leading `!` stays text, and empty or line-crossing brackets are not links. The role's range covers the visible glyphs; display text keeps its source spelling. → crates/futo-notes-editor/src/inline/wikilinks.rs, crates/futo-notes-editor/tests/wikilinks.rs
- A resolved link's label is its note id's shortest unique suffix. An absent or ambiguous target is unresolved (`note_id` absent) and its label is the raw target. Before any note ids arrive every link is unresolved. Resolution and labels use the canonical index, which answers exactly as `resolve_wikilink` and `shortest_unique_suffix` do. → crates/futo-notes-wikilinks/src/index.rs
- Code spans, indented and fenced code, and HTML are isolated. A bracket that is escaped or owned by Markdown link syntax is not wikilink syntax. Front matter isolation follows #300's recognition, which does not exist yet. → crates/futo-notes-editor/src/inline/row/parse.rs
- Edits at a link's boundaries — completing or removing a bracket, typing inside the target, or typing next to it — save exact bytes, and Undo restores them. The edited rows' roles follow the new source. Roles are not history or saved state.
- The store reads the vault's note ids itself and delivers them to a live session. Note identity, backlinks and relink intent stay store-owned. A delivery leaves source, display, revision, selection, history and an open composition unchanged. It returns semantic replacements only for links whose resolution or label changed. A portable page with an unreleased change answers Busy. → crates/futo-notes-editor/src/session/note_ids.rs, crates/futo-notes-store/src/editor_session/links.rs, crates/futo-notes-ffi/src/editor/links.rs, crates/futo-notes-editor/tests/wasm-wikilink-consumer.mjs
- A note-id delivery costs one pass over the id list. It visits only the rows holding a link whose last component matches a changed id, found through a per-subtree leaf-hash mask, so a 20,000-paragraph note with sparse links visits few rows. The mask is 64 bits, so it saturates at high link density: cost is about the link rows divided by 64 per changed leaf, and the first delivery visits every link row. Keystrokes scan wikilinks only in the paragraphs they already reparse. → crates/futo-notes-editor/src/inline/tree.rs, crates/futo-notes-editor/tests/wikilinks.rs
- The store delivers the vault's note ids when a session opens, so a host calls `refresh_note_ids` only for later vault changes. A full engine never starts a projection without them. Drawing the label as one caret-proof atom, with matching caret stops, belongs to renderer integration. → crates/futo-notes-store/src/editor_session/mod.rs, crates/futo-notes-store/src/tests/editor_session/wikilinks.rs
- Completion: an unfinished `[[` run at a collapsed caret (after the line's last `]`, outside code and HTML, with literal brackets, no composition) is the engine's to describe. A request returns the run's display range (first `[` through the caret and an immediately following `]]`), the source query typed after `[[`, and up to 20 candidates in the delivered note-id order: ids whose folded text (lowercase, one Greek sigma) contains the trimmed folded query, labelled by shortest unique suffix with the full id as `detail` when the label differs. A run nothing matches is still reported with no candidates. Ids that cannot be written as `[[id]]` are never offered. → crates/futo-notes-editor/src/session/wikilink_completion.rs, crates/futo-notes-editor/tests/wikilink_completion.rs
- Accepting a candidate takes the requested range, query and a note id and replaces exactly that range with `[[id]]`, leaving the caret after it, as one isolated accepted edit: one accepted edit, one Undo that restores the typed run and caret. A claim is stale, and changes nothing, after any edit (`StaleRevision`), when the caret left the run or the run changed, or when the id is no longer in the delivered ids (`StaleClaim`). An unwritable id is `InvalidText`; a composition in progress is `CompositionActive`. Cancelling is not calling accept: the contract keeps no completion state, so dismissal memory (Escape for the same run) is renderer-owned. Note ids are not refreshed per request. → crates/futo-notes-editor/tests/wikilink_completion.rs, crates/futo-notes-store/src/tests/editor_session/wikilinks.rs, crates/futo-notes-ffi/tests/editor_links.rs, crates/futo-notes-editor/tests/wasm-wikilink-consumer.mjs
