# List interpretation and editing

- Bullet (`-`, `+`, `*`), period/parenthesis ordered markers and checked/unchecked task markers project without revealing source syntax; opening retains their exact spelling, indentation, lazy numbers and line endings. List descriptions supply depth, interpreted ordinal, task state and first/continuation-line identity so views do not parse Markdown. → crates/futo-notes-editor/src/inline/lists.rs, crates/futo-notes-editor/tests/lists.rs
- Canonical list, quote and ATX prefixes are interpreted in physical source order, including same-line nested syntax and quotes after wide or tab-padded list markers; indentation uses physical tab columns at each container origin. Task-body `>` and `#`, escaped markers and code contents remain literal unless their actual canonical events classify them as structure. → crates/futo-notes-editor/src/inline/blocks.rs
- List commands, list keys and list shortcuts share one generic edit (DECISIONS #20; Indent and Outdent are not part of it, see the Indent line below): the command states each row's intended block shape (quote depth, list depth, item start, kind, ordinal, check state, heading); rows whose shape and container columns are unchanged keep their exact bytes, and the edited items are respelled canonically around their original body bytes. The candidate must reparse to the intended rows, display, list identity (lists the intent keeps apart stay separate) and each edited row's inline runs, links, wikilinks and atoms before one host acceptance, after at most a fixed repair set: escaping a leading body character, a blank line, a standalone `<!-- -->` separator, or the other bullet/ordered delimiter for a newly created or retargeted list. Otherwise the command is refused with `UnrepresentableFormat`, leaving source, selection, history and saved state unchanged. Indent and Outdent are never refused. → crates/futo-notes-editor/src/session/blocks/list_edit/mod.rs, crates/futo-notes-editor/src/session/blocks/list_edit/fuzz_tests.rs
- Canonical spelling of an edited item: its quote prefix bytes are kept while its quote depth is unchanged (otherwise `> `); its marker is the list's existing bullet character or ordered delimiter, `-` or `.` for a new list, at the marker column of that list's unchanged items when one lies within three columns of the parent's content column (else the parent's content column); ordered markers are written at their interpreted number; one space follows the marker unless the item keeps its level and owns later rows, which keep its authored content column (up to four spaces); an unchanged ordered item whose number was its ordinal and whose list the command renumbers has only its digits rewritten (lazy numbers stay as written); an unchanged row under unchanged ancestors keeps its bytes even when two items open on its line; continuation rows are indented to the item's content column with spaces; checkboxes are `[ ] `/`[x] `; blank rows keep only their quote markers. The note's line-ending style is kept, including in inserted separator lines. → crates/futo-notes-editor/src/session/blocks/list_edit/plan.rs
- Refused list shapes: rows whose quote opens inside a list item on the item's own line (`- > b`, `- - > b`), list items whose content column falls inside a tab, two items opening on one physical line (`- - a`) when either must change, setext headings and raw HTML or front matter rows that a command would respell, lifting an item whose fenced code block is unclosed, and every case where no repair reproduces the intended rows (for the generic edit; Indent and Outdent write whitespace and refuse nothing). → crates/futo-notes-editor/src/session/blocks/list_edit/mod.rs, crates/futo-notes-editor/tests/lists/fence_promotion.rs
- List Enter splits the visible inline body with one protected action, retaining the leaving task's state and starting the new task unchecked (at an item's text start, see the next line). A text selection is removed before the split. An empty top-level list/task item exits its list while retaining an enclosing quote; an empty nested item, last or with following siblings, outdents one level (decided 2026-11-02): it joins its parent's list right after the parent item, the items that followed it at its old level become its nested children (as Google Docs and Notion do), and ordered lists on both levels are renumbered so each stays sequential, the children counting from 1. The outdent is one Undo action. Exiting at a list's last item (outside a quote) also writes a blank line above the new line, so text typed there is a paragraph rather than a lazy continuation of the item above; the exit is one Undo action. That new line projects as a plain line, not a list row, so a renderer draws its caret at the margin: of the blank lines that end a note under a list, only the first continues the last item. → crates/futo-notes-editor/src/session/blocks/lists.rs, crates/futo-notes-editor/src/inline/blocks.rs, crates/futo-notes-editor/tests/lists.rs, crates/futo-notes-editor/tests/lists/projection.rs
- With a caret at a nonempty item's text start (bullet, ordered, task, nested or quoted), Enter opens an empty item of the same list above it and keeps the caret on the item's text, as Google Docs and Notion do: `1. first step\n2. second step` becomes `1. first step\n2. \n3. second step`, a task's new item is unchecked above its retained state, and ordered lists renumber. It is the generic list edit on a staged blank row, so an empty item that cannot interrupt the text above (the first item under a paragraph or under its parent's text) gets the separating blank line; one Undo restores the exact source and selection. → crates/futo-notes-editor/src/session/blocks/list_paragraph.rs `enter_at_item_start`, crates/futo-notes-editor/src/session/blocks/list_edit/enter.rs, crates/futo-notes-editor/tests/lists/enter_at_start.rs
- An ordered split renumbers its actual list together with the split in one exact Undo/Redo action, retaining its first number and delimiter; unrelated lists and content retain their exact bytes. Ordinary text input retains lazy numbering, and loose lists remain one semantic owner across their blank and continuation lines. → crates/futo-notes-editor/tests/lists.rs
- A split keeps the item's later rows (continuation lines, nested lists, code) in the new item, so the list stays one list and its later items keep their places. When the new item has no text on its own line, a lazy continuation line is indented to its content column (`1. a\nlazy\n1. b` + Enter after `a` gives `1. a\n2. \n   lazy\n3. b`, never a paragraph followed by literal `3. b`), gaining its missing quote markers inside a quote; a marker that grows a digit moves the indented rows with it (`9. a\n   cont` gives `9. a\n10. \n    cont`). An item begins with at most one blank line, so when an empty new item's remaining rows start after blank lines those blank lines move above the new marker (`1. a\n\n   b` + Enter after `a` gives `1. a\n\n2. \n   b`), so the new item opens directly above the rows it takes and every row stays in the list. Formatting that crosses the caret line into the item's other rows closes and reopens at each side of the split, as within the line (`1. **a\nlazy** x` gives `1. **a**\n2. \n   **lazy** x`). → crates/futo-notes-editor/src/session/blocks/list_paragraph.rs `moved_item_rows`, crates/futo-notes-editor/tests/lists/enter_split.rs
- Checkbox commands target a task marker while preserving the active text selection and carried formats; pending composition commits before the checkbox action through one protected acceptance, with separate exact Undo groups for the marked text and checkbox change. → crates/futo-notes-editor/tests/lists/fixtures.rs, crates/futo-notes-store/src/tests/editor_session/list_actions.rs
- Bullet, ordered and task commands retarget the complete touched list; repeating its current kind lifts only the selected items and their physical continuation lines. Heading-to-list conversion drops the old ATX marker and optional closing hashes while retaining the inline body and final line ending. → crates/futo-notes-editor/src/session/blocks/list_edit/ops.rs, crates/futo-notes-editor/tests/lists/commands.rs
- A bullet, ordered or task command with only a caret on a blank line starts an empty item there (`- `, `1. `, `- [ ] `) as one Undo action; within a wider selection blank rows stay blank. An empty item cannot interrupt a paragraph, so a blank line directly under one gains a separating blank line first. → crates/futo-notes-editor/src/session/blocks/list_edit/ops.rs, crates/futo-notes-editor/src/session/blocks/list_edit/repair.rs, crates/futo-notes-editor/tests/lists/commands.rs
- Tab and Shift+Tab with the caret or selection in a list item (outside code) run the Indent and Outdent commands on the supplied range (next line): the same source, selection and one Undo action as the toolbar buttons. Tab always applies; Shift+Tab where Outdent is disabled (no touched line has leading whitespace) changes nothing and inserts no tab character. In a plain paragraph, heading or quote Tab is not an indent key. → crates/futo-notes-editor/src/session/blocks/commands.rs `list_tab`, crates/futo-notes-editor/tests/lists/tab.rs
- Indent and Outdent (the toolbar buttons, and Tab and Shift+Tab in a list item) are line-start whitespace edits, not list restructuring (decided 2026-11-09: the buttons are almost never greyed out, and even a repair might not be the right choice; this supersedes the 2026-11-06 empty-item nesting rule and its blank-line repair). Indent writes one tab at the start of the caret's line, or of every physical line the selection touches (a selection that only reaches a line's very start does not touch it; a setext heading's lines move together), on every shape: list items, quotes, paragraphs, headings, raw HTML, code and table rows, whose bytes are literal. It never respells a marker, renumbers an ordered list, writes a separating blank line or closes a fence, and it is never refused, so the result reparses as it reads: the first item of a list or a line indented four columns past its parent becomes an indented code block, an ordered item other than 1 nested under a paragraph becomes lazy text, and an empty item under its sibling's text reads as that sibling's setext underline (until text is typed). Inside a fenced code block the tab is added to the code line the caret or selection is on; the fence's own opener and closer lines are not touched unless nothing else is (an empty block). Outdent removes one leading tab from each touched line or, where a line has no leading tab, up to four leading spaces (a tab's width); `ToolbarState.can_indent` is always true and `can_outdent` is true exactly when some touched line has leading whitespace. Bytes outside the touched lines' leading whitespace never change, the caret and selection keep their text, and each command is one Undo action restoring the exact source and selection. Quote depth changes only through the Quote command and the Enter and Backspace exits. → crates/futo-notes-editor/src/session/blocks/line_indent.rs, crates/futo-notes-editor/src/session/toolbar.rs, crates/futo-notes-editor/tests/lists/command_eligibility.rs
- Explicit Text and a repeated list-kind command lift the selected item through its list ancestors while retaining its quote ancestry: the item becomes paragraph text, its descendants and every later row of an ancestor item move out one level per ancestor they leave, and a selected descendant of a lifted ancestor in the same format run stays listed. Key exits lift only through lists inside the item's own quote. → crates/futo-notes-editor/src/session/blocks/list_edit/shapes.rs, crates/futo-notes-editor/tests/lists/lifting.rs
- A selection spanning different block formats applies the explicit command to each original format run in source order within one protected acceptance; each newly created run is its own list. Undo restores exact original source, selection and affinity. → crates/futo-notes-editor/src/session/blocks/list_edit/ops.rs, crates/futo-notes-editor/tests/lists/mixed_commands.rs, crates/futo-notes-editor/tests/lists/ordered_tasks.rs
- An explicit list command on a bare quoted paragraph creates a root list; converting a heading inside a quote or retargeting an existing quoted list retains its quote. Typed list shortcuts keep their quoted context. → crates/futo-notes-editor/tests/lists/mixed_commands.rs
- Explicit Ordered on an ordered task owner removes checkbox state while retaining its start and delimiter. A list fragment split off by a lifted item keeps its own physical start; foreign lists keep their exact bytes and interpreted starts. → crates/futo-notes-editor/tests/lists/ordered_tasks.rs, crates/futo-notes-editor/src/session/blocks/list_edit/shapes.rs
- A typed triggering space converts `-`, `+` or `*`, a period ordered start of at most nine digits, or `[ ]`/`[x]` within a list item; Undo restores the exact pre-trigger source. Opening an authored uppercase `[X]` task is supported; typing it remains literal. Inline code and raw marked composition do not trigger these shortcuts. Ten or more digit starts, including leading zeroes, remain literal. → crates/futo-notes-editor/src/session/blocks/list_typing.rs, crates/futo-notes-editor/tests/lists/input.rs, crates/futo-notes-editor/tests/fixtures/list-actions.json
- Ordered Enter supports the maximum nine-digit start and greater interpreted following ordinals by spelling overflowing physical markers as valid lazy `1` markers; ordinary text input never renumbers existing lazy markers. → crates/futo-notes-editor/src/session/blocks/lists.rs, crates/futo-notes-editor/tests/lists/keys.rs
- A bullet (`-`, `+`, `*`) or task marker typed on the line under a paragraph starts a list item the way an ordered marker does: an empty item cannot interrupt a paragraph, so the item is written after a separating blank line (`para` + Enter + `- apples` becomes `para\n\n- apples`). Undo of the triggering space restores the typed literal marker. → crates/futo-notes-editor/src/session/blocks/list_edit/ops.rs `list_shortcut`, crates/futo-notes-editor/tests/lists/input.rs
- A list marker (`- `, `* `, `+ `, a period ordered start, `- [ ] `, `- [x] `) typed or committed at the start of an empty list item changes that item's kind and the rest becomes its text, as in Notion and Google Docs: the same kind keeps the item in its list, a bullet marker turns an empty task into a plain item, an ordered marker in a bullet list starts its own ordered list (`- a\n- ` + `1. x` becomes `- a\n1. x`), and a following `[ ] `/`[x] ` makes the item a task with that checked state (`- [ ] spinach` into an empty task gives `- [ ] spinach`). A keyboard commit of the whole string gives the same source as typing it one character at a time and is one Undo step back to the empty item; pasting it gives the same source. → crates/futo-notes-editor/src/session/blocks/list_typing.rs, crates/futo-notes-editor/src/session/blocks/typing.rs `marker_committed_into_empty_item`, crates/futo-notes-editor/tests/lists/input.rs
- Typed shortcuts join a preceding bullet list, or an ordered list only when the typed number is its interpreted next ordinal; a following list stays independent through the generic repair set (alternate delimiter, else one `<!-- -->` separator). Verification windows reach past blank lines to the nearest nonblank neighbor on each side, so a merge across blank lines is always seen. → crates/futo-notes-editor/src/session/blocks/list_typing.rs, crates/futo-notes-editor/src/inline/mod.rs, crates/futo-notes-editor/tests/fixtures/list-shortcuts.json
- Canonical projection hides standalone newline-terminated `<!-- -->` and `<!---->` block-comment lines, including their line endings and enclosing quote prefixes; existing authored comment bytes survive ordinary editing and exact Undo/Redo. This narrow standard grammar supports independent list identity because blank lines alone do not separate same-kind CommonMark lists; other raw HTML follows its own block rules (foreign-content.md). Inline comments, meaningful HTML, code contents and an EOF comment without its terminating newline retain their existing interpretation. → crates/futo-notes-editor/src/inline/empty_comments.rs, crates/futo-notes-editor/tests/lists/comment_seams.rs, https://spec.commonmark.org/0.31.2/#example-308
- The 191 shared synthetic list cases (seventy-four original list cases, twenty-four nested-container cases, twenty-seven container-command cases, fourteen list-header cases, twenty-four prefix-frame cases and twenty-three fence-container cases and five heading/quote-command cases) carry literal source, display, native UTF-16 ranges, interpreted item ordinals/check states and exact history groups in four source consumers: editor, actual store, UniFFI and compiled WASM. Fifty-four cases are marked `refused`: every consumer asserts `UnrepresentableFormat` with source and revision unchanged. Edited-item spellings follow the canonical rule above; untouched rows keep their bytes. Native source registration does not establish execution of current native binaries; these literals are not OS input captures or latency measurements. Store controls include failed append, paused retry, failed Undo and checkpoint/reopen. → crates/futo-notes-editor/tests/fixtures/list-actions.json, crates/futo-notes-editor/tests/fixtures/list-shortcuts.json, crates/futo-notes-editor/tests/fixtures/list-staging.json, crates/futo-notes-editor/tests/fixtures/prefix-frame-commands.json, crates/futo-notes-editor/tests/fixtures/fence-container-commands.json, crates/futo-notes-editor/tests/fixtures/heading-quote-commands.json, crates/futo-notes-store/src/tests/editor_session/list_actions.rs, crates/futo-notes-ffi/tests/editor_list_actions.rs
