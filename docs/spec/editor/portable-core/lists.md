# List interpretation and editing

- Bullet (`-`, `+`, `*`), period/parenthesis ordered markers and checked/unchecked task markers project without revealing source syntax; opening retains their exact spelling, indentation, lazy numbers and line endings. List descriptions supply depth, interpreted ordinal, task state and first/continuation-line identity so views do not parse Markdown. → crates/futo-notes-editor/src/inline/lists.rs, crates/futo-notes-editor/tests/lists.rs
- List Enter splits the visible inline body with one protected action, retaining the leaving task's state and starting the new task unchecked; splitting at a checked task's text start leaves the new unchecked empty item above its retained checked text. A text selection is removed before the split, and an empty list/task item exits its list while retaining an enclosing quote. → crates/futo-notes-editor/src/session/blocks/lists.rs, crates/futo-notes-editor/tests/lists.rs
- An ordered split renumbers its actual list together with the split in one exact Undo/Redo action, retaining its first number and delimiter; unrelated lists and content retain their exact bytes. Ordinary text input retains lazy numbering, and loose lists remain one semantic owner across their blank and continuation lines. → crates/futo-notes-editor/tests/lists.rs
- Checkbox commands target a task marker while preserving the active text selection and carried formats; pending composition commits before the checkbox action through one protected acceptance, with separate exact Undo groups for the marked text and checkbox change. → crates/futo-notes-editor/tests/lists/fixtures.rs, crates/futo-notes-store/src/tests/editor_session/list_actions.rs
- Bullet, ordered and task commands retarget the complete touched list; repeating its current kind lifts only the selected items and their physical continuation lines. Heading-to-list conversion retires the old heading marker, optional closing hashes or setext underline while retaining the inline body and final line ending. → crates/futo-notes-editor/src/session/blocks/list_commands.rs, crates/futo-notes-editor/tests/lists/commands.rs
- A typed triggering space converts `-`, `+` or `*`, a period ordered start of at most nine digits, or `[ ]`/`[x]` within a list item; Undo restores the exact pre-trigger source. Opening an authored uppercase `[X]` task is supported; typing it remains literal. Inline code and raw marked composition do not trigger these shortcuts. Ten or more digit starts, including leading zeroes, remain literal. → crates/futo-notes-editor/src/session/blocks/list_typing.rs, crates/futo-notes-editor/tests/lists/input.rs, crates/futo-notes-editor/tests/fixtures/list-actions.json
- Ordered Enter supports the maximum nine-digit start and greater interpreted following ordinals by spelling overflowing physical markers as valid lazy `1` markers; ordinary text input never renumbers existing lazy markers. → crates/futo-notes-editor/src/session/blocks/lists.rs, crates/futo-notes-editor/tests/lists/keys.rs
- Creating or retargeting a list prefers a supported alternate delimiter when necessary to preserve neighboring lists' exact marker bytes and interpreted starts. Typed shortcuts join a preceding bullet list, or an ordered list only when the typed number is its interpreted next ordinal; a following list stays independent. If both ordered delimiter styles conflict, one standalone standard empty HTML comment separates the required boundary; a middle empty-item exit also retains such a boundary so reopening cannot reunite its two list halves. → crates/futo-notes-editor/src/session/blocks/list_styles.rs, crates/futo-notes-editor/src/session/blocks/lists.rs, crates/futo-notes-editor/tests/lists/comment_seams.rs
- Canonical projection hides standalone newline-terminated `<!-- -->` and `<!---->` block-comment lines, including their line endings and enclosing quote prefixes; existing authored comment bytes survive ordinary editing and exact Undo/Redo. This narrow standard grammar supports independent list identity because blank lines alone do not separate same-kind CommonMark lists; it does not implement other HTML interpretation (#300). Inline comments, meaningful HTML, code contents and an EOF comment without its terminating newline retain their existing interpretation. → crates/futo-notes-editor/src/inline/empty_comments.rs, crates/futo-notes-editor/tests/lists/comment_seams.rs, https://spec.commonmark.org/0.31.2/#example-308
- The forty-six shared synthetic list-action cases use literal source, display, native UTF-16 ranges, interpreted item ordinals/check states and exact history groups through the editor, actual store, UniFFI, compiled WASM and native Swift/Kotlin consumers; they are not OS input captures or latency measurements. Store controls include failed append, paused retry, failed Undo, flush, modeled power loss, recovery and checkpoint/reopen. → crates/futo-notes-editor/tests/fixtures/list-actions.json, crates/futo-notes-editor/tests/fixtures/list-shortcuts.json, crates/futo-notes-store/src/tests/editor_session/list_actions.rs, crates/futo-notes-ffi/tests/editor_list_actions.rs
