# Tags and header tags

Tag grammar is the canonical shared rule set, not an editor copy: boundary, digit
start, 50-character limit and case-insensitive deduplication come from
`futo-notes-tags` (also re-exported by `futo-notes-model` and used by notes metadata).
The shipping renderer's tag decoration contract is unchanged. See `docs/spec/editor/tags.md`.

- Tag queries return canonical `#name` tags in first-seen order from the line reader's tag marks in the note body: on plain, indented, heading, list, quote and table lines, never inside a code span, a fenced code block, a link's destination or a URL. `header_tags` returns the leading block of tag-only lines, which stays ordinary editable text. Queries are on-demand scans; no edit runs one. → crates/futo-notes-editor/src/lines/inline/mod.rs, crates/futo-notes-editor/src/engine/commands/wikilinks/tags.rs, crates/futo-notes-editor/src/engine/tests/wikilinks/
- A projection reports each tag's display range (`#` included) as `tags`, and the host style plan as a `Tag` span: a renderer colours those glyphs and nothing else, so the tag stays plain, editable text and typing in it never shifts the line. Code spans and fenced code report none. → crates/futo-notes-editor/src/engine/project.rs, crates/futo-notes-editor/src/host/style_plan.rs, crates/futo-notes-editor/tests/host_style_plan.rs, apps/ios/Sources/Editor/TextFirst/TextFirstStyler.swift
- The body starts on the line after closed front matter, else on line 1. Front matter is never a tag source and no tag edit changes it. → crates/futo-notes-editor/src/engine/commands/wikilinks/tags.rs `body`
- Adding a header tag normalizes its spelling, rejects invalid names (`InvalidText`, after a stale revision is reported), creates the block when absent (the tag, then a blank separator line, using the first body line's own line ending, else the line ending above it, else LF; front matter closed on the note's last line gets a line ending first), appends to the last tag line otherwise, and changes nothing when the tag is already present. A lone CR is not a line ending. → crates/futo-notes-editor/tests/fixtures/engine/wikilinks.json
- Removing a header tag deletes every spelling of it from the block, keeps all other bytes, drops a line left without tags and, when the block empties, its separator. → crates/futo-notes-editor/tests/fixtures/engine/wikilinks.json
- Each change is one command naming the lines it changes: one accepted edit holding only the changed bytes, the caret and selection carried across it (a point inside removed text moves to where it was), one Undo/Redo step restoring exact bytes and selection; a composition in progress is `CompositionActive` and a refused acceptance changes nothing. Work stays in the header lines regardless of note size. → crates/futo-notes-store/src/tests/editor_session/tags.rs, crates/futo-notes-editor/src/engine/tests/wikilinks/
