# Long regions on the full path

- No block is a region: the core keeps the note as lines and reads each line from the carry the line above leaves it (whether a fence or front matter is open). After an edit the changed lines are read again, from one line above them (a delimiter row there may make that line a table header), and reading goes on down only until a line's carry equals the carry it had before; an edit that can open or close front matter reads from line 1. So a key in a long paragraph, tight or nested list, quote or fenced code block costs its own lines, the same at 20,000 lines as at 1,000, while an edit that opens a fence nothing closes reads on to the note's end. → crates/futo-notes-editor/src/engine/read.rs, crates/futo-notes-editor/tests/long_regions.rs `local_keys_in_one_giant_region_do_not_scale_with_it`, crates/futo-notes-editor/src/engine/tests/commands.rs `work_counts_do_not_grow_with_the_note`
- Typing, Backspace and Enter in the middle of a 20,000-line fenced code block or quote cost no more counted work than the old engine's cut rows did (at most about 1.5 K per key). → crates/futo-notes-editor/src/engine/tests/fences.rs `keys_in_a_long_block_cost_no_more_than_the_old_engine`, crates/futo-notes-editor/src/engine/tests/blocks.rs `keys_in_a_long_quote_do_no_more_work_than_the_old_engine`
- Typing and Backspace inside a numbered item stay local; Enter renumbers every following item that counts on (lists.md), so its work grows with the items after it; neighboring source edits are applied in one re-read instead of re-reading each item’s neighbors separately, preserving marker spelling, line endings and exact undo. → crates/futo-notes-editor/src/engine/commands/lists/number.rs, crates/futo-notes-editor/tests/long_regions.rs, crates/futo-notes-editor/src/engine/tests/lists.rs `renumbering_reads_the_changed_tail_once_and_undo_restores_its_spelling`
- One line is one reading unit: a key in a long line reads the whole line, so it costs about twice the line's length in counted work (about 4 K at 2,000 characters, 100 K at 50,000) and nothing beyond it. On the Moto g play 2023 (32-bit, release build, measured 2026-11-13 at 1% battery) each key (a typed character, Backspace, Enter, the Backspace that rejoins) takes 3.1–3.4 ms at the median and at most 4.1 ms in a 50,000-character line, under a quarter of a 60 Hz frame; at 2,000 characters under 0.4 ms. → crates/futo-notes-editor/src/engine/read.rs, crates/futo-notes-editor/tests/long_regions.rs `keys_in_one_long_line_cost_work_in_proportion_to_the_line`
- Every edit (typing, deletion, composition, commands, exact source records, Undo and Redo, and an outside change taken in) leaves each line read and shown as a fresh open of the same text reads and shows it; the property tests check this after every step of random edit sequences. → crates/futo-notes-editor/src/engine/tests/properties/checks.rs `check_fresh`, crates/futo-notes-editor/src/engine/tests/external/property.rs
- A table's rows are lines like any other: a key in a cell re-reads its own line, so no table is staged or cut, whatever its size. Navigation, inspection and row and column commands read the whole table (tables.md). → crates/futo-notes-editor/src/engine/commands/tables/mod.rs, crates/futo-notes-editor/src/engine/tests/tables/work.rs `table_edits_at_20000_rows`

- Repeating Bullet on one middle item edits that line alone (its marker comes off; no separator is written), every other byte stays exact, and Undo restores the original item. Its counted work does not grow with the list: 44 at 1,000 items and 49 at 20,000 (the old engine counted 770 and 1,099). → crates/futo-notes-editor/src/engine/commands/lists/toggle.rs, crates/futo-notes-editor/src/engine/tests/lists.rs `removing_one_middle_bullet_costs_no_more_than_before`

- A heading, quote or list command over a long selection reads and rewrites each touched line once: Quote over a whole note of 4,000 headings, or over a heading and a 2,000-line code block, costs no more counted work than the old engine did. → crates/futo-notes-editor/src/engine/commands/blocks/mod.rs `retext`, crates/futo-notes-editor/src/engine/tests/blocks.rs `quote_over_a_long_selection_does_no_more_work_than_the_old_engine`, crates/futo-notes-editor/tests/long_regions/block_selection.rs

- Opening calculates display byte and UTF-16 sizes from the source and its hidden pieces without allocating a display string per line; inline reading skips scratch buffers only when the content has no possible inline construct. Cached sizes match rendered text, including non-BMP characters, CRLF, hidden fences, front matter and dividers. → crates/futo-notes-editor/src/engine/line.rs, crates/futo-notes-editor/src/lines/inline/mod.rs, crates/futo-notes-editor/src/engine/tests/projection.rs `cached_line_sizes_match_rendered_unicode_and_hidden_frames`
