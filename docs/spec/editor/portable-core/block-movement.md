# Block movement

A block is moved to a boundary between lines as one edit (#311). The engine decides which lines
move together, where they may land and the move; a renderer names only the display position under
the finger and the boundary it is dropped on ([the mobile gesture](../mobile/block-drag.md)). Every line stays its own block in the projection: this is only
which lines move together. → crates/futo-notes-editor/src/engine/commands/moves.rs

## What lifts

- A plain line, a heading or a divider lifts alone. → crates/futo-notes-editor/src/engine/commands/moves.rs `block_lines`, crates/futo-notes-editor/src/engine/tests/moves.rs
- A plain line indented under a list item lifts alone when it is the line named. → crates/futo-notes-editor/src/engine/commands/moves.rs `block_lines`
- A list item lifts with the lines under it: the lines after it at its quote depth that are indented further, and a fence opened under it with its code, down to the first line that is not (the lines Indent moves with it, list-indent.md). A blank line ends it. → crates/futo-notes-editor/src/engine/commands/moves.rs `block_lines`
- A quoted line lifts the whole run of consecutive quote lines it is in, any list inside the quote included; a list item in a quote cannot lift on its own. → crates/futo-notes-editor/src/engine/commands/moves.rs `block_lines`
- A line of a closed code block lifts the whole block, fences included. → crates/futo-notes-editor/src/engine/commands/moves.rs `block_lines`
- A line of a table lifts the whole table. → crates/futo-notes-editor/src/engine/commands/moves.rs `block_lines`
- An image that shares its line with other content it shows (text or another image; markers, whitespace and hidden syntax do not count, so `- ![](a.jpg)[](u)`, whose link has no text, shows only the image) lifts alone when the position named is on it: `Nice!![](a.jpg)` lifts `![](a.jpg)`, and each of `![](a.jpg)![](b.jpg)` lifts alone. Anywhere else on that line the line lifts as above, the image with it. → crates/futo-notes-editor/src/engine/commands/moves.rs `image_lifted`, crates/futo-notes-editor/src/engine/commands/images/mod.rs `shows_around`, crates/futo-notes-editor/src/engine/tests/moves/images.rs
- An image lifts with its line, as above, when it is alone on the line as shown (`![](a.jpg)`, `- ![](a.jpg)`, `[](u)![](a.jpg)`), inside another mark (`[![](a.jpg)](u) x`, `**![](a.jpg)** x`, which taking it out would leave empty), or on a quote, table, code or front matter line. → crates/futo-notes-editor/src/engine/commands/moves.rs `image_lifted`
- A blank line and front matter lift nothing. → crates/futo-notes-editor/src/engine/commands/moves.rs `block_lines`
- A code block nothing closes (code to the note's end) lifts nothing, and neither does a list item whose lines run into one: wherever it went, the lines after it would turn to code. → crates/futo-notes-editor/src/engine/commands/moves.rs `block_lines`

## Where it lands

- A block may land on any boundary between lines, the top and end of the note included, except its own two edges and the boundaries inside it. → crates/futo-notes-editor/src/engine/commands/moves/slots.rs `allowed`
- Nothing lands above or inside front matter. → crates/futo-notes-editor/src/engine/commands/moves/slots.rs `inside_unit`
- Nothing lands inside a code block, after code nothing closes, inside a table or inside a run of quote lines. → crates/futo-notes-editor/src/engine/commands/moves/slots.rs `inside_unit`
- Strictly between two lines of a list (consecutive list items and the lines under them, with no blank line between) only an unquoted list item or a single unquoted plain line lands; a quote lands beside a list, never inside it. → crates/futo-notes-editor/src/engine/commands/moves/slots.rs `allowed`
- A lifted image lands where a single plain line would, and also on its own line's two edges: dropped directly above or below that line it leaves it. Neither edge is ever its own: no slot changes nothing. → crates/futo-notes-editor/src/engine/commands/moves/slots.rs `allowed`, crates/futo-notes-editor/src/engine/tests/moves/images.rs
- A boundary is a slot only where the move to it is accepted: a drop the guard would cancel, or one that changes no byte but the digits of numbered items, is never offered. `|---|` lands at the top of `| a |\n\n|---|` but not under `| a |`, which it would make a table header, and in `a\n---\nb\n---\nc` the line `a` lifts and lands nowhere, since wherever it went the `---` it leaves would open front matter. → crates/futo-notes-editor/src/engine/commands/moves/slots.rs `slots_within`, crates/futo-notes-editor/src/engine/tests/moves/slots.rs
- Whether a move is accepted is decided without making it: the lines at the seams it creates are read in their new order by the guard's rule, from the line above the lines it moves until the reading settles, and a run whose reading has settled is not read again. For every press and boundary of the fixture notes and of seeded notes (front matter, dividers, fences, tables, quotes, lists, empty tasks, photos, CRLF), a boundary is offered exactly when the real move there is accepted. → crates/futo-notes-editor/src/engine/command/trial.rs, crates/futo-notes-editor/src/engine/commands/moves/order.rs, crates/futo-notes-editor/src/engine/tests/moves/trial.rs
- Every offered slot is a move that lands, reads as a fresh open of its bytes, and is undone exactly by one Undo. → crates/futo-notes-editor/src/engine/tests/moves/slots.rs `every_offered_slot_is_a_move_that_lands`
- Listing slots changes nothing: no edit, revision or Undo step. → crates/futo-notes-editor/src/engine/command/trial.rs `lands`
- A boundary is named by its display offset and whether it is the note's end. Around a last line that shows no characters but draws something (an empty task in `a\nb\n- [ ] `, which shows `a\nb\n`), the boundary above it and the note's end share an offset and are two slots: `a` dropped above the task gives `b\na\n- [ ] `, dropped after it `b\n- [ ] \na`, and the task itself lifts, running to the note's end. → crates/futo-notes-editor/src/engine/commands/moves/slots.rs, crates/futo-notes-editor/src/engine/tests/moves/slots.rs
- After a note's final line ending the empty last line is blank and draws nothing, so the note's end past it is no slot; the boundary above that line is the one at the display's end. A boundary named like the block's own top or bottom edge is no slot either: the block above that empty last line lands at neither, and a move there is refused. → crates/futo-notes-editor/src/engine/commands/moves/slots.rs `end_twins_last_line`, crates/futo-notes-editor/src/engine/tests/moves.rs
- Of boundaries with the same name (hidden frame lines show nothing and share their offset), the first the rules allow is the slot. → crates/futo-notes-editor/src/engine/commands/moves/slots.rs `allowed`

## What changes on arrival

A block arriving strictly between two lines of a list joins that list; elsewhere it keeps its marker. These are the only bytes a move rewrites besides moving lines (#442). → crates/futo-notes-editor/src/engine/commands/lists/arrival.rs, crates/futo-notes-editor/src/engine/tests/moves/arrival.rs

- Strictly between two lines of a list the first line of the block becomes a sibling of the item below the slot and takes its leading whitespace as spelled (tabs included); the lines under it move by the same whitespace, as Indent moves them, and keep their markers (`- a\n  - b\n  - c` with `x` dropped above `c` gives `- a\n  - b\n  - x\n  - c`; a nested `  - b` dropped above a top-level item becomes `- b`). → crates/futo-notes-editor/src/engine/commands/lists/shift.rs
- It adopts the marker style of the item below: its bullet character (`* a\n* b` with `- x` dropped between gives `* x`), or numbering with its delimiter, and the space after the marker. A plain line, an indented plain line lifted alone, or a photo lifted out of its line becomes an item (`- [ ] a\n- [ ] b` with `plain` dropped between gives `- [ ] plain`; `Nice!![](a.jpg)` with the photo dropped there gives `- [ ] ![](a.jpg)`). Where its text would then read as more (a box), one `\` is written before it, as the list buttons do (`1. [ ] n` arriving among bullets gives `- \[ ] n`).
- Below a task it gains an unchecked box. A box it already has is kept with its state (`* [x] done` arriving among `- ` items gives `- [x] done`); a numbered item cannot hold a box, so among numbered items a task keeps its own bullet and box, and the numbers around it stay.
- When the line below the slot is a line under an item rather than an item, the block takes that line's whitespace and keeps its own marker, a plain line taking `- ` (`- a\n  note` with `x` dropped between gives `- a\n  - x\n  note`), so the line below stays under its item.
- Numbered lists renumber at both ends of the move under the rule editing follows (lists.md): where a numbered item left, the items after it at its level that were counting on from it close up, up to the moved block; where a block arrives as a numbered item it counts on from the numbered item above it at its new level, repeats that number in a list numbered alike, or with no numbered item above takes the number of the item below; the items below that were counting on are bumped, and a number written with leading zeros keeps its width. `1. a\n2. b\n3. c\n4. d` with `a` dropped above `d` gives `1. b\n2. c\n3. a\n4. d`, and `d` dropped above `b` gives `1. a\n2. d\n3. b\n4. c`. → crates/futo-notes-editor/src/engine/commands/lists/arrival/numbers.rs
- A hand-numbered list that was not counting in sequence is left alone: `1. a\n5. b\n9. c` with `x` dropped above `5. b` gives `2. x` and nothing else renumbers.
- A list item dropped outside any list (directly above a list's first line or below its last included) goes to the left margin with its marker, number and box as written, the lines under it moving with it (`  - b\n    - c` gives `- b\n  - c`); `3. c` dropped above `1. a\n2. b` stays `3. c`. The list it left still closes up.
- An indented plain line dropped outside any list loses its indent, with a `\` where its text would otherwise read as another block (`  # not` gives `\# not`). A plain line dropped directly above a list's first item or directly below its last stays a plain line, and a photo dropped outside a list is a plain line of its own.
- Whether a slot is offered reads the first line as it arrives (with the digits of the item below standing in for its number) and the lines under it shifted, one at a time as the reading reaches them; the renumbered lines elsewhere are not read, since a number never changes how a line reads. Lines are compared without their digits, so a move that would change only numbers is no move and is never offered. → crates/futo-notes-editor/src/engine/commands/moves/order.rs, crates/futo-notes-editor/src/engine/command/trial.rs `trial_changes`

## The move

- A move of lines reorders whole lines and writes no other byte but the arrival changes above, with one exception: the note's last line has no line ending, so a block moving to or from the last line trades endings with the line that becomes last (`a\nb\nc` with `a` moved to the end gives `b\nc\na`; `a\r\nb` gives `b\r\na`). → crates/futo-notes-editor/src/engine/commands/moves/command.rs `move_command`, crates/futo-notes-editor/src/engine/tests/moves.rs
- An image's move takes its source out of its line and writes nothing else there (its spaces stay: `a ![](x.jpg) b` leaves `a  b`), and inserts it with a line ending as a line of its own at the slot. The ending is its line's, else the line's above, else `\n`; at the note's end it goes before the image instead (`Nice!![](a.jpg)` dropped below its line gives `Nice!\n![](a.jpg)`, `Nice!![](a.jpg)\r\nb` dropped at the end gives `Nice!\r\nb\r\n![](a.jpg)`). → crates/futo-notes-editor/src/engine/commands/moves/command.rs `image_move_command`, crates/futo-notes-editor/src/engine/tests/moves/images.rs
- Blank lines are never added, removed or lifted. → crates/futo-notes-editor/src/engine/tests/moves.rs
- A move is one host acceptance and one Undo step that restores the exact bytes and selection, every indent, marker, box and number the arrival changed included. → crates/futo-notes-editor/src/engine/tests/moves.rs, crates/futo-notes-editor/src/engine/tests/moves/arrival.rs
- A selection inside the moved text (a block's lines or a lifted image), exactly that text or part of it, travels with it; moved to the note's end, a block's line ending stays behind with the line that was last. Any other selection keeps covering the text it covered and never takes in moved text that lands at its edge: an end in the moved text stays where the text before it ends, a start there goes where the text after it starts (`a\nb\nc` with `a\n` selected and `b` moved below `c` keeps `a\n` selected; the whole of `Nice!![](a.jpg)` selected with the image dropped elsewhere keeps `Nice!`). Its ends are read from the display, so a hidden marker or hidden line at a line start (`# `, `- `, `> `, a fence) is never covered by a selection ending there. → crates/futo-notes-editor/src/engine/commands/moves.rs `moved_selection`, crates/futo-notes-editor/src/engine/tests/moves/selection.rs
- A caret in the moved block moves with its text; one elsewhere stays with its line, and one at the block's end stays with the line below. A caret beside a lifted image stays with its text. When a moved line's indent, marker or box is rewritten on arrival, a caret in its text keeps its character (`pl|ain` arriving as `- pl|ain`), and one in the rewritten indent or marker lands where the text starts, as Indent and Outdent place it. → crates/futo-notes-editor/src/engine/commands/moves/command.rs `move_command`, `image_move_command`, crates/futo-notes-editor/src/engine/tests/moves.rs
- Reading and display after a move equal a fresh open of the same bytes. → crates/futo-notes-editor/src/engine/tests/moves.rs
- A move is cancelled, with no edit and no Undo step, when any line (the moved ones, the ones it passes, or a neighbor) would read as another kind of block afterwards, but a plain line or photo that becomes an item on arrival: a plain `|---|` dropped under a pipe line, a `---` reaching line 1 with a later `---`, an image taken out of `---![](a.jpg)` leaving a divider, or out of `![](a.jpg) text` leaving an indented line. → crates/futo-notes-editor/src/engine/command/mod.rs `Command::same_kind`, crates/futo-notes-editor/src/engine/commands/moves/command.rs `image_move_command`, crates/futo-notes-editor/src/engine/tests/moves.rs
- A line that lifts nothing, or a boundary that is not one of the block's slots, is refused with nothing changed. → crates/futo-notes-editor/src/engine/commands/moves.rs `move_block`
- A move against a stale revision is rejected and changes nothing. → crates/futo-notes-editor/src/engine/tests/moves.rs
- While text is marked a move is refused (`CompositionActive`), as table commands are. → crates/futo-notes-editor/src/engine/commands/moves.rs `move_block`
- While text is marked, listing slots is refused (`CompositionActive`) too. → crates/futo-notes-editor/src/engine/commands/moves.rs `block_slots_at`
- Hosts address blocks in display coordinates: `block_at` gives what a press at an offset lifts (the position under the finger: on an image, the image's characters; anywhere else on a line, that line) as its display extent and whether its bottom edge is the note's end; `block_slots` the slots inside a display range the host names, both ends included, each as a display offset and whether it is the note's end; and `move_block` moves the block to one of them. Native sessions take display bytes. _(native shells)_ → crates/futo-notes-ffi/src/editor/moves.rs, crates/futo-notes-ffi/tests/editor_block_move.rs
- A slot range outside the display is refused, never clamped. → crates/futo-notes-editor/src/engine/commands/moves.rs `block_slots_at`, crates/futo-notes-ffi/tests/editor_block_move.rs
- Listing the slots inside a range does work in proportion to that range and the few lines read at each candidate's seams, not to the note or to the lifted block: the note above or below the range, or the block, growing from 500 to 10,000 copies leaves the work the same, front matter and a divider moved under it included. → crates/futo-notes-editor/src/engine/commands/moves/slots.rs `slots_within`, crates/futo-notes-editor/src/engine/commands/moves/held.rs, crates/futo-notes-editor/src/engine/tests/moves/slots.rs `the_work_to_find_the_slots_near_a_block_does_not_grow_with_the_note`
- Whether a list holds a line is answered from that line alone: the reader carries the items that hold the next line. → crates/futo-notes-editor/src/lines/block.rs `hold`, crates/futo-notes-editor/src/engine/commands/moves/held.rs
- Listing reads further only in one rare shape, once per listing: a move that would put a `---` on the note's first line reads the note for a second `---` (front matter opens when one follows). Finding which lines lift reads the block's own lines once. → crates/futo-notes-editor/src/engine/command/trial.rs `dashes`
- A host asks for the slots near the screen, and asks again as the view scrolls. → crates/futo-notes-editor/src/session.rs `block_slots`
- *(iOS)* Puppet's `MoveBlock {line, column?, before | after}` moves what a press at UTF-16 `column` of a display line lifts (its start when the column is omitted, so an image first on its line lifts alone; a supplied column that is not a whole number on the line, a string, a fraction, a boolean or null included, is a 400 with the note unchanged) to the boundary above `before` or below `after` (below the last display line is the note's end, so after an empty last task is after it), through the same session calls. → apps/ios/Sources/App/PuppetNative/PuppetNativeVerbs+MoveBlock.swift, apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+BlockMove.swift, apps/ios/Tests/App/PuppetNativeEditorTests+Contract.swift
- *(iOS)* Puppet's `MoveBlock` answers 409 for a boundary that is not a slot (a move the guard would cancel included), or a move the engine refuses.
- *(iOS)* While text is being composed, puppet's `MoveBlock` answers 409 and leaves the note and the composition as they were. → apps/ios/Sources/App/PuppetNative/PuppetNativeVerbs+MoveBlock.swift, apps/ios/Tests/App/PuppetNativeEditorTests+Contract.swift → apps/ios/Sources/App/PuppetNative/PuppetNativeVerbs+MoveBlock.swift
