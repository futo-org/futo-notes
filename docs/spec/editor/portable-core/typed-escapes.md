# Escapes the engine writes while typing

- A numeric-entity or backslash escape the engine wrote itself just before the caret (a lone `#` at a line start, a heading's would-be closing `#`) is dropped once the next input continues the run and the line reads plain, so `#todo` typed per key, by composition commit or as one insert saves as typed. The input is planned once with the run literal and kept only when the parser confirms it, else planned as before; escapes already in the note are never rewritten. A pasted link's entities (#358) are not covered. Known gaps, as before: an edit or sync landing between the `#` and the word, and a composition or autocorrect range that covers the `#`. → crates/futo-notes-editor/src/inline/edit/written.rs, crates/futo-notes-editor/src/session/written.rs, crates/futo-notes-editor/tests/typed_tag_source.rs `words_typed_where_a_marker_would_read_as_syntax_save_as_typed`
- The run is held only while its own session plans: it is suspended around every call to the host, so an acceptance callback that types into another session never sees it. → crates/futo-notes-editor/tests/typed_tag_source.rs `a_run_held_by_one_session_does_not_respell_another`
- Table exception: a delimiter row typed under a pipe line (`a | b`, then `-|-`; outer pipes and alignment colons too) turns both lines into a table, as when written by hand, although the pipe line is an untouched line whose block changes. Every other untouched line keeps its block kind. → crates/futo-notes-editor/tests/typed_tag_source.rs `a_delimiter_row_typed_under_a_pipe_line_makes_a_table`, crates/futo-notes-editor/tests/typed_tag_source.rs `untouched_lines_keep_their_block_kind_while_a_word_is_typed`
