# Tables: cells, keys, rows and columns

These are the portable replacement core's contracts. The shipping Milkdown editor keeps
its interaction contract until renderer integration (`../interactive-elements.md`,
`../markdown-house-style.md` "Tables"). Views never spell pipes or the delimiter row.
What is a table is the dialect's rule (`linedown.md`, "Tables"): a `|` header line, a
delimiter row directly under it, then every following `|` line, at the top level only.

- A table is read from the line readings: its header, delimiter row and rows. Each line's cells are read from that line alone; unescaped `|` bounds cells and `\|` is text in its cell. Alignment comes from the delimiter row's cells (`:--` left, `:-:` centre, `--:` right). → crates/futo-notes-editor/src/engine/commands/tables/mod.rs
- `\|` inside inline code in a cell is a pipe in that code, as GitHub and Obsidian read it: `` `p\|q` `` shows `p|q` as code and the cell is not split. Outside a table, code shows `\|` as typed. → crates/futo-notes-editor/src/lines/table.rs `code_pipes`, crates/futo-notes-editor/tests/fixtures/linedown/code-and-tables.json
- A table is as wide as its widest row. A row with fewer cells lists only the cells it has and is drawn padded; a cell past the header is a column like any other, and its text is edited and formatted like any cell's (#419). → crates/futo-notes-editor/src/engine/commands/tables/mod.rs, crates/futo-notes-editor/tests/fixtures/engine/tables.json
- Table inspection projects cells in the note's own display coordinates, so one selection serves the note and the cell view. A cell's content excludes its edge spaces and tabs; an empty cell's content is the point after its first padding space. The focused cell is the one a range lies wholly inside, on a header or body line; a range on the delimiter row or outside every cell finds the table with no focus. `inspect_tables` lists every table a line of the range lies in, each once. Each row's line and the delimiter row are reported as display ranges for hosts that lay out one line per row. → crates/futo-notes-editor/src/engine/commands/tables/mod.rs
- Hosts learn a table from the projection, never from its pipes. Each shown table line's block description has `table`, read from that line alone: its role (header, delimiter row or row), its row as `TableCell` counts it (the delimiter row 0), each cell's content as inspection reports it, and where each pipe that bounds a cell shows. The projection's `tables` give each table a described line is in, whole even where the projection holds part of it: its display range, its columns (its widest row) and each column's alignment. → crates/futo-notes-editor/src/engine/table_block.rs, crates/futo-notes-editor/src/engine/tests/tables/projection.rs
- A change's projection describes the lines it read again and lists whole each table they are in; typing or removing a delimiter row, or a header's cell count changing, reads every row under it again. A host that applies each change's projection holds every line's table facts and every table's entry as a fresh projection reports them, except the rows of lines it did not describe, which shift when a row is added or removed above them: a host that draws those restyles the table's range from the change's table entry. → crates/futo-notes-editor/src/engine/tests/properties/block_mirror.rs
- A table's entry comes from the store's index, not its rows: its end from the count of delimiter rows and the lines that end tables, its width from each chunk's widest table line. A keystroke in a cell of a 20,000-row table projects that line, the line above it and the table's entry, about 10 µs on a desktop release build, as at 100 rows. → crates/futo-notes-editor/src/engine/store.rs `widest_line`
- A native style plan carries a table line as `TableRow` (with `row` and `pipes`) or `TableDelimiter`, and each table its window touches as one whole `Table` span (range, columns, alignments). A row's span carries its table's columns and alignments, so a window whose projection holds a table's header or delimiter row plans the whole table (about 11 ms at 20,000 rows on a desktop release build, as inspection did); a window inside its body plans only the rows it meets (about 8 µs). → crates/futo-notes-editor/src/host/table_plan.rs `table_window`, crates/futo-notes-editor/tests/host_style_plan/tables.rs
- The commands that apply to the focused cell are plain state: the header row cannot be deleted or have a row inserted above it, the last body row cannot be deleted, and a one-column table cannot lose its column. A disabled command changes nothing. → crates/futo-notes-editor/src/engine/commands/tables/mod.rs
- Typing in a cell lands as typed, like typing anywhere: a typed `|` starts a new cell in that row, and a typed line break breaks the row's line, which ends the table there unless the new line starts with `|`. Nothing is escaped because of what is typed. Text a text service or dictation inserts inside one cell, marked text an input method commits included, has its line breaks turned into spaces as a paste's are (edge line breaks dropped); its other characters, a `|` included, land as given. → crates/futo-notes-editor/tests/fixtures/engine/tables.json, crates/futo-notes-editor/src/engine/commands/tables/mod.rs `cell_service_text`
- A table's delimiter row is not reachable. It stays in the source and on its display line (a host need not draw it), but a caret the user moves or places never stands on it (the person typing it excepted, below), from its display start through its text's end. `move_caret` steps past it: right from the header's end to the start of the line after the row, left from there to the header's end; where no line follows the row, the caret stays at the header's end. `place_selection` puts a caret on it at its nearer edge (the header's end or the next line's start, the latter on a tie), moves a range's end on it off it toward the range's inside, so a range never takes part of the row, and makes a range with both ends on it a caret where its start goes. A range from above the table to below it covers the row, and Copy copies the whole table. `word_stop` never stops on it (where it ends the note, the stop is the header's end) and `word_at` there finds no word. The table keys skip it (below). A host's echo (`select`) is taken as given, as an image's is (images.md), and so is a caret a paste leaves on it and a selection Undo or Redo restores there: it stays until it moves. → crates/futo-notes-editor/src/engine/commands/tables/delimiter_row.rs, crates/futo-notes-editor/src/engine/selection.rs `place_selection` `move_caret`, crates/futo-notes-editor/src/engine/words.rs, crates/futo-notes-editor/tests/fixtures/engine/tables.json, crates/futo-notes-editor/src/engine/tests/tables/mod.rs `a_delimiter_row_holds_no_word_and_copies_with_its_table`
- The person typing a delimiter row writes it as text. Typing on its line (ordinary input, not a caret move, a placed selection or a key motion) leaves the caret on the row, and typing and Backspace there are ordinary text edits of that line; while that holds, every `ViewChange` and `SelectionChange` and the session's read report `writes_delimiter_row` true, so a host draws the row (muted) then and hides it otherwise. The keystroke that finishes the row (it then has as many cells as the header and ends with a closing `|` where the header line ends with one) takes the caret to the start of the first body row's first cell; when the table has no body row a blank one (`|`, then `  |` per column) is written under the delimiter row in the same edit, one Undo step of its own. Typing `| a | b |`, Enter, then `|---|---|` a character at a time reports `writes_delimiter_row` from `|-` until the last `|`, which leaves the header, the delimiter row and one blank body row, the caret in its first cell. A header with no closing pipe has no finishing keystroke. Enter, Shift+Enter and Tab at a caret on a delimiter row do the same move: the row is never split and no line goes between it and the header (Shift+Tab there is left to the host). A Backspace right after the finishing keystroke, with the caret still where it went, takes that keystroke back as an edit of its own: the character and any body row it wrote go, and the caret is back at the row's end, writing it again. Any other way off the row (an arrow, `place_selection`, a word motion) follows the rules above, `writes_delimiter_row` turns false and no caret comes back onto the row; an edit of the header that makes the row no longer read as one leaves a plain line. → crates/futo-notes-editor/src/engine/commands/tables/delimiter_row.rs `finished_row_exit` `delimiter_row_key` `untyped_table_start`, crates/futo-notes-editor/src/engine/mod.rs `writes_delimiter_row`, crates/futo-notes-editor/src/engine/edit/mod.rs `replace_input`, crates/futo-notes-editor/src/engine/tests/tables/mod.rs `typing_a_delimiter_row_writes_it_until_it_is_finished` `backspace_and_arrows_around_a_delimiter_row_being_typed`, crates/futo-notes-editor/tests/fixtures/engine/tables.json, crates/futo-notes-ffi/src/editor/contract.rs, packages/editor/src/wasmPayloads.d.ts
- Tab and Shift+Tab select the next/previous cell's content, row by row, the delimiter row skipped (Tab in the last cell appends a row and enters its first cell, under the delimiter row in a header-only table; Shift+Tab in the first cell is left to the host). Enter selects the content of the cell below, and on the last row appends a row and enters the same column. Shift+Enter is Enter: a cell holds one line. A move is a selection change with no edit and no history. → crates/futo-notes-editor/src/engine/commands/tables/keys.rs
- Entering a cell a row lacks gives that row empty cells up to it, in one edit; a last cell with no closing pipe is closed first, its bytes untouched. A header that gains cells gives its delimiter row the same count (cells of `---` with a space each side), so the two still agree. → crates/futo-notes-editor/src/engine/commands/tables/keys.rs
- Mod+Enter puts the caret on an empty line after the table: it moves to the line after the table when that line is empty, and otherwise writes one line ending after the table's last line. → crates/futo-notes-editor/src/engine/commands/tables/keys.rs
- Paragraph Enter, Shift+Enter, Tab and Shift+Tab with the range inside one cell are the table's keys, ahead of every other family. A paragraph key on a table line outside every cell (before a row's first pipe, past its last) is not the table's: Enter there writes a line break, which ends the table at that line. → crates/futo-notes-editor/src/engine/commands/tables/keys.rs
- Backspace or Delete at a collapsed caret never removes a pipe that bounds a cell (the leading pipe and the delimiter row's pipes included), the line break between two lines of one table or the one after a delimiter row: the caret stays and nothing is written. So Backspace at the first body row's start and Delete at the header's end act as between two rows, as if the delimiter row were not there, and Backspace at the start of the line after a header-only table writes nothing. On the delimiter row the caret is writing they are ordinary text edits (above). Every other deletion in a table, an escaped pipe's included, deletes as it does anywhere. → crates/futo-notes-editor/src/engine/commands/tables/keys.rs `kept_structure`, crates/futo-notes-editor/tests/fixtures/engine/tables.json
- Row and column insertion and deletion edit table lines only, name every line they change, and insert or remove whole cells at their pipes, so every untouched cell, the alignment markers and a missing final line ending keep their exact bytes. A new row is `|` then `  |` per column, in its neighbor's line ending; a row inserted below the header goes below the delimiter row, and a header-only table gains its first body row. A new column is an empty cell of two spaces (`---` with a space each side in the delimiter row) on every line that has a cell at that position or ends right before it as one of the widest rows; a shorter row stays padded. Deleting a column removes the cell and the pipe after it (for a row's last cell, the pipe before it; a last cell with no closing pipe goes alone); a line's only cell is emptied instead, and a delimiter row keeps its only cell. A command is one accepted edit and one undo step. Alignment changes, row and column reordering and multi-cell or grid paste are deferred. → crates/futo-notes-editor/src/engine/commands/tables/structure.rs
- A row or column command keeps a caret or selection in the focused cell when the cell survives; after deleting the focused row the caret goes to the start of the cell below (above, for the last row), and after deleting the focused column to the cell to its right (left, for the last column). → crates/futo-notes-editor/src/engine/commands/tables/structure.rs
- Plain-text paste inside one cell drops edge blank lines, turns every other run of whitespace holding a line break into one space, keeps edge spaces and tabs, and writes a pasted `|` as `\|`, so it never reaches another cell; a paste that would still change the row's cells is refused with `UnrepresentableFormat`. A range across cells, or from a table line out of the table, is refused with `UnrepresentableFormat` (a valid range is never answered `InvalidRange`, #355); a caret on a table line outside its cells, and a range outside every table, is ordinary paste. The clipboard family calls the cell path first. → crates/futo-notes-editor/src/engine/commands/tables/paste.rs, crates/futo-notes-editor/src/engine/commands/clipboard/paste.rs
- A link command (`set_link`, `edit_link`) never damages a table: a link stays inside one cell. A range inside one cell links it there; a selection across cells or rows of tables alone links each cell it covers in one accepted edit and one Undo step, as the inline format toggles do, and unlinking it removes each link whose text it touches; the pipes and the delimiter row take none. A selection holding table lines and other lines links only the other lines and leaves every table line's bytes as they were (inline-formatting.md). A label edit across cells or out of the table, and a caret on a table line outside every cell (before a row's first pipe, past its last, on the delimiter row), change nothing: no edit, no history. A cell's link is kept only when the row reads back with the same cells, so in a cell a destination's `|` is written `\|`, as a pasted `|` is (a link command is a command, not typing), and a link inserted at a caret in a cell writes its text's `|` the same way; Undo restores the exact bytes. A `|` line with no delimiter row under it is a plain line and is linked whole. → crates/futo-notes-editor/src/engine/commands/inline/links/mod.rs `link_command`, crates/futo-notes-editor/src/engine/commands/tables/mod.rs `outside_one_cell`, crates/futo-notes-editor/tests/fixtures/engine/links.json, crates/futo-notes-editor/tests/links/tables.rs
- A table needs no staging at any size: a key in a cell re-reads its own line, so typing and Backspace in a middle cell cost the same counted work at 20,000 rows as at 100 (about 300). Navigation, inspection and row and column commands read the whole table, since its width is its widest row; a column command also writes every row. In a 20,000-row table of URL cells (1.9 MB) on a desktop release build, Tab takes about 4 ms, inspection 12 ms, a row insert about 1.9 M counted work and a column insert 11.5 M and 46 ms. Enter past a middle row's last pipe ends the table there, so every row below reads again as a plain line: it costs about the table's bytes (about 97 K counted work at 2,000 rows). → crates/futo-notes-editor/src/engine/tests/tables/work.rs, crates/futo-notes-editor/tests/table_rows.rs `keys_in_a_middle_table_row_do_not_scale_with_the_table`
- Portable, Store and native layers expose the same operations behind the usual acceptance and acceptance barrier; each step restores exact bytes. → crates/futo-notes-editor/src/portable/tables.rs, crates/futo-notes-store/src/editor_session/tables.rs, crates/futo-notes-ffi/src/editor/tables.rs
