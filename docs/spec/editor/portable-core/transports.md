# Portable and native transports

- The portable WASM session applies every edit to its own engine at once and returns the view change together with a `HostRequest` (`token`, `sequence`, `Append` or `Resume`) for the host; the page never waits for the host before showing an edit, running a query, moving the selection or composing, and any number of requests may be outstanding. Page-local input is refused only while the page is paused or its request numbering is exhausted. → crates/futo-notes-editor/src/portable.rs
- Session-incarnation tokens and monotonic request sequences bind append and resume replies. An acknowledgement only advances the accepted revision and drops the covered requests; it releases no view change. Duplicate, old-incarnation and unknown replies change nothing, and an impossible revision rejects as `InvalidAcknowledgement` without discarding outstanding requests. → crates/futo-notes-editor/src/portable.rs
- Opening a portable page preserves the store's pause (`HostSnapshot.paused`) and copyable source; converting an attachment to portable takes the store gate and vault guard once, reports `SessionDeleted` for a deleted note, and moves source delivery to the page. A paused draft remains copyable. → crates/futo-notes-store/src/editor_session/portable.rs
- The portable store endpoint performs blocking I/O only on its host worker. Each `Append` is replayed into the store's engine and must match the page's record exactly (`ReplayMismatch` otherwise). A failed markdown save retains the draft and does not pause input; the worker's next scheduled save retries it. → crates/futo-notes-store/src/editor_session/portable.rs
- Portable request handling takes only the attachment lock, never the store gate, so input is not delayed by a save, rename or sync workflow running on another thread; the lock makes the sequence check and the replay one decision. Requests must arrive in order: an `Append` is accepted only as sequence last+1, a `Resume` at any newer number, and anything else answers `Rejected`. A duplicate of the last request returns its original result without replaying it. The reply reports the attachment's current accepted revision and pause state. → crates/futo-notes-store/src/editor_session/portable.rs
- Identity-only retargeting preserves a portable attachment's token and request sequence. Own-action source adoption offers the store's rewritten note (`RelinkOffer`) at the revision it was made for; the page applies it as one ordinary edit and Undo step only when it still holds exactly that revision with no composition active, and sends it as an ordinary `Append`. A stale offer is dropped, and the worker never independently advances past the page's source. These are development editor transport fields, with shipping bridge schemas unchanged. → crates/futo-notes-editor/src/portable.rs, crates/futo-notes-store/src/editor_session/portable.rs
- The portable/WASM facade exposes range projection, explicit selection affinity and formatting toggles against the page's current revision, so semantic descriptions always describe the displayed text. A paused page can still query its projection for display and copying. Rich view changes serialize semantic runs, correspondence and affinity in the same call that applies the edit. → crates/futo-notes-editor/src/portable.rs, crates/futo-notes-editor/tests/portable.rs
- The compiled wasm32 consumer exchanges hidden-marker edits, formatting toggles and Undo/Redo with a separate real Rust store worker; WASM ships without native filesystem/store or heavyweight service dependencies. Shipping renderers and bridge schemas remain unchanged. → scripts/test-editor-wasm.mjs, crates/futo-notes-editor/tests/wasm-consumer.mjs

- Native Swift and Kotlin sessions retain the opening store for their lifetime and serialize calls through one session attachment; detaching saves the markdown and then releases the attachment; if the save fails the session stays attached. _(native shells)_ → crates/futo-notes-ffi/src/editor
- Native input carries exact UTF-16 code units and fixed-width unsigned ranges, including malformed strings that ordinary string transport would repair; checked native-width conversion rejects oversized ranges on 32-bit runtimes. Returned deltas and semantic/source correspondence retain explicit byte coordinates, with revision-checked UTF-16 conversion queries. _(native shells)_ → crates/futo-notes-ffi/tests/editor_contract.rs
- Swift and Kotlin forward marked composition, cancellation, changed commits, explicit-placeholder OS correction, isolated input and multi-run UTF-16 replacements, explicit affinity selection and formatting through the shared engine; one compound action appends once and Undo/Redo restore exact bytes and carried formatting. Their consumers apply engine deltas and verify a reopened note starts with no persistent Undo. _(native shells)_ → crates/futo-notes-ffi/src/editor/mod.rs, crates/futo-notes-ffi/tests/editor_history.rs
- Native failures preserve editor validation kinds and checkpoint mutations as structured values; native projections add no markdown interpretation or save policy. _(native shells)_ → crates/futo-notes-ffi/src/editor/contract.rs
- Native consumers query the final note identity and drain ordered own-action view changes once; a deleted attachment rejects the drain as well as input and saving. _(native shells)_ → crates/futo-notes-ffi/src/editor/mod.rs

- A host error reply (`Deleted`, `StaleToken` or `Rejected`) pauses the page: further input is refused with `Paused` and the draft stays copyable. `resume` is the way out: its reply returns the outstanding requests the worker has not accepted, renumbered after the resume request in order, and a successful reply unpauses the page. A refused marked-text update is retried by the caller after the page resumes. These are ordered API mechanics, not an OS event-capture or slow-storage responsiveness claim. → crates/futo-notes-editor/tests/portable.rs, crates/futo-notes-store/src/tests/editor_session/portable_waiting.rs
- The native session projects the Store's remaining save delay as an optional duration, computed in the Store clock domain; no pending save returns none and already-due work may return zero. Hosts do not compare a Rust-origin raw deadline to a platform clock. → crates/futo-notes-ffi/src/editor/mod.rs, crates/futo-notes-ffi/tests/editor_contract.rs
