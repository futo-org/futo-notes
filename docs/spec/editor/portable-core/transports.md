# Portable and native transports

- The portable WASM session emits one small ordered source-edit handoff at a time; page-local completion changes the copyable draft but releases no view delta until a matching native store append acknowledgement. Further input is backpressured while that active edit is unacknowledged, so process interruption cannot discard an already displayed timer backlog. → crates/futo-notes-editor/src/portable.rs
- Session-incarnation tokens and monotonic request sequences bind append, flush and resume replies; duplicate, stale and superseded acknowledgements never apply a view delta twice, regress watermarks or claim durability from timer execution. Matching impossible watermarks reject without discarding the pending edit. → crates/futo-notes-editor/src/portable.rs
- Opening a portable page preserves the store's recovered pause and copyable source; attachment conversion waits for any prepared native identity workflow before transferring source delivery to the page and reports lock or deletion failures. A still-pending native identity transition rejects conversion until its recovery finishes, while ordinary paused recovery remains copyable. Native hosts expose the store's typed recovery issue, and resume never bypasses review-required corruption. → crates/futo-notes-store/src/editor_session/portable.rs
- The portable store endpoint performs blocking I/O only on its host worker; it validates exact source records before append acceptance and replay, and a successful flush advances durable independently from accepted. Failed storage retains the active page draft and pauses input; resume repairs and flushes the accepted prefix before a retained edit is acknowledged or retried. → crates/futo-notes-store/src/editor_session/portable.rs
- Portable request dispatch, input readiness and reply state share the store gate, vault guard and attachment lock with identity and checkpoint workflows; queued input cannot overtake a captured recovery prefix. A duplicate request preserves its original operation result without replaying it and reports the attachment's current pause and watermarks. → crates/futo-notes-store/src/editor_session/portable.rs
- Identity-only retargeting preserves a portable attachment's token and request sequence. Own-action source adoption offers the store's rewritten note at an acknowledged revision, applied by the page as one ordinary edit and Undo step only without newer input or active composition, then sent through ordinary append acceptance before its display change is released; the worker never independently advances past the page's source. These are development editor transport fields, with shipping bridge schemas unchanged. → crates/futo-notes-editor/src/portable.rs, crates/futo-notes-store/src/editor_session/portable.rs
- The portable/WASM facade exposes range projection, explicit selection affinity and formatting toggles; pending source changes block projection and selection until acceptance so semantic descriptions cannot overtake the displayed revision. A paused recovered session can still query its accepted projection for display and copying. Rich view changes serialize semantic runs, correspondence and affinity through the same acknowledgement boundary. → crates/futo-notes-editor/src/portable.rs, crates/futo-notes-editor/tests/portable.rs
- The compiled wasm32 consumer exchanges hidden-marker edits, formatting toggles, Undo/Redo and flushes with a separate real Rust store worker; WASM ships without native filesystem/store or heavyweight service dependencies. Shipping renderers and bridge schemas remain unchanged. → scripts/test-editor-wasm.mjs, crates/futo-notes-editor/tests/wasm-consumer.mjs

- Native Swift and Kotlin sessions retain the opening store for their lifetime and serialize calls through one session attachment; detaching releases the attachment while retaining accepted recovery for reopening, without an implicit markdown checkpoint. _(native shells)_ → crates/futo-notes-ffi/src/editor
- Native input carries exact UTF-16 code units and fixed-width unsigned ranges, including malformed strings that ordinary string transport would repair; checked native-width conversion rejects oversized ranges on 32-bit runtimes. Returned deltas and semantic/source correspondence retain explicit byte coordinates, with revision-checked UTF-16 conversion queries. _(native shells)_ → crates/futo-notes-ffi/tests/editor_contract.rs
- Swift and Kotlin forward marked composition, cancellation, changed commits, explicit-placeholder OS correction, isolated input and multi-run UTF-16 replacements, explicit affinity selection and formatting through the shared engine; one compound action appends once and Undo/Redo restore exact bytes and carried formatting. Their consumers apply engine deltas and verify recovery starts with no persistent Undo. _(native shells)_ → crates/futo-notes-ffi/src/editor/mod.rs, crates/futo-notes-ffi/tests/editor_history.rs
- Native failures preserve editor validation kinds, recovery stages, review issues and committed checkpoint mutations as structured values; native projections add no markdown interpretation or save policy. _(native shells)_ → crates/futo-notes-ffi/src/editor/contract.rs
- Native consumers query the final note identity and drain ordered own-action view changes once; a deleted attachment rejects the drain as well as input and saving. _(native shells)_ → crates/futo-notes-ffi/src/editor/mod.rs

- While Append awaits its matching reply, another input, selection or projection reports Busy and the prepared draft stays copyable. An outstanding Flush also backpressures input and selection while accepted projection queries remain available. A caller retains a refused complete marked-text update and retries that same update after the outstanding reply is acknowledged, without displaying an unaccepted backlog. These are ordered API mechanics, not an OS event-capture or slow-storage responsiveness claim. → crates/futo-notes-editor/tests/portable.rs, crates/futo-notes-store/src/tests/editor_session/portable_waiting.rs
- The native session projects the Store's remaining recovery flush delay as an optional duration, computed in the Store clock domain; no pending flush returns none and already-due work may return zero. Hosts do not compare a Rust-origin raw deadline to a platform clock. → crates/futo-notes-ffi/src/editor/mod.rs, crates/futo-notes-ffi/tests/editor_contract.rs
