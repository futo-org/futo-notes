# Paired typing

What a typed backtick, `*`, `~`, `[` or `]`, and Backspace in an empty pair, do. Each rule reads only the text around the caret, never what was typed before it. The characters and their pairs are one table (→ crates/futo-notes-editor/src/engine/commands/paired_typing/pairs.rs). Cases: `crates/futo-notes-editor/tests/fixtures/engine/paired-typing.json` (backtick), `paired-typing-code-blocks.json` (blocks made and closed by typing), `paired-typing-emphasis.json` (`*`, `~`), `paired-typing-brackets.json` (`[`, `]`).

## Hosts

- Paired typing is the input action `PairedTyping` (Rust `InputAction`, FFI `EditorInputAction`, the WASM payloads' `InputAction`). Every host sends it for a plain typed key, desktop and phones alike; compositions, paste and text services never use it. With text other than exactly one of `` ` ``, `*`, `~`, `[`, `]`, or while text is marked, it is `Typing` exactly (`_` and `(` never pair). → crates/futo-notes-editor/src/history.rs, crates/futo-notes-editor/src/engine/commands/paired_typing/mod.rs `paired_input`
- A host asks the engine's table whether a text is one of those characters, keeping no copy (to split a text service's commit that ends in one): Rust `is_paired_typing_key`, FFI `editor_is_paired_typing_key`, WASM `is_paired_typing_key`. → crates/futo-notes-editor/src/engine/commands/paired_typing/pairs.rs `is_paired_typing_key`
- Every Backspace key (`Backspace`, `BackspaceJoiningHeading`, `PairedBackspace`) removes one level of an empty pair first, so a phone's Backspace and the desktop's agree on pairs; the keys differ only at a heading's text start (block-commands.md). `PairedBackspace` (FFI `EditorParagraphKey`, JNI ordinal 7, the WASM payloads' `ParagraphKey`) is the desktop's Backspace. Delete has no pair rule: in a fresh pair it removes only the half after the caret. → crates/futo-notes-editor/src/engine/surface.rs `key`
- A caret move that paired typing makes (a step over, a step out, or nothing) returns no source edit, so the portable session and WASM answer `null`; the host reads the new selection from the session (`selection`). They do not report affinity: the session keeps it, so input at the same caret lands outside the format, unless the host first sends the caret again with its old affinity. Native hosts get the affinity in the returned view change. → crates/futo-notes-editor/src/portable.rs `issue_accepted`, crates/futo-notes-editor/tests/portable/unchanged_input.rs

## Where nothing pairs

- In a code block (a character that makes its line the block's closing fence aside, [fenced-code.md](fenced-code.md)) or front matter, inside inline code (a backtick at its text end aside), at a caret that carries the toolbar's formats (they wrap what is typed: `*` under Bold gives `__*__`), and after an escaping `\` (an odd run of them), every pair character is typed as typing types it. → crates/futo-notes-editor/src/engine/commands/paired_typing/caret.rs `caret_pairing`
- A pair is not written, nor grown, where it would make its line a divider or an opening fence it is not now: there the character is typed (`` `|x `` gives ` `x ``; `~|` at a line's start gives `~~|`, as `~~~~` would open a fence; `*|*` alone on a line gives `***`, a divider). → crates/futo-notes-editor/src/engine/commands/paired_typing/caret.rs `pair_makes_block`

## At a caret

- A pair is written with the caret between its halves, as typing writes text there (at a divider's edge, on a line of its own); one Undo step removes both halves. → crates/futo-notes-editor/src/engine/commands/paired_typing/caret.rs `pair_command`
- Inside an empty pair (as many opening halves right before the caret as closing halves right after, all shown, none escaped) the opening character grows it one level, as one Undo step that undoes one level: `*|*` to `**|**` to `***|***` (italic, bold, both), `[|]` to `[[|]]`. At the last level (`***|***`, `[[|]]`, `~~|~~`) it is typed plain. → crates/futo-notes-editor/src/engine/commands/paired_typing/caret.rs `empty_level`
- With a shown closing half after the caret, its character writes nothing and the caret moves past one character: `` ` `` past a backtick, `*` past a `*`, `~` past a `~`, `]` past a `]` (so `**bold |**` and `*` gives `**bold *|*`; the rest then reads as an empty pair, and a further `*` grows it). Not an Undo step. A `]` before a hidden `]` (a link's text end) is typed. → crates/futo-notes-editor/src/engine/commands/paired_typing/caret.rs `caret_pairing`
- With the caret at a format's text end, before its hidden closing marker (Code for a backtick, Bold or Italic for `*`, Strike for `~`), the character writes nothing and the caret takes the marker's far side: its display offset stays, its affinity becomes `Forward`, and the next character typed is plain (`` `bar‸` `` then ` baz` gives `` `bar` baz ``; `***b‸***` and `*` leaves bold and italic). Any hidden marks at that point are passed with it, and a longer or padded closing marker is passed whole. Before an inline code span's hidden opening marker a backtick likewise moves the caret inside it. Not an Undo step. → crates/futo-notes-editor/src/engine/commands/paired_typing/caret.rs `caret_pairing`
- Past a hidden closing marker of Bold or Italic (for `*`) or Strike (for `~`), the character writes nothing, so typing the closing marker by hand after a pair ends after the format: `**|**`, `bold`, `*`, `*` gives `**bold**|`. Where the same character stands right before that format's opening marker (the leftover of a longer opener, `**bold*|`, which reads as `*` and italic), it is typed, so `**bold**` typed by hand where no pair was written still reads bold. A backtick past a code span writes a pair (`` `a`| `` gives `` `a``|` ``). → crates/futo-notes-editor/src/engine/commands/paired_typing/caret.rs `reopens`
- Beside other hidden syntax (a link's `[` or `](u)`, an emphasis opening marker), and inside their own format (`*` in bold or italic text, `~` in struck text, where a pair would read as a hidden opener the caret cannot stand in), `*`, `~`, `[` and `]` are typed. → crates/futo-notes-editor/src/engine/commands/paired_typing/caret.rs `caret_pairing`

## Each character

- Backtick: with no backtick after the caret it writes a pair; inside a fresh pair it steps over the closing one (it never grows). → crates/futo-notes-editor/tests/fixtures/engine/paired-typing.json
- Backtick: on a line that is only spaces or tabs and two backticks, with the caret at its end and no quote, it makes a code block: the line becomes an empty block, an opening fence of three backticks and a closing fence of three backticks at the same indent, in the line's own line ending, which shows as one empty code line. The caret stays at the opening fence's end, so the letters typed next write its language, and changes report `writes_language` ([fenced-code.md](fenced-code.md)). One Undo step. A `- ` or `> ` before the backticks is not an indent, so there it writes a pair. → crates/futo-notes-editor/src/engine/commands/paired_typing/caret.rs `lone_pair_block`
- `*` writes `*|*`, except where only the line's indent and quote markers stand before the caret (`* ` would make a bullet; `> ` then `*` too), right after a letter or digit (`2*3`, `a*`), and right after a `*` outside an empty pair (`x *|` gives `x **|`): there it is typed. Before a letter it pairs (`*|*word`, which reads as italic once text is typed in it). → crates/futo-notes-editor/src/engine/commands/paired_typing/caret.rs `may_open`
- `~`: one is typed. A `~` right after one lone `~` (not part of a longer run, not escaped, and not after a letter or digit) writes `~~|~~`, the lone one becoming part of the opening half; one Undo step leaves the lone `~`. So `~~strike~` and `~` typed by hand closes strikethrough. → crates/futo-notes-editor/src/engine/commands/paired_typing/caret.rs `may_open`
- `[` writes `[|]` anywhere a pair may be written, and `]` only steps over a shown `]`; `(` never pairs. A task is typed as before: `- ` then `[` reads `- [|]` (a bullet with the text `[]`), a space `- [ |]` (the text `[ ]`), `]` steps over to `- [ ]|`, and a space makes `- [ ] |` a task. → crates/futo-notes-editor/tests/fixtures/engine/paired-typing-brackets.json
- Wikilink completion sees the run inside `[[|]]`: typing in it keeps the run, and accepting a candidate replaces the run and the `]]` after it ([wikilinks.md](wikilinks.md)); two typed `]` step over the closing brackets instead. → crates/futo-notes-editor/src/engine/commands/wikilinks/completion.rs

## Over a selection

- A pair character takes the selection to its next format level, as the toolbar's toggles write each format (inline-formatting.md), as one Undo step; the selection stays on the text. `*`: none to Italic, Italic to Bold (Italic off, Bold on: `*x*` gives `**x**`), Bold to Bold and Italic (`***x***`); a backtick: to Code; `~`: to Strike. The level is read as the toggles read the selection's formats. → crates/futo-notes-editor/src/engine/commands/paired_typing/selection.rs `next_level_turns`, crates/futo-notes-editor/src/engine/commands/inline/mod.rs `formats_turned`
- At the last level (Bold and Italic for `*`, Strike for `~`, all Code for a backtick), where the command changes nothing or refuses, over code lines, and for `[` and `]`, the character is typed over the selection as typing types it (`x ***[ab]*** y` and `*` gives `x ****|*** y`). → crates/futo-notes-editor/src/engine/commands/paired_typing/selection.rs `paired_selection`, crates/futo-notes-editor/tests/fixtures/engine/paired-typing-code-blocks.json
- `~` strikes a selection in one keystroke: a stateless rule cannot type the first of two `~` over a selection without losing the text, so one `~` is the strike, as one `*` is italic. → crates/futo-notes-editor/tests/fixtures/engine/paired-typing-emphasis.json
- A backtick over a selection across lines does what the Code block command does over it ([fenced-code.md](fenced-code.md)), one Undo step; over lines all code of one block it is typed. Over a selection holding a code block, or any of one, and a line outside it, it changes nothing and adds no Undo step, as the command does: it is never typed over the block. → crates/futo-notes-editor/src/engine/commands/paired_typing/selection.rs `paired_selection`

## Backspace

- With a collapsed caret in an empty pair (as for growing: matching runs of halves, all shown, the first not escaped, outside code, front matter and inline code), Backspace removes one level, one Undo step each: `***|***` to `**|**` to `*|*` to nothing, `[[|]]` to `[|]`, and `` `|` `` and `~~|~~` whole. A link's hidden brackets (`[|](u)`) are no pair. Over a selection, while text is marked, and anywhere else it is that Backspace key exactly. → crates/futo-notes-editor/src/engine/commands/paired_typing/backspace.rs `empty_pair`
