# Fenced code and key intent

What the text-first editor does with fenced code (the dialect's "Code" section in `linedown.md`). Cases: `crates/futo-notes-editor/tests/fixtures/engine/fences.json`.

- A fence's opening and closing lines are hidden; each code line shows its whole text, leading whitespace included, and nothing in it is read as Markdown. An empty code block shows one empty line; typing there writes the code line first. → crates/futo-notes-editor/src/engine/line.rs
- The toolbar reports code (and inline formatting off) whenever the caret is on a fence's line; inline toggles change nothing there. → crates/futo-notes-editor/src/engine/surface.rs `toolbar`
- Code block (and Wrap code block, which does the same) puts the lines the selection touches into one new fence, their text exactly as written: markers, inline syntax and indentation become code text. The new fence is three backticks, or one more than the longest line of only backticks inside it. Its lines take the first line's line ending; the last line's ending stays after the closing line. → crates/futo-notes-editor/src/engine/commands/fences/mod.rs `code_on`
- A selection that reaches into an existing block takes that whole block in: its code joins the new fence, its own fence lines go, and an empty block keeps its empty line. → crates/futo-notes-editor/src/engine/commands/fences/mod.rs `code_on`
- When every touched line is code of one block (or the caret is on an empty block), Code block takes those lines out: the code above and below them keeps a fence of its own, each part with the original opening line (a closing line written for the upper part copies the block's closing line, or the opening line's indent and fence characters when nothing closed it). An empty block leaves one empty line. → crates/futo-notes-editor/src/engine/commands/fences/mod.rs `code_off`
- A line taken out of code stays a plain line: one `\` is written before text that would otherwise read as another block (`# x` becomes `\# x`, ```` ```js ```` becomes ```` \```js ````, a `|---|` under a pipe line becomes `\|---|`). Leading whitespace and inline syntax are kept as written. → crates/futo-notes-editor/src/engine/command.rs `kept_line`
- A code block command that would change how a line outside it reads (wrapping a table's header or delimiter row alone) changes nothing, through the command guard. Each command is one Undo action that restores the exact bytes and selection. → crates/futo-notes-editor/src/engine/command.rs `Engine::run`
- Enter and Shift+Enter in code write the line's own line break, then the code line's leading spaces and tabs up to the caret; over a selection inside one block they replace it the same way. They land as typing does: a line break that leaves ```` ``` ```` on its own line closes the block there. → crates/futo-notes-editor/src/engine/commands/fences/keys.rs `code_break`
- Enter on an empty block writes its first code line and a second one, the caret on the second (typing's empty-line rule). → crates/futo-notes-editor/src/engine/edit/plan.rs
- Enter on an empty (or whitespace-only) last code line of a block that ends the note, where at most an empty line follows the closing line, leaves the block: that code line goes and the caret moves to an empty line after the closing line, at the closing line's indent. A block nothing closes is closed there. With anything after the block the line stays code, and Shift+Enter never leaves. → crates/futo-notes-editor/src/engine/commands/fences/keys.rs `leave_block`
- Enter with exactly a closed block's whole code selected keeps the block and opens an empty line after its closing line, at its indent, the caret on it. → crates/futo-notes-editor/src/engine/commands/fences/keys.rs `enter_after_block`
- Tab in code writes two spaces at a caret, or at the start of each selected line; Shift+Tab takes a leading tab, else up to two leading spaces, off each touched line. The toolbar's Indent writes one tab at the start of each touched code line, and Outdent takes off what Shift+Tab does; Indent is offered on code lines, Outdent only where a touched line has something to take off. On an empty block, Tab and Indent write its first code line. Both ends of the selection must be code of one block; otherwise code does not claim the key or button. → crates/futo-notes-editor/src/engine/commands/fences/keys.rs `code_indent`, `code_indent_state`
- Backspace at a block's first code line, or Delete at the end of the line above the block, joins that code line to the line above; the rest of the block stays code (a one-line block goes). Backspace at the line after a block, or Delete at the end of its last code line, joins that line into the code, and the closing line moves below it. Backspace on an empty block removes it. Any selection that cuts a fence keeps it the same way (interpretation-and-input.md). → crates/futo-notes-editor/src/engine/commands/fences/cut.rs `kept_frame`
