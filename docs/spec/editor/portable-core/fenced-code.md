# Fenced code and key intent

- Fenced backtick and tilde code hides its opening/closing lines, returns code and the first info-string word as language semantics, and keeps opaque body text and untouched fence spelling exact, including unmatched fences, CRLF and unknown languages; views do not parse or rewrite source for coloring. → crates/futo-notes-editor/src/inline/fences.rs, crates/futo-notes-editor/tests/fences.rs
- Code body input bypasses inline conversion and formatting; selected formatting skips code while changing prose. Enter inserts one LF and repeats the existing container prefix inside code; literal delimiter lines lengthen only the enclosing fence when needed to retain code meaning. Empty fences expose an editable body caret without showing source markers. → crates/futo-notes-editor/src/session/blocks/fences.rs
- Physical code rows keep prefix, opaque content and line ending distinct: authored blank CRLF rows retain both bytes and preserve the parser’s distinction between stripped fence indentation and opaque spaces, and unmatched EOF carets remain owned by code. Replacing a selected complete internal ending retires only its following container prefix when that ending disappears; a surviving ending keeps that prefix's exact spelling. → crates/futo-notes-editor/src/inline/fences.rs, crates/futo-notes-editor/tests/fences/physical_rows.rs
- One terminal body line ending belongs to the hidden fence frame; additional blank lines remain editable code text, and deleting them or the whole body retains the unselected closing frame. Open fences retain their exact final-newline spelling on open. → crates/futo-notes-editor/src/inline/fences.rs, crates/futo-notes-editor/tests/fences/frame.rs
- A line-start exactly-triple-backtick opener followed by an optional language word stays literal until Space or Enter converts that line to a closed, local code structure; conversion and the code-block command each form one exact Undo action and leave following content untouched. The store accepts the action before display; a refused acceptance retains the draft unchanged. → crates/futo-notes-editor/tests/fences.rs, crates/futo-notes-store/src/tests/editor_session/seams.rs
- Code Tab inserts two spaces at a collapsed supplied caret or at each selected line start; Shift+Tab removes up to two leading spaces from touched code lines. Both ends must belong to the same fenced block, each key has one exact Undo action, and non-code Tab leaves source unchanged. Renderer focus escape remains outside this key intent. → crates/futo-notes-editor/src/session/blocks/fence_tab.rs, crates/futo-notes-editor/tests/fences/keys.rs
- A code block that closes the note can be left: Enter on the empty last code line (the caret after a newline typed at the end of the body) removes that line and leaves the caret on the empty line after the closing fence. With any text after the block the line stays code. The code-block command on lines that are all code takes them out of the fence instead; the rows above and below keep their fence. → crates/futo-notes-editor/src/session/blocks/fences.rs `fence_exit`, crates/futo-notes-editor/src/session/blocks/code_command.rs `code_toggle_off`, crates/futo-notes-editor/tests/fences/keys.rs, crates/futo-notes-editor/tests/fences/commands.rs
