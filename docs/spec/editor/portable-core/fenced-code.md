# Fenced code and key intent

What the text-first editor does with fenced code (the dialect's "Code" section in `linedown.md`). Cases: `crates/futo-notes-editor/tests/fixtures/engine/fences.json`, for a block as one object and its edges `code-block-object.json` beside it, and for a fence under a list item or in a quote `fences-under-items-and-quotes.json`.

- A fence's opening and closing lines are hidden; each code line shows its whole text, leading whitespace included, and nothing in it is read as Markdown. An empty code block shows one empty line; typing there writes the code line first. Immediately after typing an opening fence, the caret stays at its hidden end so subsequent letters write its language; Enter starts the first code line. Under paired typing a backtick after a line's lone pair writes an empty block, the caret at the opening fence's end; Enter there starts its first code line ([paired-typing.md](paired-typing.md)). → crates/futo-notes-editor/src/engine/line.rs
- An indented opening fence (under a list item) still opens a block at the top level, drawn at the left margin: a code line starting with the opening fence's leading whitespace hides it, so indent past the fence's shows as code, and a line with less or other leading whitespace shows whole (linedown.md). The file keeps every byte. → crates/futo-notes-editor/src/lines/block.rs `fenced`
- Enter's new code line, an empty block's first line (typing, paste, Enter, Tab, Indent, a heading joined into it) and each pasted line after the first start with the opening fence's leading whitespace; Tab, Indent, Shift+Tab and Outdent act after it. → crates/futo-notes-editor/src/engine/code_block.rs `fence_indent`
- A fence after `>` is quoted text, never a block (linedown.md): the line reader reads no fence in a quote. → crates/futo-notes-editor/src/lines/block.rs `read_block`
- On a quoted line typing backticks and Enter act as on any quoted line: Enter continues the quote. → crates/futo-notes-editor/src/engine/commands/blocks/keys.rs `block_enter`
- While the caret stands at an opening fence's hidden end (its letters write the language), every `ViewChange` and `SelectionChange` reports `writes_language` true, and the session's `writes_language` read says so after input that returns no change. The caret's pin there is the one fact: typing a fence, with or without paired typing, and Undo or Redo back to that caret report it; a reopened session never does. → crates/futo-notes-editor/src/engine/mod.rs `writes_language`
- `place_selection` is the user's own selection (a press, a drag): as `select_with_affinity`, but the same range also ends a selected block and a language caret, which becomes an ordinary caret on the block's first code line at the same display offset (on an empty block, on its line, where typing writes the code line first). It is also fitted out of images ([images.md](images.md)) and off a table's delimiter row ([tables.md](tables.md)); a wikilink is left as it is. → crates/futo-notes-editor/src/engine/selection.rs `place_selection`
- A host writes a block's header with `set_code_block_header` (a display offset in its code, a language and a name; an empty one clears it). It rewrites only the opening fence's info string: the language token, and the `name:` value in place; `hl:`, `ll:`, other text and their order, the fence characters and the indent stay. A name not there yet is written after the language, before the other keys; a repeated `name:` becomes one. → crates/futo-notes-editor/src/engine/commands/fences/header.rs, crates/futo-notes-editor/src/lines/fence_info.rs `write_fence_info`
- When the line would not read back through the line reader as the same opening fence with exactly the requested language and name and its marks unchanged (a language with whitespace before its end or that reads as a key, a name with outer spaces or a key, a control character or line break, clearing a language that other text would replace), and for a backtick in a backtick fence's info (CommonMark would not read the line as a fence), it changes nothing and refuses with `InvalidText`. → crates/futo-notes-editor/src/engine/commands/fences/header.rs
- Hosts ask the engine what a header field keeps of typed text and keep no rule of their own: `typed_code_block_name` drops backticks and control characters (a tab or line break becomes a space) and keeps outer spaces, since a field is typed a character at a time (the host trims the name it writes); `typed_code_block_language` keeps the same as one word: no leading whitespace, whitespace with text after it written `-` (`c sharp` gives `c-sharp`), and whitespace at its end kept as one space, since a keyboard commits a picked word and then a space and typing `c`, space, `s` reads `c-s`. Module functions on WASM, `editor_typed_code_block_language` and `editor_typed_code_block_name` on FFI. The rule is the same for both fence kinds, though Markdown lets a tilde fence's info hold a backtick, so a block's header reads the same whichever fence it has. `set_code_block_header` drops whitespace at a language's end (`Python ` writes `Python`; only whitespace writes none) and writes what they keep, except what it still refuses: a language that reads as a key (`name:`, `hl:` or `ll:` at its start) or, on a tilde fence, starts with `~`, and a name with outer whitespace or a key at a word start (`a hl:2`); such a name is never rewritten. → crates/futo-notes-editor/src/lines/fence_info.rs `typed_code_block_language` `typed_code_block_name`, crates/futo-notes-editor/src/wasm/code_blocks.rs, crates/futo-notes-ffi/src/editor/code_blocks.rs, crates/futo-notes-editor/src/engine/tests/fence_headers.rs `what_a_header_field_keeps_is_written_or_refused_for_a_named_reason` `a_language_field_keeps_one_trailing_space_that_the_header_drops`
- Values the block already has change no text and add no Undo step; a language caret on that block still becomes an ordinary caret, as below. → crates/futo-notes-editor/src/engine/commands/fences/header.rs
- A header it writes is one Undo step that restores the exact bytes and the selection. No display offset moves, so the selection, a selected block and the affinity stay; a language caret on that block becomes an ordinary caret at the start of its code. A block nothing closes and a fence under a list item work the same. → crates/futo-notes-editor/src/engine/commands/fences/header.rs
- Hosts draw a block from what the engine reports, never from the info string: each shown code line has its 1-based number in its block, whether it is the block's first and last code line, and its `hl:`/`ll:` mark; each block has its whole display range, language, `name:` and line count, even where a projection or style window holds only part of it. → crates/futo-notes-editor/src/engine/code_block.rs, crates/futo-notes-editor/src/host/style_plan.rs
- Adjacent blocks stay apart: each reports its own range and numbers from 1. An empty block shows one line, numbered 1, first and last, in a block of one line. A block nothing closes ends at the note's last line. → crates/futo-notes-editor/src/engine/code_block.rs
- A change's projection describes the lines it read again, and the code line after them when it became or stopped being its block's first line; it lists whole every block a described code line is in. → crates/futo-notes-editor/src/engine/read.rs `first_flipped_end`
- A host that applies each change's projection holds every line's block facts and every block's entry as a fresh projection reports them, except the numbers and marks of code lines the change did not describe, which shift when a line above them in their block is added or removed or their block is split or joined: a host that draws those restyles the block's range from the change's block entry. → crates/futo-notes-editor/src/engine/read.rs `edit`
- An info string change reads the whole block again. → crates/futo-notes-editor/src/lines/block.rs `OpenFence`
- [iOS text-first] A fenced block shows its language once, preserving its case, in a 16-point header above its first code line; adjacent fenced blocks each show their own label. Long labels truncate within half the code width and never change saved bytes. → apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+Style.swift, apps/ios/Sources/Editor/TextFirst/TextFirstLayoutFragments.swift
- [Android text-first] How a fenced block draws and takes touch on Android: [fenced-code-android.md](fenced-code-android.md).
  > **Gap:** *(iOS)* A block shows its language label only: no `name:`, line numbers, `hl:`/`ll:` bands, copy glyph, selected-block look or "add a line" affordances.
  > **Gap:** *(Android)* Line marks (`hl:`, `ll:`) are not drawn and cannot be set; the fence keeps their text.
  > **Gap:** *(Android)* Tab and Up from a header field opened by a long-press do not reach the field.
  > **Gap:** *(iOS)* A block that ends the note can show a second label on an empty last code line, and a block on a long note's quick first screens shows no label until that text is restyled (an edit there). iOS infers the first code line from a projection instead of the style plan's `first`.
- The toolbar reports code (and inline formatting off) whenever the caret is on a fence's line; inline toggles change nothing there. → crates/futo-notes-editor/src/engine/surface.rs `toolbar`
- Code block (and Wrap code block, which does the same) puts the lines the selection touches into one new fence, their text exactly as written: markers, inline syntax and indentation become code text. Quoted lines are no exception: no block is made inside a quote, so the fence stands at the top level with their `>` as code text. The new fence is three backticks (a line of three or more backticks alone is always a fence, so never one of the lines put in). Its lines take the first line's line ending; the last line's ending stays after the closing line. → crates/futo-notes-editor/src/engine/commands/fences/mod.rs `code_on`
- Code block over a selection that already holds a code block, or any of one, together with a line outside it (above, below or both) changes nothing and adds no Undo step: a block is never put inside another. Over exactly a block's code, or the block selected as one object, it takes the code out (below). → crates/futo-notes-editor/src/engine/commands/fences/mod.rs `code_on`, crates/futo-notes-editor/tests/fixtures/engine/fences.json
- When every touched line is code of one block (or the caret is on an empty block), Code block takes those lines out: the code above and below them keeps a fence of its own, each part with the original opening line (a closing line written for the upper part copies the block's closing line, or the opening line's indent and fence characters when nothing closed it). An empty block leaves one empty line. → crates/futo-notes-editor/src/engine/commands/fences/mod.rs `code_off`
- A line taken out of code keeps how it looked, so it stays a plain line (the rule is appearance, not exact bytes: putting a line into code and taking it out again may add a `\`): one `\` is written before text that would otherwise read as another block (`# x` becomes `\# x`, ` ```js ` becomes `\```js`, a `|---|` under a pipe line becomes `\|---|`). Leading whitespace and inline syntax are kept as written. → crates/futo-notes-editor/src/engine/command.rs `kept_line`
- A code block command that would change how a line outside it reads changes nothing: over lines that start below a table's header or end above its last row it writes nothing, and the command guard cancels any other. Each command is one Undo action that restores the exact bytes and selection. → crates/futo-notes-editor/src/engine/commands/fences/mod.rs `cuts_table`, crates/futo-notes-editor/src/engine/command/run.rs `Engine::run`
- Enter and Shift+Enter in code always write a line break, never leave the block: the line's own line break, then the opening fence's leading whitespace and the shown code's leading spaces and tabs up to the caret, on any code line, blank or last, of any block; over a selection inside one block they replace it the same way. They land as typing does: a line break that leaves ` ``` ` on its own line closes the block there. → crates/futo-notes-editor/src/engine/commands/fences/keys.rs `code_break`
- Under paired typing a backtick or `~` that makes its code line the block's closing fence ends the block there, and the block's old closing line, which would then open a block of the text below, is removed in the same edit with its line break: one Undo step, the caret after the typed character. The code lines between become text. A fence too short to close is code. → crates/futo-notes-editor/src/engine/commands/paired_typing/caret.rs `closes_block`, crates/futo-notes-editor/tests/fixtures/engine/paired-typing-code-blocks.json
- Enter on an empty block writes its first code line and a second one, the caret on the second (typing's empty-line rule). → crates/futo-notes-editor/src/engine/edit/plan.rs
- Enter and Shift+Enter with exactly all of a block's code selected (an ordinary selection) remove the code and leave the block with one empty code line, the caret on it. → crates/futo-notes-editor/src/engine/commands/fences/selected.rs `emptied_block`
- Tab in code writes two spaces at a caret, or at the start of each selected line's shown code; Shift+Tab takes a leading tab, else up to two leading spaces, off each touched line's shown code. The toolbar's Indent writes one tab at the start of each touched line's shown code, and Outdent takes off what Shift+Tab does; Indent is offered on code lines, Outdent only where a touched line has something to take off. On an empty block, Tab and Indent write its first code line. Both ends of the selection must be code of one block; otherwise code does not claim the key or button. → crates/futo-notes-editor/src/engine/commands/fences/keys.rs `code_indent`, `code_indent_state`
- A code block is one object. A host selects it with `select_code_block` (a display offset in its code, as a tap on its header gives), and the engine's key rules below select it too; every `ViewChange` and `SelectionChange` then reports it as `selected_block`, its display range, which the selection equals. An empty block's selection is a caret on its one line. Selecting the same range again keeps it (a host's echo); any other selection, `place_selection` of any range, any edit, and Enter end it. Undo and Redo restore it with the selection. → crates/futo-notes-editor/src/engine/commands/fences/selected.rs
- Backspace or Delete on the selected block removes it whole, fences included, and leaves the line it stood on empty, the caret there. Typing, paste and composition over it replace it whole with their text; a paste ends it even when its text is the block's own, the caret then on the line after it (clipboard.md); Cut takes it whole and Copy copies it whole, fences included. Each is one Undo step that restores the selected block. → crates/futo-notes-editor/src/engine/commands/fences/selected.rs, crates/futo-notes-editor/src/engine/commands/fences/reach.rs `block_reach`
- Enter and Shift+Enter on the selected block put the caret at the end of its last code line and change nothing. On a selected empty block they put the caret at the start of the line after the block, with no edit; where no line follows or that line opens another block, on an empty line opened after it as `OpenLineAfterCodeBlock` opens one, as one Undo step. Tab and Indent act on its code lines as on a selection of them. → crates/futo-notes-editor/src/engine/commands/fences/selected.rs `selected_block_key`, crates/futo-notes-editor/src/engine/commands/fences/open_line.rs `below_block`, crates/futo-notes-editor/tests/fixtures/engine/code-block-object.json
- Backspace in a block down to one empty line (an empty block, or one empty code line) selects the block; the next Backspace removes it. Backspace at the start of a block's code otherwise does nothing: a block never joins the line above it. Delete at the end of a block's code does nothing. → crates/futo-notes-editor/src/engine/commands/fences/edges.rs `backspace_at_block`, `delete_at_block`
- Backspace at the start of the line right after a block's closing line selects the block, and removes that line when it is blank (spaces and tabs only). A line with a marker (a list item, quote, heading or indented line) takes Backspace by its own rule first. Delete at the end of the line right before an opening fence selects the block; a blank line there is removed instead, and the caret goes to the start of the block's code. Every Backspace at the note's start, on a blank first line right above an opening fence, removes that line the same way, so the block opens the note (an empty block or one nothing closes too); above any other line at the note's start it does nothing. → crates/futo-notes-editor/src/engine/commands/fences/edges.rs
- `OpenLineBeforeCodeBlock` and `OpenLineAfterCodeBlock` open an empty line before the opening line or after the closing line of the block the range starts in, at that line's indent, the caret on it: the way to a line beside a block that starts or ends the note, or that touches another block. A block nothing closes is closed first, with its opening line's indent and fence characters. Outside code they change nothing. Each is one Undo step. → crates/futo-notes-editor/src/engine/commands/fences/open_line.rs
- `OpenCodeLineBelow` opens a new code line after the code line the range ends on, and `OpenCodeLineAbove` one before the code line it starts on, the caret on it, at the indent Enter at that line's end writes (the opening fence's leading whitespace, then the shown code's); the selection's text stays. On an empty block they write its first code line and a second, the caret on the second (below) or the first (above). Outside code they change nothing. Each is one Undo step. → crates/futo-notes-editor/src/engine/commands/fences/open_line.rs `open_code_line`, crates/futo-notes-editor/tests/fixtures/engine/code-block-object.json
- Caret movement is the host's: arrows into, out of and over a block (ArrowDown on the last code line of a block that ends the note opens a line after it), and presses on its header and edges, reach the engine only through `select_code_block`, a selection (`place_selection` for the user's own press), `set_code_block_header`, and the commands above. → crates/futo-notes-editor/src/engine/commands/fences/selected.rs `select_code_block`
