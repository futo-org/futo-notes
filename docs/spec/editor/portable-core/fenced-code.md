# Fenced code and key intent

- Fenced backtick and tilde code hides its opening/closing lines, returns code and the first info-string word as language semantics, and keeps opaque body text and untouched fence spelling exact, including unmatched fences, CRLF and unknown languages; views do not parse or rewrite source for coloring. → crates/futo-notes-editor/src/inline/fences.rs, crates/futo-notes-editor/tests/fences.rs
- Code body input bypasses inline conversion and formatting; selected formatting skips code while changing prose. Enter inserts one line break in the caret line's spelling (interpretation-and-input.md) and repeats the existing container prefix plus the code line’s leading spaces and tabs before the caret; literal delimiter lines lengthen only the enclosing fence when needed to retain code meaning. Empty fences expose an editable body caret without showing source markers. → crates/futo-notes-editor/src/session/blocks/fences.rs
- Empty fenced code repeats its authored container body prefix for Enter, Shift+Enter and multiline typed or pasted input. With no authored body row, continuation uses the opener’s content indentation while retaining quote markers and tabs; list markers stay on the opener and never become code input, including at unmatched EOF. → crates/futo-notes-editor/src/session/blocks/fences.rs `fence_continuation_prefix`, crates/futo-notes-editor/tests/fences/keys.rs, crates/futo-notes-editor/tests/fences/input.rs
- Physical code rows keep prefix, opaque content and line ending distinct: authored blank CRLF rows retain both bytes and preserve the parser’s distinction between stripped fence indentation and opaque spaces, and unmatched EOF carets remain owned by code. Replacing a selected complete internal ending retires only its following container prefix when that ending disappears; a surviving ending keeps that prefix's exact spelling. → crates/futo-notes-editor/src/inline/fences.rs, crates/futo-notes-editor/tests/fences/physical_rows.rs
- One terminal body line ending belongs to the hidden fence frame; additional blank lines remain editable code text, and deleting them or the whole body retains the unselected closing frame. Open fences retain their exact final-newline spelling on open. → crates/futo-notes-editor/src/inline/fences.rs, crates/futo-notes-editor/tests/fences/frame.rs
- A line-start exactly-triple-backtick opener followed by an optional language word stays literal until Space or Enter converts that line to a closed, local code structure; conversion and the code-block command each form one exact Undo action and leave following content untouched. In a list item the code block opens inside the item: its body and closing rows are indented to the item's content column (keeping any quote markers), so the list continues around it (`- ` + typed ` ``` ` + Enter gives ` - ```\n  \n  ``` `). A task's text follows its checkbox, where no fence can open, so backticks typed there stay text and Enter is the task's own Enter; a table row likewise stays a row of cells. The body and closing rows take the caret line's line ending. The store accepts the action before display; a refused acceptance retains the draft unchanged. → crates/futo-notes-editor/src/session/blocks/fences.rs `fence_conversion`, crates/futo-notes-editor/tests/fences.rs, crates/futo-notes-editor/tests/fences/keys.rs, crates/futo-notes-editor/tests/fences/input.rs, crates/futo-notes-store/src/tests/editor_session/seams.rs
- Code Tab inserts two spaces at a collapsed supplied caret or at each selected line start; Shift+Tab removes a leading tab, or else up to two leading spaces, from touched code lines. The toolbar's Indent button puts one tab on the caret's code line or on every touched code line (the empty line of a fresh code block included, with its list indentation first inside a list item), and Outdent takes one tab, or else up to two spaces, off; neither ever touches a fence's opening or closing line, a code block with no line between them has nothing to indent, and Outdent is disabled where no touched line has anything to take off. Both ends must belong to the same fenced block, each key has one exact Undo action. Outside code, Tab in a list item is the Indent command (list-indent.md) and elsewhere leaves source unchanged. Renderer focus escape remains outside this key intent. → crates/futo-notes-editor/src/session/blocks/fence_tab.rs, crates/futo-notes-editor/tests/fences/keys.rs
- A code block that closes the note can be left: Enter on the empty last code line (the caret after a newline typed at the end of the body) removes that line and leaves the caret on the empty line after the closing fence. Inside a quote or list item the new line is at that container's level (`> `, the item's indent), the way Enter continues a quote. With any text after the block the line stays code. → crates/futo-notes-editor/src/session/blocks/fences.rs `fence_exit`, crates/futo-notes-editor/tests/fences/keys.rs
- When a code block ends the note, a saved note's final line ending leaves an empty line after the closing fence at the same display position as the end of the last code line; a caret there is on the code, so typing and Enter at the end of that line edit the code rather than refusing. Toolbar state and formatting commands use that same code ownership: inline toggles remain inactive, Code block removes the touched code, and genuine prose after the fence remains prose. Rendering retains the hidden frame and synthetic EOF records. → crates/futo-notes-editor/src/session/blocks/fences.rs `fence_input`, crates/futo-notes-editor/tests/fences/keys.rs `a_code_block_ending_a_saved_note_takes_enter_and_typing_at_its_last_line`, crates/futo-notes-editor/src/inline/block_queries/visit.rs, crates/futo-notes-editor/tests/inline/toolbar.rs
- Enter with a selection that is exactly one code block's whole body keeps the block and acts after it: an empty line below the closing fence (at the block's container level), the caret on it, also when the block is the last in the note. Replacing the selection by typing or deleting still works on its text. An unclosed fence has no after: Enter acts at the end of the selection. → crates/futo-notes-editor/src/session/blocks/fences.rs `selected_fence`, `fence_selected_enter`, crates/futo-notes-editor/src/session/paragraphs.rs, crates/futo-notes-editor/tests/fences/keys.rs
- A replacement spanning an entire closed code body and text outside it retires that fence’s dependent hidden framing, preserving unselected text and line endings; selecting only code body text retains its frame. Cut parser rows use the complete canonical opener, body and closer for that ownership decision. The replacement, its exact source and selection are one Undo action across direct, native OS and explicit multi-run input. → crates/futo-notes-editor/src/inline/edit/context.rs, crates/futo-notes-editor/tests/fences/protected_input.rs
- The code-block command on lines that are all code takes the touched rows out of the fence; the rows above and below keep their fence. The rows become plain text: anything that would read as Markdown structure (`# x`, `- a`, `> q`, `1. x`, `---`) is kept literal with a backslash, and leading and trailing spaces or tabs are encoded so they are not dropped and the display selection stays valid. Pipes use numeric entities so table-looking text stays prose, including a converted delimiter beside an untouched header; tables outside the converted rows retain their structure. → crates/futo-notes-editor/src/session/blocks/code_command.rs `code_toggle_off`, `prose_literal`, crates/futo-notes-editor/tests/fences/commands.rs, crates/futo-notes-editor/tests/fences/code_off.rs
- Removing code retains enclosing quote/list prefixes while retiring hidden fence indentation; opaque body spaces and tabs remain visible. A first-code list item keeps its marker exactly once when the frame splits, and later fenced sections use the item’s continuation prefix. With no body row, the empty enclosing container remains and the retired frame’s ending adds no visible text. → crates/futo-notes-editor/src/inline/blocks.rs `container_prefix`, crates/futo-notes-editor/src/session/blocks/code_command.rs `code_toggle_off`, crates/futo-notes-editor/tests/fences/code_off.rs

- Code block wraps every selected written physical line, including mixed headings, lists, quotes and existing code, in one fence as one Undo action; a selection wholly within one code block retains the code toggle-off behavior. The command leaves neighboring source exact and chooses a fence longer than any body backtick run. → crates/futo-notes-editor/src/session/blocks/code_command.rs `wrap_code_block`, crates/futo-notes-editor/tests/fences/commands.rs
