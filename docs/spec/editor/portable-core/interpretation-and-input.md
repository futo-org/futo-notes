# Exact source, interpretation and input

- A session opens exact UTF-8 source, including CRLF, trailing whitespace and final-newline spelling; opening and dropping an unchanged store session writes nothing. → crates/futo-notes-editor, crates/futo-notes-store/src/editor_session
- Lines an action does not edit keep their exact bytes and line endings: a command edits only the lines it acts on (renumbering a numbered list is the one exception), and is cancelled with no edit and no history when it would change the block of any other line (a fence, front matter or table opened or closed). Nothing is respelled to fit a reader. Undo restores exact in-memory bytes; authored note writes may append the final line ending required by the save contract (recovery.md). → crates/futo-notes-editor/src/engine/command.rs `Engine::run`
- Insertion, deletion and replacement use distinct source/display UTF-8 byte coordinates; revision-checked conversions expose distinct source/display UTF-16 code-unit ranges for native hosts. Hidden markers have explicit source/display correspondence; an HTML entity is literal text and shows as typed; one-to-one stretches arrive as literal runs, never per-byte records. → crates/futo-notes-editor/src/coordinates.rs, crates/futo-notes-editor/tests/inline/correspondence.rs
- Reversed or out-of-range edits, UTF-8 character splits, UTF-16 surrogate splits, unpaired surrogate input and stale revisions reject explicitly before acceptance, leaving text, selection and history unchanged; input preserves exact line endings and Unicode spelling. → crates/futo-notes-editor/src/coordinates.rs, crates/futo-notes-editor/tests/unicode.rs
- Identical selection/affinity echoes retain carried formatting and the typing group; an actual selection or affinity change breaks the run even if the caret later returns. Selection-only updates carry the current source revision and create no source delta or history step; Undo/Redo restore the exact selection, affinity and carried formats before/after their original edit. → crates/futo-notes-editor/src/session.rs
- Caret movement and selection collapse stop at extended grapheme boundaries, including combining sequences, joined emoji, flags and CRLF; valid foreign replacement ranges may address code-point boundaries within a grapheme. A caret supplied between a CRLF's CR and LF acts at the end of its line (before the CR) for selection, typing, composition, paste and every key, and a selection endpoint there widens over the whole break, so no input there refuses or leaves a bare CR. → crates/futo-notes-editor/src/movement.rs, crates/futo-notes-editor/src/session.rs `outside_crlf`, crates/futo-notes-editor/tests/paragraphs.rs
- Input acceptance holds an exclusive session borrow that prevents synchronous callback re-entry; repeated native notifications using the original revision reject before host acceptance. → crates/futo-notes-editor/src/session.rs, crates/futo-notes-editor/tests/unicode.rs
- Each successful operation returns one ordered display replacement, its resulting selection and the accepted revision; views apply these changes without parsing source. The portable callback is a host acceptance seam, not a save acknowledgement. → crates/futo-notes-editor/src/types.rs, crates/futo-notes-editor/tests/common/mod.rs
- Consecutive adjacent single-grapheme typing, backward deletions or forward deletions of the same kind join a history group while the injected monotonic clock advances less than 500 ms between accepted inputs; exactly 500 ms, a backward clock movement, a changed selection/affinity, a direction change, a newline or an isolated action starts a new group. Rejected input does not change the group. → crates/futo-notes-editor/src/history.rs, crates/futo-notes-editor/tests/history.rs
- Undo and Redo restore exact source bytes plus opening/resulting selection, affinity and carried formats for the entire group, including local marker repairs; each group travels through one acceptance before one display change. Failed acceptance preserves the whole group and current draft, and a new accepted edit discards the redo branch. → crates/futo-notes-editor/src/session.rs, crates/futo-notes-editor/tests/history.rs
- Replaying a source record while composition is active rejects with `CompositionActive` before host acceptance, so an external record cannot shift a pending marked range; stale revisions still reject first. → crates/futo-notes-editor/src/session.rs, crates/futo-notes-editor/tests/composition.rs
- The legacy `InputAction::CompositionCommit` remains available for hosts that own provisional text themselves; an engine-staged session finishes through `commit_composition` instead. Mixing both ownership modes rejects with `CompositionActive` before acceptance so provisional intermediate text cannot become an Undo step. → crates/futo-notes-editor/src/session.rs
- Marked composition is an engine-owned provisional overlay pinned to an opening committed-display range; repeated updates replace its complete text without changing source, revision or history. A changed commit applies one isolated action; cancel discards only the overlay, and empty, identical or repeated commits create no source record or history step. → crates/futo-notes-editor/src/session/composition.rs
- While composing, marked text is drawn in the inline formats it will have once committed, never plain until the commit: each composition update reports them (`Composition.runs`). Typed text takes the carried formats at the caret (a collapsed Bold, Italic, Strikethrough or Code toggle, or the span the caret sits inside, so typing inside **bold** draws bold and a word composed after toggling Bold off draws plain), including in a heading; on a reconverted word, characters the commit keeps retain their own formats and the changed ones take the formats of the first character they replace. → crates/futo-notes-editor/src/session/composition/marked.rs, crates/futo-notes-editor/tests/composition.rs
  > **Gap:** under the rebuilt core (`engine` feature) a composition reports no runs yet, so marked text draws plain until it commits (`session/next.rs` and `compose` fill `runs` with nothing).
- Ordinary input and compound replacements arriving during composition address the provisional display and commit the marked text plus the replacement through one acceptance; the composition and following input retain separate exact history groups, and further adjacent typing can join the following input group; invalid ranges, malformed foreign text, stale revisions and failed acceptance retain the pending composition and accepted source. Overlay coordinates use a persistent display Rope and materialize only the affected envelope. → crates/futo-notes-editor/src/session/composition.rs
- Formatting during composition commits the pending text before toggling the carried format at the committed caret; Undo/Redo remain inert while marked text is pending, and selection notifications cannot move its pinned edit. An unchanged reconversion still ends at the marked text's end before the next command. → crates/futo-notes-editor/tests/composition.rs
- Text-service replacement derives separate changed character runs from the supplied display range, preserving exact source spelling between corrected words, including hidden delimiters; its caret ends after the supplied replacement, and Undo/Redo restore exact bytes and selection as one action. → crates/futo-notes-editor/src/session/os_replacement.rs
- Dictation placeholders are explicitly tagged ranges within the inserted text containing only U+FFFC; the engine excludes those ranges before committing. Untagged U+FFFC remains literal user content, including existing exact source, and malformed placeholder ranges reject before acceptance. → crates/futo-notes-editor/src/session/os_replacement.rs
- A multi-run replacement supplies nonoverlapping ranges in ascending opening-display coordinates; one action preserves exact unchanged runs, validates every foreign range/string before acceptance and creates one accepted edit and history step. Its final caret and carried formats follow the final replacement. Compound planning materializes its affected paragraph envelope, never an unrelated note prefix or suffix. → crates/futo-notes-editor/src/session/transaction.rs
- A typed character always lands, as typed, at the position the caret maps to, whatever block it is typed in, and is never refused, escaped or encoded: no `\` and no HTML entity is written because of what is typed, so a line reads as its typed text reads (`- ` makes a bullet, a lone `#` is saved as `#`). The property run types random text, block markers and inline delimiters one character at a time and checks the note changes by exactly the typed bytes; `TYPING_CASES` and `TYPING_SEED` widen it. → crates/futo-notes-editor/src/engine/tests/properties/, docs/spec/editor/portable-core/linedown.md
- A selection that crosses a code block's boundary, into or out of it, is replaced like any selection across lines by every input (typing, paste, Enter, Backspace, Delete, composition, a text service's runs): the text after it joins the line it starts on and the input lands as given. A fence's opening or closing line inside the selection whose block goes on outside it stays, moved to just after the joined line, so the code left outside the selection stays code and no line after it turns into code; a block with no code line left goes whole (Backspace at a block's first code line joins that line to the line above). One Undo restores the exact source and selection. → crates/futo-notes-editor/src/engine/commands/fences/cut.rs `kept_frame`, crates/futo-notes-editor/tests/fixtures/engine/fences.json
- A typed inline delimiter is written as typed. It formats when it pairs on its own line by the dialect's rules and otherwise shows as literal text; nothing is escaped to stop it pairing or to keep other text formatted. → crates/futo-notes-editor/src/lines/inline/

- Paragraph Enter and Shift+Enter use the supplied platform display range, insert exactly one line break spelled like the caret line's ending (CRLF on a CRLF line, else LF, as pasted line breaks are), and each form an isolated Undo action. Every Enter and Shift+Enter path follows this spelling, including list splits and exits, quotes, headings and code, and so do the lines the divider and code-block commands (and the typed divider shortcut) write; a changed stretch that already mixed in a bare LF keeps LF. Start/middle/end, repeated and empty-line input retain exact untouched CRLF and final-newline bytes through checkpoint. Headings, quotes and fenced code use their structural Enter rules; list and table keys remain in their dependent command slices. → crates/futo-notes-editor/src/session/paragraphs.rs, crates/futo-notes-store/src/tests/editor_session/list_actions.rs, crates/futo-notes-editor/src/session/blocks/line_endings.rs `crlf_enter`, crates/futo-notes-editor/tests/paragraphs.rs `enter_writes_the_caret_lines_crlf_in_every_block_kind`, crates/futo-notes-editor/tests/blocks/line_endings.rs
- Paragraph Backspace/Delete remove the supplied selection or one visible extended grapheme in their direction; CRLF is one line-break deletion. Deleting at the document boundary changes neither revision nor history. Each key Undo restores its exact source, selection and carried formatting. → crates/futo-notes-editor/tests/paragraphs.rs
- Native and WASM paragraph-key consumers forward intent to this same engine without interpreting Markdown or choosing deletion footprints. → crates/futo-notes-editor/src/engine/surface.rs `key`
- History remains in-session only: reopening a saved note starts with no Undo/Redo groups. The store adapts its injected editor clock into the engine grouping clock. → crates/futo-notes-store/src/editor_session/clock.rs, crates/futo-notes-store/src/tests/editor_session.rs
- Selection affinity explicitly chooses the preceding or following visible neighbor at hidden boundaries; native UTF-16 ranges address display text independently of exact source. Caret movement crosses visible graphemes without exposing markers. → crates/futo-notes-editor/src/session.rs, crates/futo-notes-editor/src/coordinates.rs
- No edit writes an HTML entity into a note, and none encodes a neighbouring character to keep formatting: a delimiter an edit leaves unpaired shows as literal text. The one `\` a command writes is the one that keeps a line the block the command intends (block-commands.md). → crates/futo-notes-editor/src/engine/command.rs `kept_line`
- Inline code opens and closes on one line. Editing inside it writes what is typed, with no backtick-length or padding repair, and its contents are not read for other marks. → crates/futo-notes-editor/src/lines/inline/
- Each source change carries a revision-tagged semantic replacement for its reparsed paragraph window, even if formatting changes leave display text identical; explicit projection queries return semantics and correspondence for a requested display range. → crates/futo-notes-editor/src/types.rs
- Inline source edits, formatting and history use the same store acceptance/checkpoint workflow as plain input; edits carry source ranges rather than rendered offsets. → crates/futo-notes-store/src/editor_session/input.rs, crates/futo-notes-store/src/tests/editor_session.rs

Inline formatting toggles, carried formats and typing under them: [inline-formatting.md](inline-formatting.md). Heading, quote and divider block commands: [block-commands.md](block-commands.md).
