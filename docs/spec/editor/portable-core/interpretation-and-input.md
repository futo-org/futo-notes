# Exact source, interpretation and input

- A session opens exact UTF-8 source, including CRLF, trailing whitespace and final-newline spelling; opening and dropping an unchanged store session writes nothing. → crates/futo-notes-editor, crates/futo-notes-store/src/editor_session
- Blocks and list items an action does not edit keep their exact bytes and line endings; edited ones may be respelled canonically if they reparse to the intended display and shapes (lists.md), else the action refuses with `UnrepresentableFormat`. Undo restores exact in-memory bytes; authored note writes may append the final line ending required by the save contract (recovery.md). → crates/futo-notes-editor/src/session/blocks/list_edit/mod.rs
- Insertion, deletion and replacement use distinct source/display UTF-8 byte coordinates; revision-checked conversions expose distinct source/display UTF-16 code-unit ranges for native hosts. Hidden markers and decoded entities have explicit source/display correspondence; one-to-one stretches arrive as literal runs, never per-byte records. → crates/futo-notes-editor/src/coordinates.rs, crates/futo-notes-editor/tests/inline/correspondence.rs
- Reversed or out-of-range edits, UTF-8 character splits, UTF-16 surrogate splits, unpaired surrogate input and stale revisions reject explicitly before acceptance, leaving text, selection and history unchanged; input preserves exact line endings and Unicode spelling. → crates/futo-notes-editor/src/coordinates.rs, crates/futo-notes-editor/tests/unicode.rs
- Identical selection/affinity echoes retain carried formatting and the typing group; an actual selection or affinity change breaks the run even if the caret later returns. Selection-only updates carry the current source revision and create no source delta or history step; Undo/Redo restore the exact selection, affinity and carried formats before/after their original edit. → crates/futo-notes-editor/src/session.rs
- Caret movement and selection collapse stop at extended grapheme boundaries, including combining sequences, joined emoji, flags and CRLF; valid foreign replacement ranges may address code-point boundaries within a grapheme. → crates/futo-notes-editor/src/movement.rs
- Input acceptance holds an exclusive session borrow that prevents synchronous callback re-entry; repeated native notifications using the original revision reject before host acceptance. → crates/futo-notes-editor/src/session.rs, crates/futo-notes-editor/tests/unicode.rs
- Each successful operation returns one ordered display replacement, its resulting selection and the accepted revision; views apply these changes without parsing source. The portable callback is a host acceptance seam, not a save acknowledgement. → crates/futo-notes-editor/src/types.rs, crates/futo-notes-editor/tests/common/mod.rs
- Consecutive adjacent single-grapheme typing, backward deletions or forward deletions of the same kind join a history group while the injected monotonic clock advances less than 500 ms between accepted inputs; exactly 500 ms, a backward clock movement, a changed selection/affinity, a direction change, a newline or an isolated action starts a new group. Rejected input does not change the group. → crates/futo-notes-editor/src/history.rs, crates/futo-notes-editor/tests/history.rs
- Undo and Redo restore exact source bytes plus opening/resulting selection, affinity and carried formats for the entire group, including local marker repairs; each group travels through one acceptance before one display change. Failed acceptance preserves the whole group and current draft, and a new accepted edit discards the redo branch. → crates/futo-notes-editor/src/session.rs, crates/futo-notes-editor/tests/history.rs
- Replaying a source record while composition is active rejects with `CompositionActive` before host acceptance, so an external record cannot shift a pending marked range; stale revisions still reject first. → crates/futo-notes-editor/src/session.rs, crates/futo-notes-editor/tests/composition.rs
- The legacy `InputAction::CompositionCommit` remains available for hosts that own provisional text themselves; an engine-staged session finishes through `commit_composition` instead. Mixing both ownership modes rejects with `CompositionActive` before acceptance so provisional intermediate text cannot become an Undo step. → crates/futo-notes-editor/src/session.rs
- Marked composition is an engine-owned provisional overlay pinned to an opening committed-display range; repeated updates replace its complete text without changing source, revision or history. A changed commit applies one isolated action; cancel discards only the overlay, and empty, identical or repeated commits create no source record or history step. → crates/futo-notes-editor/src/session/composition.rs
- Ordinary input and compound replacements arriving during composition address the provisional display and commit the marked text plus the replacement through one acceptance; the composition and following input retain separate exact history groups, and further adjacent typing can join the following input group; invalid ranges, malformed foreign text, stale revisions and failed acceptance retain the pending composition and accepted source. Overlay coordinates use a persistent display Rope and materialize only the affected envelope. → crates/futo-notes-editor/src/session/composition.rs
- Formatting during composition commits the pending text before toggling the carried format at the committed caret; Undo/Redo remain inert while marked text is pending, and selection notifications cannot move its pinned edit. An unchanged reconversion still ends at the marked text's end before the next command. → crates/futo-notes-editor/tests/composition.rs
- Text-service replacement derives separate changed character runs from the supplied display range, preserving exact source spelling between corrected words, including hidden delimiters and entities; its caret ends after the supplied replacement, and Undo/Redo restore exact bytes and selection as one action. → crates/futo-notes-editor/src/session/os_replacement.rs
- Dictation placeholders are explicitly tagged ranges within the inserted text containing only U+FFFC; the engine excludes those ranges before committing. Untagged U+FFFC remains literal user content, including existing exact source, and malformed placeholder ranges reject before acceptance. → crates/futo-notes-editor/src/session/os_replacement.rs
- A multi-run replacement supplies nonoverlapping ranges in ascending opening-display coordinates; one action preserves exact unchanged runs, validates every foreign range/string before acceptance and creates one accepted edit and history step. Its final caret and carried formats follow the final replacement. Compound planning materializes its affected paragraph envelope, never an unrelated note prefix or suffix. → crates/futo-notes-editor/src/session/transaction.rs
- Typing produces what the Markdown parser reads, and a typed character is never refused for its block context: a line-start shortcut whose block cannot be written leaves its marker as literal text and the character lands, so a shell that forwards each keystroke never drops one. A bounded property run types block markers and letters one character at a time, and as one committed string, into every block context and checks no input refuses and every typed letter is displayed. → crates/futo-notes-editor/src/session/input.rs, crates/futo-notes-editor/src/session/blocks/list_edit/fuzz_tests.rs `typed_characters_are_never_refused_and_always_land`

> **Gap:** Inline delimiters typed mid-text (`*`, `_`, backticks) can still refuse with `UnrepresentableFormat` when no local flanking repair reproduces the display, for example a space typed after `_]_` before a word, or `.*x` typed at the start of the second line of a two-line `**bold**` span. The property run excludes them; the Android shell drops such a keystroke.

- Paragraph Enter and Shift+Enter use the supplied platform display range, insert exactly one LF, and each form an isolated Undo action. Start/middle/end, repeated and empty-line input retain exact untouched CRLF and final-newline bytes through checkpoint. Headings, quotes and fenced code use their structural Enter rules; list and table keys remain in their dependent command slices. → crates/futo-notes-editor/src/session/paragraphs.rs, crates/futo-notes-store/src/tests/editor_session/list_actions.rs
- Paragraph Backspace/Delete remove the supplied selection or one visible extended grapheme in their direction; CRLF is one line-break deletion. Deleting at the document boundary changes neither revision nor history. Each key Undo restores its exact source, selection and carried formatting. → crates/futo-notes-editor/tests/paragraphs.rs
- *(Android text-first editor)* Backspace at a heading's visible start removes the preceding blank physical line and retains the heading, or joins its text into the preceding nonblank line using ordinary paragraph deletion. A first-line heading still becomes Text; a join the paragraph engine cannot represent (including immediately after a fenced code block) refuses without changing source or history. The successful action has one exact Undo step. → crates/futo-notes-editor/src/session/blocks/keys.rs `heading_join_backspace`, crates/futo-notes-editor/tests/blocks/heading_join.rs
- Formatting survives selection deletion and a single inserted line break; a blank line closes and reopens the inline span locally, retaining carried formatting for the next typed character. Native and WASM paragraph-key consumers forward intent to this same engine without interpreting Markdown or choosing deletion footprints. → crates/futo-notes-editor/src/inline/spelling.rs
- History remains in-session only: reopening a saved note starts with no Undo/Redo groups. The store adapts its injected editor clock into the engine grouping clock. → crates/futo-notes-store/src/editor_session/clock.rs, crates/futo-notes-store/src/tests/editor_session.rs
- Bold, italic, strikethrough and inline code return display text without their markers, semantic runs and source/display correspondence; nested/adjacent runs retain original delimiter spelling outside the necessary edit footprint. Multiline emphasis follows CommonMark, and code contents isolate inline syntax. → crates/futo-notes-editor/src/inline/row.rs, crates/futo-notes-editor/tests/inline.rs
- Selection affinity explicitly chooses the preceding or following visible neighbor at hidden boundaries; native UTF-16 ranges address display text independently of exact source. Caret movement crosses visible graphemes without exposing markers. → crates/futo-notes-editor/src/session.rs, crates/futo-notes-editor/src/coordinates.rs
- Replacing a selection preserves the surviving marks on either side and carries the selection's initial formatting; deleting all marked content removes empty markers while retaining the format for subsequent input. Whitespace at emphasis edges remains visible outside markers until following input can join the span. → crates/futo-notes-editor/src/inline/edit.rs
- Backspace from a collapsed caret keeps the caret's carried formatting, so deleting a space typed after italic text (a keyboard's double-space period) and typing on continues the italic span. → crates/futo-notes-editor/src/session/input.rs, crates/futo-notes-editor/tests/inline.rs
- Formatting toggles preserve visible text and selection and form one exact-source history action; a collapsed toggle changes carried formatting without writing empty markdown. Candidate verification rejects unsafe formatting before acceptance. → crates/futo-notes-editor/src/session.rs
- A selected toggle touching more than one block formats each block's visible inline body on its own — paragraph, heading text, list or task item body, quote body and each table cell's contents — and skips code, front matter, raw HTML, dividers, blank lines and table delimiter rows; no span crosses a block or cell boundary, so the block structure is unchanged. → crates/futo-notes-editor/src/session/formatting/bodies.rs, crates/futo-notes-editor/tests/inline/multi_block.rs
- A multi-block toggle takes one direction for the whole selection: when every body (edge whitespace and blank lines aside) already carries the format it is removed everywhere, otherwise it is added to every body lacking it. → crates/futo-notes-editor/src/session/formatting.rs `toggle_bodies`
- A multi-block toggle is one host acceptance and one Undo step restoring exact source and selection; the selection is unchanged. A body the format cannot be spelled in is skipped, and the toggle refuses with `UnrepresentableFormat` only when no body can take it. Its work is linear in the selected note. → crates/futo-notes-editor/src/session/formatting.rs, crates/futo-notes-editor/src/session/formatting/fuzz_tests.rs
- When an edit changes CommonMark delimiter flanking, a necessary local boundary repair may encode the immediate adjacent scalar as a numeric entity; the visible scalar, surrounding formats and exact Undo remain intact. Decoded multi-scalar entities support valid code-point replacement ranges without losing the unselected scalar. → crates/futo-notes-editor/src/inline/edit.rs, crates/futo-notes-editor/tests/inline.rs
- Inline-code editing repairs backtick length and padding locally, preserves visible spaces, and splits code around newly inserted literal line breaks; existing code-span line endings project as CommonMark spaces while their exact source bytes remain intact. → crates/futo-notes-editor/src/inline/row.rs, crates/futo-notes-editor/src/inline/edit.rs
- Each source change carries a revision-tagged semantic replacement for its reparsed paragraph window, even if formatting changes leave display text identical; explicit projection queries return semantics and correspondence for a requested display range. → crates/futo-notes-editor/src/types.rs
- Inline source edits, formatting and history use the same store acceptance/checkpoint workflow as plain input; edits carry source ranges rather than rendered offsets. → crates/futo-notes-store/src/editor_session/input.rs, crates/futo-notes-store/src/tests/editor_session.rs
