# Exact source, interpretation and input

- A session opens exact UTF-8 source, including CRLF, trailing whitespace and final-newline spelling; opening and dropping an unchanged store session writes nothing. → crates/futo-notes-editor, crates/futo-notes-store/src/editor_session
- Lines an action does not edit keep their exact bytes and line endings: a command edits only the lines it acts on (renumbering a numbered list is the one exception), and is cancelled with no edit and no history when it would change the block of any other line (a fence, front matter or table opened or closed). Nothing is respelled to fit a reader. Undo restores exact bytes, and a save writes them exactly (recovery.md). → crates/futo-notes-editor/src/engine/command.rs `Engine::run`
- Insertion, deletion and replacement use distinct source/display UTF-8 byte coordinates; revision-checked conversions expose distinct source/display UTF-16 code-unit ranges for native hosts. Hidden markers have explicit source/display correspondence; an HTML entity is literal text and shows as typed; one-to-one stretches arrive as literal runs, never per-byte records. → crates/futo-notes-editor/src/coordinates.rs, crates/futo-notes-editor/src/engine/tests/projection.rs
- Reversed or out-of-range edits, UTF-8 character splits, UTF-16 surrogate splits, unpaired surrogate input and stale revisions reject explicitly before acceptance, leaving text, selection and history unchanged; input preserves exact line endings and Unicode spelling. → crates/futo-notes-editor/src/coordinates.rs, crates/futo-notes-editor/tests/unicode.rs
- Identical selection/affinity echoes retain carried formatting and the typing group; an actual selection or affinity change breaks the run even if the caret later returns. Selection-only updates carry the current source revision and create no source delta or history step; Undo/Redo restore the exact selection, affinity and carried formats before/after their original edit. → crates/futo-notes-editor/src/session.rs
- Caret movement and selection collapse stop at extended grapheme boundaries, including combining sequences, joined emoji, flags and CRLF; valid foreign replacement ranges may address code-point boundaries within a grapheme. A caret supplied between a CRLF's CR and LF acts at the end of its line (before the CR) for selection, typing, composition, paste and every key, and a selection endpoint there widens over the whole break, so no input there refuses or leaves a bare CR. A selection collapsed to an edge a native control left inside a grapheme stops at that grapheme's boundary in the direction of the move. A step onto a table's delimiter row goes past it ([tables.md](tables.md)). → crates/futo-notes-editor/src/engine/selection.rs `move_caret` `grapheme_edge` `outside_crlf`, crates/futo-notes-editor/src/engine/tests/input.rs
- Words come from ICU4X's word segmenter with its full dictionaries, so Chinese, Japanese and Thai split as macOS splits them (`我们在北京` is `我们`, `在`, `北京`), over the display text of one display line: a word never crosses a line break, and hidden syntax, an indent and hidden fence lines are not in it. `word_at` (what a double click selects) is the segment at the offset (a run of spaces or punctuation is one), or the word just before it when only that is a word (past a word's or the line's end); nothing on an empty line. `word_stop` (where Option+Arrow stops and Option+Backspace deletes to) is the end of the next word forward or the start of the previous one backward, going on across line breaks and blank lines, else the display's end or start. A table's delimiter row holds no word and is never a stop ([tables.md](tables.md)). Both are reads: no revision, selection or history changes. A native view's own word delete is mapped by its own rule, not these (`host/display_mirror.rs` `word_stop`). → crates/futo-notes-editor/src/engine/words.rs, crates/futo-notes-editor/tests/words.rs
- Typed text holding a control character other than tab and line feed, or one of Apple's function-key code points U+F700–U+F7FF, is `InvalidText` and changes nothing: Ctrl+Option+letter and AppKit's quoted keys (Ctrl+Q, then a key) type them, and a line break is typed as Enter. Paste, text-service replacements and compositions are not typing, so a replacement may carry the note's own CRLF. → crates/futo-notes-editor/src/engine/surface.rs `typeable`, crates/futo-notes-editor/tests/unicode.rs
- Transpose (Ctrl+T on Apple) swaps the graphemes on either side of a caret, or the two before it at a line's end, and leaves the caret after them; a selection, a line's start or a lone character on a line is no edit. One accepted edit and one Undo action, which puts the caret back where it was. → crates/futo-notes-editor/src/engine/commands/transpose.rs, crates/futo-notes-editor/tests/transpose.rs
- Input acceptance holds an exclusive session borrow that prevents synchronous callback re-entry; repeated native notifications using the original revision reject before host acceptance. → crates/futo-notes-editor/src/session.rs, crates/futo-notes-editor/tests/unicode.rs
- Each successful operation returns one ordered display replacement, its resulting selection and the accepted revision; views apply these changes without parsing source. The portable callback is a host acceptance seam, not a save acknowledgement. → crates/futo-notes-editor/src/types.rs, crates/futo-notes-editor/tests/common/mod.rs
- Consecutive adjacent single-grapheme typing, backward deletions or forward deletions of the same kind join a history group while the injected monotonic clock advances less than 500 ms between accepted inputs; exactly 500 ms, a backward clock movement, a changed selection/affinity, a direction change, a newline or an isolated action starts a new group. Rejected input does not change the group. → crates/futo-notes-editor/src/history.rs, crates/futo-notes-editor/tests/history.rs
- Undo and Redo restore exact source bytes plus opening/resulting selection, affinity and carried formats for the entire group, including local marker repairs; each group travels through one acceptance before one display change. Failed acceptance preserves the whole group and current draft, and a new accepted edit discards the redo branch. → crates/futo-notes-editor/src/session.rs, crates/futo-notes-editor/tests/history.rs
- Marked composition, text-service replacements and dictation: [composition-and-replacements.md](composition-and-replacements.md).
- A typed character always lands, as typed, at the position the caret maps to, whatever block it is typed in, and is never refused, escaped or encoded: no `\` and no HTML entity is written because of what is typed, so a line reads as its typed text reads (`- ` makes a bullet, a lone `#` is saved as `#`). The property run types random text, block markers and inline delimiters one character at a time and checks the note changes by exactly the typed bytes, besides what three lines that show no text need (an empty code block's line ending and its opening fence's indent, a divider's own line below, an empty `>` line's space, [block-commands.md](block-commands.md)), and the blank first body row the keystroke that finishes a table's delimiter row writes ([tables.md](tables.md)); `TYPING_CASES` and `TYPING_SEED` widen it. → crates/futo-notes-editor/src/engine/tests/properties/, docs/spec/editor/portable-core/linedown.md
- Under the opt-in `PairedTyping` action a typed backtick, `*`, `~`, `[` or `]` may write or grow a pair, move the caret, format a selection, or make or close a code block instead ([paired-typing.md](paired-typing.md)); every other action types as above. → crates/futo-notes-editor/src/engine/commands/paired_typing/mod.rs
- A divider line shows only its rule, so typing at the rule's edge writes the text on a line of its own beside it (before it at its start, after it at its end), inside the divider's quotes, with the line's own line ending; text that brings its own line break there lands as typed. → crates/futo-notes-editor/src/engine/edit/plan.rs `beside_divider`, crates/futo-notes-editor/src/engine/line.rs
- A selection that crosses a code block's boundary, into or out of it, takes every block it reaches into or out of whole, fences included, for every input (typing, paste, Enter, Backspace, Delete, Cut, composition, a text service's runs) and for Copy: the text after it joins the line it starts on and the input lands as given. A range from a block's code to the start of the line after the block holds the line break that stands for the hidden closing fence, so it takes the block whole; past a block that ends the note, where no line follows, a range from its code to the note's end stays in the code. A range that only meets a block's outer edge does not take it: one that is exactly all the code (to the code's end, without the break after it) is an ordinary selection; one from the end of a block's code starts after its line break; one ending where a block's code starts stops before the line break above the block when it writes text (a paste, Enter, Shift+Enter and the divider, which rewrite the lines it leaves, included) or starts mid-line, so nothing joins the opening fence, and takes that line break when it removes whole lines. A block that shows no code (one empty line) has no inside: a range from it takes it. One Undo restores the exact source and selection. → crates/futo-notes-editor/src/engine/commands/fences/reach.rs `block_reach`, `kept_break`, crates/futo-notes-editor/src/engine/edit/plan.rs `plan_cleared`, crates/futo-notes-editor/tests/fixtures/engine/fences.json, crates/futo-notes-editor/tests/fixtures/engine/hidden-line-edges.json
- A typed inline delimiter is written as typed. It formats when it pairs on its own line by the dialect's rules and otherwise shows as literal text; nothing is escaped to stop it pairing or to keep other text formatted. → crates/futo-notes-editor/src/lines/inline/

- Paragraph Enter and Shift+Enter use the supplied platform display range, insert exactly one line break spelled like the caret line's ending (CRLF on a CRLF line, else LF, as pasted line breaks are), and each form an isolated Undo action. Every Enter and Shift+Enter path follows this spelling, including list splits and exits, quotes, headings and code, and so do the lines the divider and code-block commands (and the typed divider shortcut) write; a changed stretch that already mixed in a bare LF keeps LF. Start/middle/end, repeated and empty-line input retain exact untouched CRLF and final-newline bytes through checkpoint. Headings, quotes and fenced code use their structural Enter rules; list and table keys remain in their dependent command slices. → crates/futo-notes-editor/src/engine/commands/blocks/keys.rs `plain_enter`, crates/futo-notes-editor/tests/fixtures/engine/clipboard/plain-enter.json, crates/futo-notes-editor/tests/fixtures/engine/blocks.json
- Paragraph Backspace/Delete remove the supplied selection or one visible extended grapheme in their direction; CRLF is one line-break deletion; an image or a wikilink the step reaches into goes whole ([images.md](images.md), [wikilinks.md](wikilinks.md)). Deleting at the document boundary changes neither revision nor history, except Backspace on a blank first line above a code block ([fenced-code.md](fenced-code.md)). Each key Undo restores its exact source, selection and carried formatting. → crates/futo-notes-editor/src/engine/tests/mod.rs `backspace_and_delete_take_one_grapheme`
- Backspace at a collapsed caret after a grapheme that ends in a zero-width non-joiner (U+200C, which Persian writers type inside words) removes only the non-joiner: the letter before it stays and the caret stays after that letter. Delete, caret movement and every other cluster are unchanged, and one Undo restores the non-joiner and the caret. A native view's queued Backspace mapped by `DisplayMirror::at_caret` follows the same rule. → crates/futo-notes-editor/src/backspace_length.rs, crates/futo-notes-editor/tests/unicode.rs, crates/futo-notes-editor/tests/host_mirror.rs `a_backspace_after_a_zero_width_non_joiner_is_only_the_non_joiner`
- Native and WASM paragraph-key consumers forward intent to this same engine without interpreting Markdown or choosing deletion footprints. → crates/futo-notes-editor/src/engine/surface.rs `key`
- History remains in-session only: reopening a saved note starts with no Undo/Redo groups. The store adapts its injected editor clock into the engine grouping clock. → crates/futo-notes-store/src/editor_session/clock.rs, crates/futo-notes-store/src/tests/editor_session.rs
- Selection affinity explicitly chooses the preceding or following visible neighbor at hidden boundaries; native UTF-16 ranges address display text independently of exact source. Caret movement crosses visible graphemes without exposing markers. Input at a collapsed caret the host placed somewhere other than the session's selection stands where a fresh selection there would: after hidden syntax at the note's start, otherwise before it, so text typed where a span ends lands inside it. → crates/futo-notes-editor/src/engine/selection.rs, crates/futo-notes-editor/src/engine/edit/plan.rs, crates/futo-notes-editor/src/coordinates.rs
- No edit writes an HTML entity into a note, and none encodes a neighbouring character to keep formatting: a delimiter an edit leaves unpaired shows as literal text. The one `\` a command writes is the one that keeps a line the block the command intends (block-commands.md). → crates/futo-notes-editor/src/engine/command.rs `kept_line`
- Inline code opens and closes on one line. Editing inside it writes what is typed, with no backtick-length or padding repair, and its contents are not read for other marks. → crates/futo-notes-editor/src/lines/inline/
- Each source change carries a revision-tagged semantic replacement for its reparsed paragraph window, even if formatting changes leave display text identical; explicit projection queries return semantics and correspondence for a requested display range. → crates/futo-notes-editor/src/types.rs
- Inline source edits, formatting and history use the same store acceptance/checkpoint workflow as plain input; edits carry source ranges rather than rendered offsets. → crates/futo-notes-store/src/editor_session/input.rs, crates/futo-notes-store/src/tests/editor_session.rs

Inline formatting toggles, carried formats and typing under them: [inline-formatting.md](inline-formatting.md). Heading, quote and divider block commands: [block-commands.md](block-commands.md).
