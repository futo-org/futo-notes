# Find in note

These are the portable replacement core's contracts. The shipping Milkdown find
bar keeps [its contract](../find-in-note.md) until renderer integration and cutover;
platform bars stay thin and render the engine's report verbatim.

- Matching is case-insensitive literal search over the display text, so hidden markers (list, quote and heading markers, inline syntax, an escape's backslash) and link destinations are not findable, while text spanning a hidden mark (`**bo**ld`) matches. Every Greek sigma is one letter; a character whose lowercase is longer matches only itself. Occurrences never overlap. → crates/futo-notes-editor/src/engine/commands/find.rs, crates/futo-notes-editor/tests/fixtures/engine/find.json
- Every line break is a barrier: no match crosses from one line to the next, whatever the lines are (two plain lines, two quote lines, a bullet and the indented line under it, code lines). A query holding a line break finds nothing. → crates/futo-notes-editor/src/engine/commands/find.rs, crates/futo-notes-editor/tests/fixtures/engine/find.json
- In a table only cell contents are findable: pipes, cell padding and the delimiter row are barriers, cells past the header are findable, and an escaped pipe is cell text. A pipe line with no delimiter row under it is a plain line and is found whole. Front matter and dividers are never found. The scan request carries these as `barriers`, and `soft_breaks` is always empty. → crates/futo-notes-editor/src/engine/commands/find.rs
- Every match is selectable, and its tight source range shows exactly the match: it starts after any marker or opening syntax before it and ends before any closing syntax after it. → crates/futo-notes-editor/src/engine/tests/find.rs
- Opening or changing the query scans once, as an explicit find action, and makes the first match at or after the selection start current, wrapping to the first. Stepping moves to the next or previous match with wrap, selects it and returns a reveal request; during composition it is a no-op, as selection changes are. Zero matches and a closed find make stepping a no-op; closing clears matches, keeps the query for the next open and leaves the selection. The report carries one-based current, total, the current display range and its tight source range. State lives on the note's engine only. → crates/futo-notes-editor/src/engine/commands/find.rs
- Find never edits source, accepts an edit or adds an Undo step; stepping changes only the selection. → crates/futo-notes-editor/src/engine/tests/find.rs
- Each accepted change only logs its display window (O(1), from `Engine::accept`); matches are carried through that log on the next find read, matches inside a replaced window are dropped (counted in `dropped`), and the report is `stale` until a rescan lands. A host takes a scan snapshot after input settles, scans it on any thread and applies the result; a result for another engine, revision or query generation (including after close) is refused with no state change, as are host matches that are out of order, overlapping, empty, out of range or inside a character. Past 64 unread edits the matches are dropped until a rescan lands, while the current match and the step position are still carried. A change that reached the note without being logged drops the matches instead of carrying them. → crates/futo-notes-editor/src/engine/commands/find.rs, crates/futo-notes-editor/tests/host_find_plan.rs
- At 20,000 lines typing with find open costs no scan (`FindWork.scans` unchanged) and the matches follow the text; a scan request reads the display once and only the table lines for barriers (`FindWork.barrier_bytes`). → crates/futo-notes-editor/src/engine/tests/find.rs
- The same operations are exposed unchanged through the portable session, WASM, Store and native FFI (`find_set_query`, `find_step`, `find_close`, `find_report`, `find_matches`, `find_scan_request`, `find_apply_scan`, pure `find_scan`); portable session and WASM also have `*_utf16` variants of range-taking calls (`find_matches`, the table calls); native FFI has no such twins, so hosts convert UTF-16 ranges with `utf16_to_display` first. Portable input awaiting host acknowledgement rejects find queries as busy; closing always succeeds. → crates/futo-notes-editor/tests/find/wasm-find-consumer.mjs, crates/futo-notes-ffi/tests/editor_find.rs
