# Composition and text-service replacements

What the engine does with an input method's marked text, a text service's replacement and dictation; the rest of input is in [interpretation-and-input.md](interpretation-and-input.md).

- Replaying a source record while composition is active rejects with `CompositionActive` before host acceptance, so an external record cannot shift a pending marked range; stale revisions still reject first. → crates/futo-notes-editor/src/session.rs, crates/futo-notes-editor/tests/composition.rs
- The legacy `InputAction::CompositionCommit` remains available for hosts that own provisional text themselves; an engine-staged session finishes through `commit_composition` instead. Mixing both ownership modes rejects with `CompositionActive` before acceptance so provisional intermediate text cannot become an Undo step. → crates/futo-notes-editor/src/session.rs
- Marked composition is an engine-owned provisional overlay pinned to an opening committed-display range; repeated updates replace its complete text without changing source, revision or history. A changed commit applies one isolated action; cancel discards only the overlay, and empty, identical or repeated commits create no source record or history step. → crates/futo-notes-editor/src/engine/edit/compose.rs
- Committing marked text replaces only the stretch that differs from what the marked range showed, so the characters it keeps keep their source spelling and formats (`half**way**` reconverted to `hallway` saves `hall**way**`) and the caret ends after the whole text; an unchanged commit writes nothing and still leaves the caret at the marked text's end. Marked text over a caret other than the selection commits as typing at that caret does (at the end of bold it joins the bold). → crates/futo-notes-editor/src/engine/edit/plan.rs `plan_input`, crates/futo-notes-editor/src/engine/edit/compose.rs, crates/futo-notes-editor/src/engine/tests/commits.rs
- While composing, marked text is drawn in the inline formats it will have once committed, never plain until the commit: each composition update reports them (`Composition.runs`). Typed text takes the carried formats at the caret (a collapsed Bold, Italic, Strikethrough or Code toggle, or the span the caret sits inside, so typing inside **bold** draws bold and a word composed after toggling Bold off draws plain), including in a heading; on a reconverted word, characters the commit keeps retain their own formats and the changed ones take the formats of the first character they replace. → crates/futo-notes-editor/src/engine/edit/compose.rs `marked_runs`
- Ordinary input and compound replacements arriving during composition address the provisional display and commit the marked text plus the replacement through one acceptance; the input lands on the characters it addressed there even when the commit hides or shows marks before, inside or after the marked text (`x *b ` composing `b https://x.test/a* ` and replacing the first `b` writes `x *B b https://x.test/a* `), and lands as it would with nothing marked, so a text service's replacement keeps the hidden markers in the stretch it leaves unchanged; the composition and following input retain separate exact history groups, and further adjacent typing can join the following input group; invalid ranges, malformed foreign text, stale revisions and failed acceptance retain the pending composition and accepted source. Overlay coordinates use a persistent display Rope and materialize only the affected envelope. → crates/futo-notes-editor/src/engine/edit/compose.rs `committed_at`, crates/futo-notes-editor/src/engine/tests/commits.rs, crates/futo-notes-editor/src/engine/tests/input.rs
- Formatting during composition commits the pending text before toggling the carried format at the committed caret; Undo/Redo remain inert while marked text is pending, and selection notifications cannot move its pinned edit. An unchanged reconversion still ends at the marked text's end before the next command. → crates/futo-notes-editor/src/engine/command/run.rs `Engine::run`, crates/futo-notes-editor/tests/composition.rs
- Text-service replacement derives separate changed character runs from the supplied display range, preserving exact source spelling between corrected words, including hidden delimiters; runs whose edits meet in the source (a run across a code block's boundary moves its fence line past the next) are replaced as one run, and a last run whose edit reaches past the replacement's kept end replaces through that end, so the source before them stays as it was; its caret ends after the supplied replacement, and Undo/Redo restore exact bytes and selection as one action. → crates/futo-notes-editor/src/engine/edit/plan.rs `plan_runs`, crates/futo-notes-editor/tests/fixtures/engine/fences.json
- Dictation placeholders are explicitly tagged ranges within the inserted text containing only U+FFFC; the engine excludes those ranges before committing. Untagged U+FFFC remains literal user content, including existing exact source, and malformed placeholder ranges reject before acceptance. → crates/futo-notes-editor/src/session.rs `clean_placeholders`
- A multi-run replacement supplies nonoverlapping ranges in ascending opening-display coordinates; one action preserves exact unchanged runs, validates every foreign range/string before acceptance and creates one accepted edit and history step. Its final caret and carried formats follow the final replacement. Each run replaces only what differs from what it covers, as a text service's run does, against the text before the action; planning reads only the lines the runs touch, never an unrelated note prefix or suffix. While text is marked, the marked text commits first in the same acceptance, and one run then lands as typing does. → crates/futo-notes-editor/src/engine/edit/mod.rs `replace_runs`, crates/futo-notes-editor/src/engine/tests/input.rs
- Input that writes back the text it replaces (a letter typed over itself, a text service's or a multi-run replacement putting back the same words) writes no source record, revision or Undo step, and its caret ends after its text, where a changed replacement of the same length would leave it; nothing typed over an empty range keeps the selection. The portable session and WASM answer it, and any input that only moved the selection, with no edit (`null`) and keep taking input. → crates/futo-notes-editor/src/engine/edit/mod.rs `replace_input` `replace_runs`, crates/futo-notes-editor/src/portable.rs `issue_accepted`, crates/futo-notes-editor/tests/portable/unchanged_input.rs, crates/futo-notes-editor/tests/wasm-consumer.mjs
