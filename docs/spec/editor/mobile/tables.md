# Tables

- *(mobile)* The native text-first editor renders existing root tables as a header/body grid (columns max(110, note width ÷ columns) wide, in points on iOS and dp on Android, borders, the header row filled and semibold, the delimiter line shown as nothing, each column's alignment kept, bold, italic, strikethrough, inline code and links drawn as in a paragraph) with one shared horizontal scroll per table; a horizontal drag that starts on a table wider than the note scrolls all its columns together, and any other drag scrolls the note. The row's Markdown spelling stays in the text, hidden, and the caret never stops inside a row. Tapping a cell raises no keyboard on the note; it opens a cell-sized field in place over the cell (not a sheet or separate screen), on the same editor session, with the note's own keyboard toolbar (no Done button): Undo, Redo, bold, italic, strikethrough and link act on the cell, block and picture items are dimmed, and the hide-keyboard item returns to the note. Typing, deleting, composition, single-cell paste, copy, cut, Enter (the cell below, a new row on the last), Tab and Shift+Tab (hardware keyboard) and Undo in the field are the engine's, in the note's own display coordinates, so a typed `|` lands as typed and starts a new cell, while a pasted `|` is written `\|` and a pasted line break becomes a space; a tap on the note outside the table returns to the note, and a tap on another cell opens that cell. The open cell has a row grip at the table's left edge and a column grip on its top edge, each a native menu: the row grip's Add above, Add below, Delete row and Delete table; the column grip's Add to left, Add to right, Delete column and Delete table; each is one engine command and one Undo step, the engine's availability decides which are enabled (Add above and Delete row are not on the header row), and Delete table leaves the engine's blank lines where the table was, with the caret on one of them. A tap in a box a short row draws but lacks asks the engine for that cell, which gives the row the missing cells in one edit. A link in a cell opens on a tap while no cell of its table is open; a tap on a link while a cell of that table is open opens the tapped cell instead, and a tap on a link in the cell that is already open opens the link. Image content is refused while the selection is in a cell: no file is written. Existing alignment and untouched bytes survive save and reopen. There is no table creation, resizing, reordering, alignment control or multi-cell selection or paste on this surface. → apps/ios/Sources/Editor/TextFirst/TextFirstTables.swift, TextFirstTables+Missing.swift, TextFirstCellEditor.swift, TextFirstCellEditor+Toolbar.swift, TextFirstCellEditor+Links.swift, TextFirstTableGrips.swift, TextFirstEditorController+Taps.swift, TextFirstLayoutFragments.swift, apps/ios/Tests/Editor/TextFirst/TextFirstTableTests.swift, apps/android/app/src/main/java/com/futo/notes/textfirst/EditorEngineTables.kt, TextFirstTableSpans.kt, TableCellEditText.kt, TextFirstTableCellHost.kt, TextFirstTableGeometry.kt, TextFirstTableGrips.kt, TableGridTouch.kt, TextFirstToolbar.kt, EngineStyleSpans.kt, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstTableTest.kt, TextFirstTableSceneTest.kt, TextFirstTableEditingTest.kt
- *(iOS)* A horizontal drag that starts where the system's screen-edge back swipe claims it is that back swipe, and tapping a cell selects that cell's content. → apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+Taps.swift, TextFirstCellEditor.swift, apps/ios/Tests/Editor/TextFirst/TextFirstTableTests.swift
- *(Android)* The header and body rows meet with no gap between them, a row is as tall as its tallest cell's text plus even padding, and never less than 48 dp so each cell stays a touch target, with each cell's letters as seen (capital tops to descender bottoms) centred vertically in it, in the grid and in the open cell's field alike, its find marks on them; the header row's borders show over its fill in light and dark. → apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstTableSpans.kt, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstLineMetricsTest.kt `tableHeaderAndBodyRowsMeet`
- *(Android)* A delimiter row being typed (`writes_delimiter_row`) shows as its typed text, muted, with the caret in it, under the header's grid; the keystroke that finishes it hides it again and opens the first body cell's field, as a tap on that cell does. A Backspace there straight after (FUTO sends it as the DEL key in the empty cell) is the note's Backspace key, which takes the keystroke back: the field closes and the note keeps the keyboard. → apps/android/app/src/main/java/com/futo/notes/textfirst/EngineStyleSpans.kt, EditorEngineUpdates.kt, EngineInputConnection.kt, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstTypedDelimiterRowTest.kt
- *(Android)* The table's columns are the same width on every row of a table, drawn from the engine's table-wide column count, so a typed `|` widens every row at once and its Undo narrows them; the header's fill ends at the last column. The open field takes the note's own background with a 2 dp outline in the link colour (a header cell keeps its fill) and is clipped to the table's visible width when the table is scrolled sideways. The field shows the cell with the spaces typed at its edges, and the keyboard reads that same text and caret, so a trailing space typed mid-sentence stays, capitals and suggestions follow the text, and the field is rewritten only where it differs from the engine; a tap puts the caret at the tap with nothing selected, and a key that arrives in a cell (Enter, Tab) leaves the caret at the end of its text. The soft Enter key is the table's Enter, not Done. A pan that starts at either edge of the note over a table that can pan is the table's: the system's Back gesture is excluded over those rows. → apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstTableSpans.kt, TableCellEditText.kt, EditorEngineTables.kt, TableBackExclusion.kt, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstTableEditingTest.kt
- *(Android)* The grips are native popup menus anchored at the grips; the destructive items are in the danger colour, the keyboard and the cell stay up, and Delete table is the engine's whole-table deletion (all cells selected, then Backspace) and one Undo restores the table and reopens the cell it was deleted from. Both grips go while less than 20 dp of the open cell is in view, the column grip stays inside the view for a table that starts the note and sticks to the top of the visible table once the header has scrolled off, and a toolbar tap while a menu shows only closes the menu. Undo or Redo that brings a table back opens its cell, and a link in a cell opens a wikilink that resolves (an unresolved one does nothing). → apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstTableGrips.kt, TextFirstTableCellHost.kt, TextFirstNoteView.kt, TableGridTouch.kt, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstTableEditingTest.kt
