# Find in note

- *(mobile)* Find on the native text-first editor consumes the shared find core ([portable-core/find.md](../portable-core/find.md)): the note's overflow menu opens a find bar docked above the keyboard (query, count, previous, next, close); every match is painted behind the text and the current one is distinct; stepping selects the match and scrolls it into view (the first press after the query changes lands on the current match, later ones move from it; after an edit drops the current match, with or without a rescan since, Next goes to the first match at or after where it was and Previous to the last match before it (wrapping), so neither steps past a match or moves the wrong way; typing then deleting inside the current match, or undoing that edit, leaves the user on the same match and Next lands on it again; an edit that leaves the current match in place, however many edits there are before the next rescan, changes nothing and the next press advances); editing keeps the bar open and the marks follow the text, rescanned once typing settles. Plain, formatted and Unicode text all match; find never changes the note's bytes, Undo history or saves, and a step during composition is a no-op; marks are hidden while a composition is open. There is no replace, regex or other option. → crates/futo-notes-editor/src/host/find_plan.rs, crates/futo-notes-editor/tests/host_find_plan.rs, apps/ios/Sources/Editor/TextFirst/TextFirstFind.swift, apps/ios/Tests/Editor/TextFirst/TextFirstFindTests.swift, apps/ios/UITests/TextFirstBottomEdgeUITests.swift, apps/android/app/src/main/java/com/futo/notes/textfirst/EditorEngineFind.kt, FindMarks.kt, TextFirstFind.kt, TextFirstEditTextFind.kt, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstFindTest.kt, TextFirstTableSceneTest.kt `closingCellFindDismissesTheQueryKeyboard`
- *(iOS)* A match inside a table cell is painted in that cell and stepping to it scrolls the grid to its column (the cell's field opens only when the cell is tapped); a match in an image's alt text or destination, which the engine counts, is painted over the picture because its spelling is hidden. → TextFirstFind.swift `tableMarks`, `drawFindMarks`
- *(Android)* With the Find query focused, an Enter or Numpad Enter key pair or a soft-keyboard Search action requests exactly one step; Shift+Enter steps backward, and these keys leave the query text unchanged. → apps/android/app/src/main/java/com/futo/notes/ui/NoteEditorFindBar.kt `FindQueryEditText`, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstFindTest.kt `aQueryEnterRequestsOneStepWithItsDirection`
