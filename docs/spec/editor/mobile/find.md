# Find in note

- *(mobile)* Find on the native text-first editor consumes the shared find core ([portable-core/find.md](../portable-core/find.md)): the note's overflow menu opens a find bar docked above the keyboard (query, count, previous, next, close); every match is painted behind the text and the current one is distinct; stepping selects the match and scrolls it into view (the first press after the query changes lands on the current match, later ones move from it); editing keeps the bar open and the marks follow the text, rescanned once typing settles. Plain, formatted and Unicode text all match; find never changes the note's bytes, Undo history or saves, and a step during composition is a no-op; marks are hidden while a composition is open. There is no replace, regex or other option. → apps/ios/Sources/Editor/TextFirst/TextFirstFind.swift, apps/ios/Tests/Editor/TextFirst/TextFirstFindTests.swift, apps/android/app/src/main/java/com/futo/notes/textfirst/EditorEngineFind.kt, FindMarks.kt, TextFirstFind.kt, TextFirstEditTextFind.kt, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstFindTest.kt, crates/futo-notes-editor/src/host/find_plan.rs
- *(iOS)* A match inside a table cell is painted in that cell and stepping to it scrolls the grid to its column (the cell's field opens only when the cell is tapped); a match in an image's alt text or destination, which the engine counts, is painted over the picture because its spelling is hidden. → TextFirstFind.swift `tableMarks`, `drawFindMarks`
