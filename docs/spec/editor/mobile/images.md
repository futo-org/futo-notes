# Images

- *(mobile)* An image (`![alt](destination)`) draws inline as one unit: the glyphs of its Markdown spelling stay in the text (hidden) and the bitmap takes their place, never wider than the line, aspect kept; words after it on the line flow past it. A vault reference loads from the vault root (percent-decoded, never from outside it) and is decoded off the main thread to the display width, turned upright by its EXIF orientation. While it loads a placeholder holds its place, and a file that cannot be read keeps a smaller placeholder showing the alt text; editing stays usable and the Markdown is never rewritten. A failed load is tried again later (a synced file may arrive). → apps/ios/Sources/Editor/TextFirst/TextFirstImages.swift, TextFirstEditorController+Images.swift, TextFirstLayoutFragments.swift, apps/ios/Tests/Editor/TextFirst/TextFirstImageTests.swift, apps/android/app/src/main/java/com/futo/notes/textfirst/ImageLoader.kt, TextFirstEditTextImages.kt
- *(mobile)* An image's only caret stops are before and after it: a caret or selection edge that lands inside its glyphs moves to the nearer end, and one step from an end (an arrow key) crosses the whole image. A plain tap anywhere on an image puts a normal collapsed caret right after it, drawn at the image's right edge: typing inserts after the image, and Backspace from there removes the image whole in one edit (one Undo restores it). A long-press, a drag selection or select-all can still select an image as one object; Enter with exactly that selection keeps the image and acts after it, so a last image can always be left, and Backspace over it removes it whole in one edit. Text typed right after an image is plain text. → apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+Images.swift `clampedOutOfImages`, TextFirstEditorController+Taps.swift `imageHit`, apps/ios/Tests/Editor/TextFirst/TextFirstImageTests.swift, TextFirstImageCaretTests.swift, apps/android/app/src/main/java/com/futo/notes/textfirst/ImageTouch.kt
- *(mobile, dev builds only; release iOS and Android still render images in the WebView editor)* An `http(s)` image reference renders inline: it loads asynchronously with platform TLS verification and no custom persistent cache, so there is no offline guarantee. The Markdown URL is never rewritten. While loading, and on failure (offline, invalid or unreachable), the placeholder stays and editing remains usable. A result lands only on an image still in the editor that requested it; a retired loader or another note's editor never receives it. Vault-relative images are unchanged. → apps/ios/Sources/Editor/TextFirst/TextFirstImages.swift `TextFirstImageLoader`, apps/ios/Tests/Editor/TextFirst/TextFirstImageTests.swift `anHttpsImageLoadsAndOfflineLeavesThePlaceholder`, apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstImages.kt, `TextFirstRemoteImageTest`
- *(mobile, dev builds only)* The toolbar's Camera and Image items claim the originating editor session before leaving the app; the picked or captured image is saved into the vault and inserted at the caret through that claim, which names the session. Navigation or reopening the note retires the claim, so an old result cannot insert into another note, and a file saved for an insertion the engine refuses (stale claim, caret in code) is deleted, leaving no blob; once the engine accepts the insertion its file stays. → apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+ImageInsert.swift, apps/ios/Tests/Editor/TextFirst/TextFirstImageTests.swift, apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstImages.kt `TextFirstImageAttachmentTest`
- *(mobile, dev builds only)* Pasting an image from the clipboard saves it through the same attachment workflow as the picker: the originating session is claimed when the paste happens, so the image lands in the note it came from. A paste that carries an image and no text is an image paste and never also pastes text or a URI string; paste of plain text is unchanged. A closed session refuses image content without writing a file. → apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+ImageInsert.swift `pasteImageFromPasteboard`, apps/ios/Tests/Editor/TextFirst/TextFirstImageTests.swift, apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstClipboard.kt, `TextFirstImageContentTest`

- *(iOS)* A full-width photo occupies one visual line; its hidden spelling does not wrap onto another photo-height line. A line entered after it uses ordinary text geometry. → apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+Images.swift, apps/ios/Tests/Editor/TextFirst/TextFirstImageTests.swift
- *(iOS)* Presenting the full-screen camera keeps the originating editor attached, so accepting the capture inserts into that note; actual navigation away still retires the attachment. → apps/ios/Sources/Editor/TextFirst/TextFirstNoteScreen.swift, apps/ios/Tests/Editor/TextFirst/TextFirstImageTests.swift `aFullScreenPickerKeepsTheOriginatingEditorAttached`
