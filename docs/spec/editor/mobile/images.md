# Images

- *(mobile)* An image (`![alt](destination)`) draws inline as one unit: the glyphs of its Markdown spelling stay in the text (hidden) and the bitmap takes their place, never wider than the line, aspect kept; words after it on the line flow past it. A vault reference loads from the vault root (percent-decoded, never from outside it) and is decoded off the main thread to the display width, turned upright by its EXIF orientation. While it loads a placeholder holds its place, and a file that cannot be read keeps a smaller placeholder showing the alt text; editing stays usable and the Markdown is never rewritten. A failed load is tried again later (a synced file may arrive). → apps/ios/Sources/Editor/TextFirst/TextFirstImages.swift, TextFirstEditorController+Images.swift, TextFirstLayoutFragments.swift, apps/ios/Tests/Editor/TextFirst/TextFirstImageTests.swift, apps/android/app/src/main/java/com/futo/notes/textfirst/ImageLoader.kt, TextFirstEditTextImages.kt
- *(mobile)* An image's only caret stops are before and after it: a caret or selection edge that lands inside its glyphs moves to the nearer end, and one step from an end (an arrow key) crosses the whole image. A drag selection or select-all can still select an image as one object, and so can a long-press on Android while a field of the note's screen is focused (with the keyboard down, on iOS and Android a long-press lifts the image instead, alone when it shares its line with other content, [block drag](block-drag.md)); Enter with exactly that selection keeps the image and acts after it, so a last image can always be left, and Backspace over it removes it whole in one edit. Text typed right after an image is plain text. → apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+Images.swift `clampedOutOfImages`, TextFirstEditorController+Taps.swift `imageHit`, apps/ios/Tests/Editor/TextFirst/TextFirstImageTests.swift, TextFirstImageBoundaryTests.swift, TextFirstImageCaretTests.swift, apps/android/app/src/main/java/com/futo/notes/textfirst/ImageTouch.kt
- *(Android)* A plain tap on an image selects it as one object, as a tap on a code block's header does: no caret, no handles and no Cut/Copy/Paste menu, the image carrying the selection colour. With the image selected, Backspace or Delete (a keyboard's collapse-and-delete included) removes it whole in one edit, never the text beside it; a typed character replaces it; Enter keeps it and opens a line after it. → apps/android/app/src/main/java/com/futo/notes/textfirst/ImageTouch.kt, ImageSelectionTint.kt `imageSelectedWhole`, EngineInputConnection.kt `selectedDeletion`, `TextFirstObjectKeyboardDeleteTest`
  > **Gap:** *(iOS)* a plain tap on an image puts a collapsed caret right after it, drawn at the image's right edge; typing inserts after the image.
- *(Android)* Editing or moving a block keeps the images that remain in it loaded at the same column width. If a previously decoded image needs to load again during that editor session, its placeholder reserves the remembered size for that width. → apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstEditTextStyling.kt, ImageLoader.kt, TextFirstSpans.kt
- *(Android)* A photo alone on its row has as much room above it as below it, the row's line spacing counted in; a full-width photo, table or rule spans the text column exactly, as far from its right edge as from its left. → apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstSpans.kt `TfImage.chooseHeight`, TextFirstEditTextWidth.kt `contentWidth`
- *(Android)* A caret right before or after a loaded image on its row, when the image is taller than the text, is as tall as the image, from its top to its bottom, and stands just outside the image's edge on the side it touches, drawn over the note, as on desktop; beside two, the taller. Beside a shorter image, or one still loading, it stays one text line tall. A caret a tap or an arrow key puts on a loaded image's row, and a tap that selects the image, shows the whole image, or its top first when it is taller than the space, never only a strip of it under the bar; a top already shown above the keyboard stays where it is, and the page never moves to the image's bottom. Typing beside an image (a key, Backspace, Enter, a paste) always shows where the text lands, the row's baseline end with a line's height of room above the keyboard, even when the image already fills the view: the scroll may move on the first character and then stays. → apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstEditTextCaret.kt `photoBesideCaret`, TextFirstEditTextReveal.kt `revealCaret` / `revealPhotoRow`, `TextFirstPhotoCaretTest`, `TextFirstPhotoRevealTest`
- *(Android)* Backspace with the caret right after an image, or hardware Delete right before it, selects the image first; the next press deletes it whole in one edit (one Undo restores it). A selected image carries the selection colour over it. An image that cannot be read shows its alt text, or its file name, muted in its placeholder, and is selected and deleted like any image. → apps/android/app/src/main/java/com/futo/notes/textfirst/EditorEngineKeyboard.kt `imageBesideCaret`, ImageSelectionTint.kt, `TextFirstImageDeleteTest`
  > **Gap:** *(iOS)* Backspace right after an image removes it whole at once, one Undo step, with no selection first.
- *(iOS; Android dev builds only)* An `http(s)` image reference renders inline: it loads asynchronously with platform TLS verification and no custom persistent cache, so there is no offline guarantee. The Markdown URL is never rewritten. While loading, and on failure (offline, invalid or unreachable), the placeholder stays and editing remains usable. A result lands only on an image still in the editor that requested it; a retired loader or another note's editor never receives it. Vault-relative images are unchanged. → apps/ios/Sources/Editor/TextFirst/TextFirstImages.swift `TextFirstImageLoader`, apps/ios/Tests/Editor/TextFirst/TextFirstImageTests.swift `anHttpsImageLoadsAndOfflineLeavesThePlaceholder`, apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstImages.kt, `TextFirstRemoteImageTest`
- *(iOS; Android dev builds only)* The toolbar's Camera and Image items claim the originating editor session before leaving the app; the picked or captured image is saved into the vault and inserted at the caret (on a line of its own when the caret's line is a plain line or a heading showing other visible content (another photo counts) and the split leaves both halves reading as they did, else inline, [portable-core images](../portable-core/images.md)) through that claim, which names the session. Navigation or reopening the note retires the claim, so an old result cannot insert into another note, and a file saved for an insertion the engine refuses (stale claim, caret in code) is deleted, leaving no blob; once the engine accepts the insertion its file stays. → apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+ImageInsert.swift, apps/ios/Tests/Editor/TextFirst/TextFirstImageTests.swift, apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstImages.kt `TextFirstImageAttachmentTest`
- *(iOS; Android dev builds only)* Pasting an image from the clipboard saves it through the same attachment workflow as the picker: the originating session is claimed when the paste happens, so the image lands in the note it came from. A paste that carries an image and no text is an image paste and never also pastes text or a URI string; paste of plain text is unchanged. A closed session refuses image content without writing a file. → apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+ImageInsert.swift `pasteImageFromPasteboard`, apps/ios/Tests/Editor/TextFirst/TextFirstImageTests.swift, apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstClipboard.kt, `TextFirstImageContentTest`

- *(iOS)* A full-width photo occupies one visual line; its hidden spelling does not wrap onto another photo-height line. A line entered after it uses ordinary text geometry. Text that shares the image's paragraph (before it, or wrapped after it) keeps ordinary line heights: only the image's own line is photo-tall, so an image inserted after or between words adds no blank space of its own. An image too wide to share the line it lands on moves to the next visual line by itself: the text before it keeps as few lines as it needs ("Hello world![](x.png)" is "Hello world", then the photo), and an image narrow enough to fit stays on the text's line. → apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+Images.swift, apps/ios/Sources/Editor/TextFirst/TextFirstImages.swift, apps/ios/Sources/Editor/TextFirst/TextFirstTypesetDelegate.swift, apps/ios/Tests/Editor/TextFirst/TextFirstImageTests.swift, apps/ios/Tests/Editor/TextFirst/TextFirstImageWrapTests.swift
- *(iOS)* Presenting the full-screen camera keeps the originating editor attached, so accepting the capture inserts into that note; actual navigation away still retires the attachment. → apps/ios/Sources/Editor/TextFirst/TextFirstNoteScreen.swift, apps/ios/Tests/Editor/TextFirst/TextFirstImageTests.swift `aFullScreenPickerKeepsTheOriginatingEditorAttached`
- *(Android text-first editor)* A photo whose size arrives after the rows below it are drawn (it finishes loading when a note is reopened at its scroll, or the view takes a new width) moves those rows with it: every row is drawn once, where it is laid out, never over another. A photo loaded for a width the view no longer has (it was rotated while the photo loaded) is not shown; the load for the new width is. → apps/android/app/src/main/java/com/futo/notes/textfirst/EditableRendererUpdate.kt `setSpanRedrawingBelow`, TextFirstEditTextStyling.kt `requestImageLoads`, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstPhotoLandingRedrawTest.kt `rowsBelowAPhotoThatLandsLateAreDrawnWhereTheyAreLaidOut` / `aPhotoDecodedForAnOldWidthLandingLastIsDropped`
