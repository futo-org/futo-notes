# Code blocks

How each phone draws a block, how its header fields take typed text, and how a hold selects it. The facts a block is drawn from are in [fenced code](../portable-core/fenced-code.md).

- [iOS text-first] A fenced block shows its language once, preserving its case, in a 16-point header above its first code line; adjacent fenced blocks each show their own label. Long labels truncate within half the code width and never change saved bytes. → apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+Style.swift, apps/ios/Sources/Editor/TextFirst/TextFirstLayoutFragments.swift
- [Android text-first] A fenced block draws from the engine's facts as a card: !300's well fill and hairline border, rounded at its first and last code line, a gap between touching blocks; a header above its first code line with its `name:` at the left in monospace and its language as written in the fence and a copy glyph at the right, the name ellipsized before the language and the language within half the width; a line-number gutter sized to the block's line count, the number on a wrapped line's first visual line only (a right-to-left line draws it on its right). Sizes scale with the system font size, and saved bytes never change. Adding or removing a line restyles the block's whole range, so every number under it follows at once. A press on the header selects the block (`select_code_block`), drawn with the selection's tint and an accent ring and no handles, and raises the keyboard; the keyboard's collapse of that selection before Enter or a typed letter is not passed on. A press on the language and copy glyph copies the block's code without its fences; the glyph shows a checkmark for about a second; Android 13 and later confirm the copy with the system's own clipboard notice, and below 13 a "Copied to clipboard" toast does. On touch a tap on the name edits it while the block is active and otherwise selects the block, a tap on the language edits it while the caret is in the block and otherwise copies, and a hold on either field edits it with its text selected; each keystroke writes the fence through `set_code_block_header`. The line numbers brighten on the lines the selection is on. Where no ordinary line reaches a block (it starts or ends the note, or touches another block), the active block (caret or selection in it) shows "add a line above" in its header and "add a line below" in its skirt; a press runs `OpenLineBeforeCodeBlock` or `OpenLineAfterCodeBlock` and raises the keyboard, as does a press under a block that ends the note. → apps/android/app/src/main/java/com/futo/notes/textfirst/TfCodeBlock.kt, apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstEditTextCode.kt, apps/android/app/src/main/java/com/futo/notes/textfirst/CodeBlockChrome.kt, apps/android/app/src/main/java/com/futo/notes/textfirst/CodeBlockTouch.kt, apps/android/app/src/main/java/com/futo/notes/textfirst/EditorEngineUpdates.kt
  > **Gap:** *(iOS)* A block shows its language label only: no `name:`, line numbers, `hl:`/`ll:` bands, copy glyph, selected-block look or "add a line" affordances.
  > **Gap:** *(Android)* Line marks (`hl:`, `ll:`) are not drawn and cannot be set; the fence keeps their text.
  > **Gap:** *(Android)* Tab and Up from a header field opened by a long-press do not reach the field.
  > **Gap:** *(iOS)* A block that ends the note can show a second label on an empty last code line, and a block on a long note's quick first screens shows no label until that text is restyled (an edit there). iOS infers the first code line from a projection instead of the style plan's `first`.
- *(Android)* A block's name and language fields write the fence on every keystroke, with the keyboard's capitals and suggestions, and keep of typed text what `typed_code_block_name` / `typed_code_block_language` keep (no rule of the host's); the name is written trimmed. A picked suggestion and the keyboard's space after it write `Python`: the field holds the trailing space while open and the fence gets the word. → apps/android/app/src/main/java/com/futo/notes/textfirst/CodeHeaderField.kt, `TextFirstCodeHeaderKeyboardTest`
- *(Android)* A hold on a block's header, or a hold inside a block already selected as one object, selects the block and shows Cut, Copy and Paste over it, with no selection handles; a tap on the header selects it with no menu. The menu follows the block as the note scrolls and hides while the block is off screen. → apps/android/app/src/main/java/com/futo/notes/textfirst/CodeBlockCallout.kt, `TextFirstCodeBlockCalloutTest`
- *(Android)* A selection begun in a block's code stays within that code while both its ends are there; a handle carried out of the block takes the selection with it, and the block is then taken whole, as by a selection begun outside it. The handle is always at the selection's end, and the other handle at its other end: the note's selection is one range, the one tinted, copied and shared. A range that only meets a block's end, from its last code character onto the line below, holds none of the block and not its line break (both characters of a CRLF break), as Copy takes nothing there. → apps/android/app/src/main/java/com/futo/notes/textfirst/CodeSelection.kt `resolveCodeSelection`, apps/android/app/src/test/java/com/futo/notes/textfirst/CodeSelectionTest.kt, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstCodeDragPaintTest.kt `aDragFromCodeIntoTheTextBelowFollowsTheHandleAndTakesTheBlock` / `aRangeFromTheCodesEndOntoTheLineBelowHoldsNothing`
- *(Android)* A block selected as one object is kept in view above the keyboard and toolbar when the keyboard rises or the selection lands; a block taller than the space keeps its header at the top. → apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstEditTextReveal.kt, `TextFirstCodeBlockRevealTest`
