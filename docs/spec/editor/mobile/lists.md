# Lists, checkboxes and links

- *(mobile)* A list item's bullet, number or checkbox is its first character, the engine's marker unit (portable-core lists.md), drawn once, in the item's marker column: one list step wide, or the whole number and its gap when wider. Wrapped and continued rows hang at the item's text. A selection tints the marker exactly when it covers that character, an empty item's included; the indent before it is never tinted. → apps/android/app/src/main/java/com/futo/notes/textfirst/TfListMarker.kt, apps/android/app/src/main/java/com/futo/notes/textfirst/ListMarkerColumn.kt, apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstSpans.kt `TfList`, apps/android/app/src/test/java/com/futo/notes/textfirst/EngineStyleSpansTest.kt, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstListSelectionPaintTest.kt, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstGlyphMetricsTest.kt, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstListMarkerTouchTest.kt `aMarkerIsDrawnOnceInItsOwnColumn`
- *(mobile)* A tap on a bullet or number acts as on a character: on the leading half of its marker column (the left, the right in a right-to-left item) the caret goes just before the marker, on the other half to the start of the item's text. → apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstEditTextTouch.kt, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstListMarkerTouchTest.kt `aTapOnEitherHalfOfAMarkerPutsTheCaretOnThatSide`
- *(mobile)* With the keyboard up, a hold on a marker selects just that marker, with handles and Cut and Copy, so Copy gives its source (`10. `); with the keyboard down a hold lifts the block (block-drag.md). → apps/android/app/src/main/java/com/futo/notes/textfirst/ListMarkerTouch.kt, apps/android/app/src/main/java/com/futo/notes/textfirst/NotePlatformLongClick.kt, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstListMarkerTouchTest.kt `aHoldOnAMarkerWithTheKeyboardUpSelectsItAndCopiesItsSource`
  > **Gap:** *(mobile)* Share, Look Up, Translate and the other system text actions receive a selected list marker as the object-replacement character U+FFFC, as they do a divider or an image, not as its text.
- *(mobile)* A tap on a checkbox ticks it; a hold selects it, as any marker, and ticks nothing. → apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstEditTextTouch.kt, apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstCheckbox.kt, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstListMarkerTouchTest.kt `aCheckboxTicksOnATapAndIsSelectedNotTickedByAHold`
- *(Android text-first editor)* Right after a marker the keyboard capitalises as at a line's start. → apps/android/app/src/main/java/com/futo/notes/textfirst/ImeCapsMode.kt, apps/android/app/src/test/java/com/futo/notes/textfirst/ImeCapsModeTest.kt
- *(mobile)* A tap on a task's checkbox, on an external link's own glyphs or on a resolved wikilink acts on that control alone: the checkbox toggles, the link opens, the note opens, and the tap places no caret and raises no keyboard (the caret stays where it was). A tap on the text beside them is ordinary text interaction. → apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstEditText.kt, apps/android/app/src/main/java/com/futo/notes/textfirst/ExternalLinkTouch.kt `linkAt`, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstTapGestureTest.kt `aTapOnEachWrappedLineOfALinkOpensItAndPlacesNoCaret` / `aTapOnAnUnbrokenWrappedLinkOpensItAndPlacesNoCaret`, apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+Taps.swift, apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+Links.swift, apps/ios/Tests/Editor/TextFirst/TextFirstLinkTests.swift

- *(iOS)* An empty checklist row keeps its checkbox at the same baseline when its first character is typed or deleted. → apps/ios/Sources/Editor/TextFirst/TextFirstLayoutFragment+ListMarkers.swift, apps/ios/Tests/Editor/TextFirst/TextFirstBlockDrawingTests.swift
- *(iOS)* The Link prompt starts in the destination field when its label is already supplied by the selection; an unchanged label keeps inline formatting. A destination typed without a scheme that looks like a web address (it starts with `www.`, or ends in a well-known public domain such as `.com` or `.org`, and is not a `.md` note) is saved with `https://` in front, so what the note holds is what the link opens; anything the editor is unsure of is saved as typed. On tap, only a destination with an explicit scheme (`http`, `https`, `mailto`, `tel`, `sms`) opens outside the app, behind the external-open guard; `javascript:`, `file:` and `data:` never open. A destination without a scheme is a note path, resolved from the current note's folder: the note opens if it exists and otherwise nothing happens, and a `#fragment` alone does nothing. A hand-written `[x](google.com)` therefore does not open a browser. → apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+Links.swift, apps/ios/Tests/Editor/TextFirst/TextFirstLinkTests.swift, crates/futo-notes-editor/src/link_target.rs, crates/futo-notes-editor/tests/link_target.rs
