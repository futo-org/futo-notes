# Lists, checkboxes and links

- *(mobile)* Selecting a complete list row extends its highlight over the rendered number, bullet or task checkbox; a caret or partial-word selection does not highlight that marker. → apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstEditTextSelection.kt `drawListSelection`, apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstSpans.kt `drawSelectedMargin`, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstGlyphMetricsTest.kt, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstCaretTest.kt `listMarkersFollowNativeSelectionWithoutATextChange` / `emptyListRowsHighlightOnlyTheirSelectedNewline`, apps/ios/Sources/Editor/TextFirst/TextFirstLayoutFragments.swift `highlightedMarkerRect`, apps/ios/Tests/Editor/TextFirst/TextFirstBlockDrawingTests.swift `aFullySelectedRowHighlightsItsMarker`
- *(mobile)* A tap on a task's checkbox, on an external link's own glyphs or on a resolved wikilink acts on that control alone: the checkbox toggles, the link opens, the note opens, and the tap places no caret and raises no keyboard (the caret stays where it was). A tap on the text beside them is ordinary text interaction. → apps/android/app/src/main/java/com/futo/notes/textfirst/TextFirstEditText.kt, apps/android/app/src/main/java/com/futo/notes/textfirst/ExternalLinkTouch.kt `linkAt`, apps/android/app/src/androidTest/java/com/futo/notes/textfirst/TextFirstTapGestureTest.kt `aTapOnEachSoftLineOfALinkOpensItAndPlacesNoCaret` / `aTapOnAnUnbrokenWrappedLinkOpensItAndPlacesNoCaret`, apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+Taps.swift, apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+Links.swift, apps/ios/Tests/Editor/TextFirst/TextFirstLinkTests.swift

- *(iOS)* An empty checklist row keeps its checkbox at the same baseline when its first character is typed or deleted. → apps/ios/Sources/Editor/TextFirst/TextFirstLayoutFragment+ListMarkers.swift, apps/ios/Tests/Editor/TextFirst/TextFirstBlockDrawingTests.swift
- *(iOS)* The Link prompt starts in the destination field when its label is already supplied by the selection; an unchanged label keeps inline formatting. A destination typed without a scheme that looks like a web address (it starts with `www.`, or ends in a well-known public domain such as `.com` or `.org`, and is not a `.md` note) is saved with `https://` in front, so what the note holds is what the link opens; anything the editor is unsure of is saved as typed. On tap, only a destination with an explicit scheme (`http`, `https`, `mailto`, `tel`, `sms`) opens outside the app, behind the external-open guard; `javascript:`, `file:` and `data:` never open. A destination without a scheme is a note path, resolved from the current note's folder: the note opens if it exists and otherwise nothing happens, and a `#fragment` alone does nothing. A hand-written `[x](google.com)` therefore does not open a browser. → apps/ios/Sources/Editor/TextFirst/TextFirstEditorController+Links.swift, apps/ios/Tests/Editor/TextFirst/TextFirstLinkTests.swift, crates/futo-notes-editor/src/link_target.rs, crates/futo-notes-editor/tests/link_target.rs
