# Escaping audit at 396c7a29d

This is a source inventory for [MD01](markdown-fidelity.md#md01), not a patch or a recommendation to delete every escape. A literal-text command, a link destination and a typed Markdown delimiter have different contracts. Mason's 2026-11-10 decision rejects silent escaping of typed markers; it does not authorize corrupting tables, destinations or retained visible text.

## Milkdown's active serializer

Paths start at `packages/editor/src/markdown/`.

- `inline.ts::textPieces` offers raw-versus-escaped sites for punctuation, leading whitespace and mark boundaries. The punctuation allowlist schedules a parse; it does not decide the final spelling.
- `choose.ts` parses candidate output and removes unnecessary escapes. Its budget may retain correct but nonminimal escaping.
- `inlineTokens.ts::escapeReferences`, `cellPipes`, `codeSpan`, `destination`, `titlePart`, `escapeLabel` and the wikilink cell writer protect entity-looking ampersands, table pipes, code delimiters, link/image fields and literal labels.
- `blocks.ts`, `normalize.ts` and `serializer.ts` supply structural spellings; `pieces.ts` carries alternatives. `cache.ts` caches the same bytes rather than introducing another spelling policy.
- `milkdown-compat/ownedSerializer.ts` installs this writer. A schema `toMarkdown` handler is not the current save authority (`packages/editor/AGENTS.md`).

## Decisions and reversals

1. CM6 stored source and revealed markers at the cursor. The deleted `docs/specs/markdown-live-transform.md@1c3b665aa^` distinguishes line-exit and progressive inline reveal; it is not a requirement to restore those visual modes.
2. Justin's 2026-08-27 ADR-0002 accepted normalize-on-edit for Milkdown, with no rewriting on open, no content loss and one serializer.
3. !363 repaired raw-output and flanking corruption; !384 fixed its `&#xNAN;` regression; !394 replaced remark-stringify with the owned parser-checked writer; !477 used references for leading whitespace.
4. On `android-text-first`, 28a0ba971 and 29e0f67b9 (2026-11-05) explicitly traded raw delimiter spelling for never dropping typing. The current desktop checkout contains the same escape/fallback mechanisms.
5. Mason's 2026-11-10 instruction reverses that trade for typed Markdown. It requires engine/spec changes; the desktop's absence of visible asterisks is not proof that its saved source is already compliant.

Recommendation: preserve exact typed source and derive live formatting from it; keep escaping limited to explicitly literal commands and field encodings. Resolve table pipes, toolbar-carried formatting beside ambiguous delimiters, and typed link/image policy as named examples before changing the engine. Keep existing author-written escapes exact.
