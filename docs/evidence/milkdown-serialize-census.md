# Block-serializer equivalence census

Generated by `just chunk-census --serialize` (`scripts/milkdown-chunk-census.mjs`). It drives the
shipped `editor.html` over a corpus of real notes and, for each note, compares the editor's
`serializerCtx` — the owned serializer (`packages/editor/src/markdown/`, #266) writing the whole
document, which is what `getMarkdown()` and a copy's plain text use — against a fresh per-block
cache's output for the same document (`createDocumentSerializer` in
`src/features/editor/milkdown/serializationLoop.ts`, over `packages/editor/src/markdown/cache.ts`).
That cache is what the editor's change notification and `getContent()` serialize through, so this
is the claim it rests on: byte-identical output, proportional to the edit instead of to the note. A
serializer that throws on either side counts as a failure, never as a match. Re-run it after any
change to the serializer, its cache, or the Milkdown plugin chain.

The corpus is real user notes and lives outside this repo, so nothing below is note content: only
counts.

> **2026-10-06, the owned serializer (#266).** The cache no longer mirrors remark-stringify's
> joining rules: the serializer owns the block separator (`joinDocument`) and the only cross-block
> state, the list marker and the definitions (`planDocument`, `references`), recomputed from cached
> block summaries on every call.

> **2026-09-08, the remark-era cache** (`blockSerializer.ts`, deleted in #266) needed a
> unit-partitioning simulation of remark's `bulletLastUsed` and `blankLineJoin` to reach 0
> divergent; its first draft diverged on 19 notes.
