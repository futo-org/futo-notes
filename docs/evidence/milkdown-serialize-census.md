# Milkdown block-serializer equivalence census

Generated by `just chunk-census --serialize` (`scripts/milkdown-chunk-census.mjs`). It drives the
shipped `editor.html` over a corpus of real notes and, for each note, compares Milkdown's own
serializer called directly on the loaded document against a fresh `BlockSerializer`'s output for the
same document (`src/features/editor/milkdown/blockSerializer.ts`). That cache is what the editor's
change notification and `getContent()` now serialize through, so this is the claim it rests on:
byte-identical output, proportional to the edit instead of to the note. Re-run it after any change
to the block serializer, `blankLineJoin` (packages/editor/src/milkdown-compat/emptyLine.ts), the
remark stringify options, or the Milkdown plugin chain.

The corpus is real user notes and lives outside this repo, so nothing below is note content: only
counts.

> **2026-09-08, first run of the final grouping rule.** The first draft grouped units as
> `list (emptyParagraph* list)*` and diverged on 19 notes, in two classes the rule had missed: 11
> where a top-level list is immediately followed by a blockquote whose first child is a list (remark's
> `bulletLastUsed` is still the outer list's marker when the blockquote's own `containerFlow` handles
> that child, so it alternates — upstream behaviour), and 8 where `list, empty, heading, empty, list`
> alternates the second list's marker because `blankLineJoin` only forgets its remembered bullet at a
> join with a non-empty block on BOTH sides. Both are now covered by the unit-partitioning simulation
> in `blockSerializer.ts` (a list's marker reaches its very next non-leaf sibling; a remembered bullet
> forces every gap from where it was primed through the list that restores it into one unit). 30
> synthetic shapes through the same seam, including both classes rebuilt as fixtures, adjacent lists
> with every marker, lists separated by two to five blank lines, a blockquote ending in a list before
> an empty paragraph and a list, front matter, tables between lists, and the device gate's fixtures,
> were all equivalent.
