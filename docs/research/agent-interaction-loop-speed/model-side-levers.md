## 6. Model-side levers

| Lever | Evidence | Source | Status |
|---|---|---|---|
| Prompt caching | Cache reads 0.1x base input price (0.025x on Fable 5.1 / Mythos 5.1); writes 1.25x (5-min) or 2x (1-hour); minimum cacheable prefix 512–4,096 tokens by model; automatic prefix lookback of 20 blocks where "a run of consecutive `tool_use` blocks counts as one position"; pre-warming reduces TTFT. No quantified latency % in the current docs | https://platform.claude.com/docs/en/docs/build-with-claude/prompt-caching | shipped |
| Cache-preserving control changes | Changing `budget_tokens`, top-level `effort`, or `tool_choice` between requests invalidates message-level cache; Fable 5.1 / Opus 5 support per-message effort via a `role: "system"` message that "preserves the prompt cache"; task budgets' countdown marker also breaks caching if mutated client-side | https://platform.claude.com/docs/en/docs/build-with-claude/extended-thinking ; https://platform.claude.com/docs/en/docs/build-with-claude/effort ; https://platform.claude.com/docs/en/docs/build-with-claude/task-budgets | shipped |
| Preserved reasoning across tool calls | OpenAI Responses API: "40–80% better cache utilization compared to Chat Completions"; GPT-5 "5% better on TAUBench… purely by taking advantage of preserved reasoning". Anthropic: interleaved thinking between tool calls; Opus 4.5 and 4.6+ keep prior turns' thinking blocks in context | https://developers.openai.com/blog/responses-api ; extended-thinking docs | shipped |
| Parallel tool calls in one turn | Anthropic API returns multiple `tool_use` blocks by default (`disable_parallel_tool_use` to turn off) and accepts multiple `tool_result` blocks in one message; Claude Code has a `PostToolBatch` hook; Cursor RL rewards parallelism | define/implement tool-use docs; hooks doc; Cursor post | shipped |
| Streaming tool inputs | `eager_input_streaming: true` streams tool arguments "without server-side buffering or JSON validation", so a large edit or document starts arriving before generation finishes | fine-grained-tool-streaming docs | shipped |
| Reduced thinking on routine steps | `output_config.effort` levels `low`/`medium`/`high`/`xhigh`/`max`; "Lower effort also means fewer and terser tool calls"; low "Combine multiple operations into fewer tool calls"; adaptive thinking "may skip thinking entirely on easy inputs". Browser Use `flash_mode` "skips evaluation, next goal and thinking and only uses memory" | effort docs; extended-thinking docs; Browser Use params | shipped |
| Smaller model for perception, larger for planning | Browser Use `page_extraction_llm` ("a small & fast model" for DOM extraction); Anthropic: Opus lead + Sonnet subagents; Agent S2: generalist planner + specialist grounding models; effort `low` "such as subagents" | sources above | shipped / research |
| Faster serving of the same policy | Cognition SWE-1.5 at "up to 950 tok/s", "6x faster than Haiku 4.5", "13x faster than Sonnet 4.5", with a trained draft model for speculative decoding and a request priority system; Cursor Composer "four times faster than similar models" | https://cognition.com/blog/swe-1-5 ; https://cursor.com/blog/composer | shipped (vendor-measured) |
| Speculative actions (predict the next action with a cheap model, pre-execute, commit if the big model agrees) | "up to 55% next-action prediction accuracy, translating into up to 20% latency reductions" across gaming, e-commerce, web search; lossless | https://arxiv.org/abs/2510.04371 (ICLR 2026) | research |
| Task budgets (advisory countdown across the whole loop) | Model "uses it to prioritize work and finish gracefully"; too-small budgets cause "refusal-like behavior"; minimum 20,000 tokens; not available in Claude Code | task-budgets docs | shipped beta |
